Detail
resolve_import in gen_arch_map.py takes one token internal_imports wrote, the importer's module path, the inventory's module paths and the paths package_paths reads from the __init__.py files, and returns one module or None. An absolute token tries its dotted prefixes longest first, each as a path, against the modules equal to it or ending in / plus it; the first prefix that matches decides, and two matches return None, so a one-segment token is the unique-stem match. A relative token starts from the importer's package, which is the importer itself when its file is a package's __init__.py and its parent otherwise, climbs one level for each dot past the first, returns None for a climb past the top, and matches exactly, trimming its tail back to the package. _classifiable_edges in trajectory_arch.py resolves every token of the live inventory through it and skips an import that resolves to None or to the importing module itself; a gen_arch_map without resolve_import or package_paths leaves the rule silent. The dependency diagram draws its arrows through the same function.
Rationale
The rule looked each token up by its last path segment, so every dotted and relative import missed and no edge into a package was ever checked, while the dependency diagram kept a resolver of its own that took the first of several matches. One resolver, in the module that writes the tokens, keeps the check and the picture on one answer. A token that names nothing, or names several modules, is skipped rather than guessed, since a guessed edge would be a finding against a seam that does not exist.
