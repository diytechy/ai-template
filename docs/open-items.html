SR-183Per-function complexity is measured against a stamped baseline, and gated only where a repo opts inapproval owed

Requirement

The delivered harness shall report each source function's cognitive complexity against a stamped per-function baseline, failing a declared gate on any divergence from that baseline only where the repo has enabled the gating mode.

Rationale

Realizes SN-007 (the kit holds itself to its own standard) and SN-012 (a heavy layer costs a repo that does not use it nothing). SR-220Overlapping queued work is consolidated through one judgement per queue stateapproval owed

Requirement

While the queued work items include a set that overlaps, the delivered loop content shall hand that set to a single judgement, at most once for any one state of the queued rows and never beside another queued or active judgement, and shall enact the judgement's outcome as a recorded restructuring, each absorbed item closed in a terminal state naming its one successor with its scope text unchanged.

Rationale

A DERIVED requirement, and labelled so. SN-025 asks that no human curate what comes next; its acceptance states only that the next work derives from the tracked work-item graph, which a stranger reading it would derive as work selection alone. This row states what that promise needs once the loop also mints work: rows minted one finding at a time overlap, and without this row either a human merges them, which is the curation the need rules out, or the loop builds the same job more than once. Two lenses shape it. UNATTENDED-OPS: an overlap is a standing state, so a judgement fired on it re-asks the same question on every idle tick unless the judged state is remembered past the judging row's close, an unbounded retry that pages nobody. PERFORMANCE: each judgement is a strong-tier session, so asking once per queue state is the operating-cost bound rather than an optimisation. The restructuring is recorded rather than done by deletion so that an absorbed item's scope and its successor stay readable after the act. Fed back to the need: SN-025's acceptance could name the loop keeping its own queue free of duplicated work; until it does, this row is derived and says so. Choosing the next work stays SR-148's, and reporting an overlap as a warning stays SR-157's.
