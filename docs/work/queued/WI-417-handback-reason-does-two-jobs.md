title = "The handback reason string does two unrelated jobs and one of them is a layering violation (found 2026-08-03 while reading WI-413/WI-416; filed as its own row per the working agreement, NOT folded into either). JOB 1 - THE LAYERING VIOLATION: `NEEDS-HUMAN` in a handback reason is the LANE prescribing its own disposition, which R3 gives to the disposition row (docs/rulings-context-2026-08-01.md §R3 point 2 - the dispatcher surfaces an open item 'where a human ruling is genuinely needed', and that 'genuinely' is the adjudicator's judgement, not the returning lane's). It also ANCHORS the judge it triggers: intake._handback_drafts clips the reason at _LINE_CLIP=140 into the minted row's ## Context, so the adjudication brief OPENS with the defendant's verdict - observed live on WI-416, truncated mid-word. The dispatcher's AUTOMATIC reason ('worker exit 7 (NEEDS-HUMAN)', dispatch.py:464-466) is an exit code plus its label, a fact and probably defensible; a hand-written prose reason that prescribes an outcome is not. JOB 2 - THE COUPLING: tier_signal (intake.py:151-152) is the reason string's ONLY consumer - a case-insensitive substring test for 'NEEDS-HUMAN' selecting strong vs medium buildtier. So the review TIER and the disposition VERDICT ride one magic substring, with no shared constant, no validation and no refusal on a miss: 'NEEDS_HUMAN' or 'needs human' silently downgrades the disposition row. THE ASK, three judgements: (1) key the tier off something FACTUAL the dispatcher already has (the worker exit-code class, or review-rounds-exhausted) rather than off a word that also reads as a verdict; (2) rule whether a handback reason is constrained at all - a named constant plus a loud refusal, or explicitly free prose with the prescription convention retired in the guidance; (3) judge whether the automatic 'worker exit N (NEEDS-HUMAN)' label survives - it may, an exit code being a fact. Consider also whether the ## Context clip should quote the reason at all, given it anchors. (4) RENAME THE LABEL - `NEEDS-HUMAN` names an ACTOR where the signal is policy-independent, and the code already knows better: plan_round._PAGE_ACTIONS (plan_round.py:70-74) maps the SAME situation to stop-needs-human / surface-block-continue-others / design-check-session BY GATE LEVEL, and agent_loop.py:2851 records the invariant that under autonomous/single-ratify an attention-only outcome lands on EXIT_STALL, never a NEEDS-HUMAN gate. So exit 7's name hard-codes the ATTENDED answer into a signal every gate level reads - and this repo's declared level is autonomous, where it is wrong on its face. Owner's proposed replacement (2026-08-03): NEEDS-JUDGEMENT, which names the owed ACT and leaves WHO supplies it to the adjudicator's combination of gate level + issue + high-level view. The exit NUMBER (7) is the machine contract and does not move, so this is a label/doc migration for adopters, not a behaviour change; sequence it AFTER judgement (1), because once the tier keys off cause class the label stops being load-bearing. Surfaces to change: agent_common END_STATES + EXIT_NEEDS_HUMAN, agent_loop's --help exit table and its two stop_banner headlines, dispatch._lane_close's reason string, PROCESS_OPTIONS.md and ADOPTING.md. DO NOT rename bootstrap.STACK_NEEDS_HUMAN or check_docs._NEEDS_HUMAN_RE - those name the 'Needs-<human>' open-items bucket, where an owner call genuinely IS the point. SCOPE-NARROWING EVIDENCE (traced 2026-08-03, so the builder need not re-hunt): of the five layers carrying this label, only two reach a later agent's context - dispatch's reason string and intake's context clip. stop_banner (agent_common.py:1811) PRINTS ONLY; it reads status.md via current_state_excerpt and writes nothing, its old durable home docs/run-state having retired at concurrency-restructure Phase 5.
