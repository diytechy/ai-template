## Deliverable

The §A5.1 cell split is implemented exactly as ruled, in `check_trajectory.py`. Two declared tables — `SPINE_TRACED_CELLS` and `SPINE_RATIFIED_CELLS`, one entry per spine registry — carry both halves of the ruling; `spine_cell_class(csv_path, column)` is the one place either is consulted. The traced cells the ruling names (SR `SN-Refs`/`Phase`/`Area`/`Lifecycle`, LLR `Module`/`CodeSymbol`/`TestRefs`/`Component`/`Phase`, TC `Verifies`/`Evidence`/`Automated`/`Phase`) no longer arm the re-attest warn.

DIRECTION CHOSEN, AND WHY: an allowlist with a fail-safe residual, not an allowlist alone. Both halves are declared, and a column in NEITHER falls to RATIFIED. A pure allowlist fails in the wrong direction — a column added to a registry after the ruling was written would be silently un-ratified, and the failure mode of this detector is asymmetric in a way that decides the design: a spurious window is a window somebody sees, argues with and files (WI-280's cost, real but paid in the open), while a missed window is seen by nobody, and the whole point of the marker is that the owner's sitting sees the change. Falling to ratified means a new column can only ever be too loud. Two tests pin it: `test_staged_spine_unknown_column_falls_to_ratified` (a column in neither table still warns — mutation-proved RED against an allowlist-only residual) and `test_spine_cell_split_classifies_every_shipped_column`, which asserts every column of this repo's live registries AND of the blank forms the kit ships is classified explicitly, plus that the two halves never overlap. The second is what keeps the first honest: the residual is silent by construction, so without it a new column could ride the residual unnoticed forever; with it, adding a column fails at the ruling.

SEAM FOR WI-388, NOT ADJUDICATION. The scan is now `staged_spine_amendments(root, base="HEAD", head=None)`, which returns one record per amended Verified row — `{"registry", "id", "ratified": {cell: (before, after)}, "traced": {...}}` — and `staged_spine_findings` is a thin formatter reporting only the ratified half. A traced-only edit is therefore silent in the warn but fully present in the returned data, with the before/after §A5.2 says the adjudication body is derived from. `test_staged_spine_amendments_expose_the_traced_half_for_adjudication` pins that pairing directly (the warn empty, the record carrying `SN-Refs: ("SN-001", "SN-009")`). No minting, no dial, and no adjudication kind added here — that is WI-388's row.

The rev pair is part of the seam and REVIEW-A round 1 is why. `head=None` (the default) compares the index against `base` — the hook's `--staged` question — but §A5.2 mints adjudication from a trunk COMMIT, and a commit is not the index: driven, the identical `SN-Refs` re-point yielded the traced record while staged and `[]` once committed, so WI-388's dispatcher would have run after the commit landed and got nothing. `_spine_revs` makes the pair explicit, so `staged_spine_amendments(root, "HEAD~1", "HEAD")` answers the post-commit question without re-opening the scan; `test_staged_spine_amendments_read_a_commit_range_not_only_the_index` drives both sides of a real commit and is mutation-proved against an index-only `_spine_revs`. The mechanism WI-388 owns — minting, the id allocation, the gate-policy arms — is untouched.
