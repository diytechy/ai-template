## Deliverable

DONE 2026-07-28. All 17 Path.write_text() call sites across the kit scripts converted to the open(..., newline=chr(92)+'n') form, plus THREE append sites the new guard found that the row had not counted - two of them appending to docs/log.md, so an integration on Windows was writing CRLF into it. Zero write_text sites remain and zero text-mode .open() lacks a newline policy, both verified by AST. THE IMPLEMENTATION CONSTRAINT, which is the whole reason this is not a one-liner: Path.write_text(newline=) is 3.13+ and the kit floor is 3.11, so the obvious fix is a TypeError on the oldest Python the kit claims. Found the hard way earlier the same day when a test caught the same slip in a fixture. The two-line open() form is inlined at each site rather than routed through a helper: the F5 independently-copyable rule means a helper would have to be copied into all eight scripts, and eight copies of a helper is a worse trade than sixteen extra lines with no new API. That decision is recorded in the census under lf-write-preamble (3 CROSS-SCRIPT blocks, triaged individually, not blanket-stamped). The SAME-FILE pair the change created - the two atomic-JSON writers in agent_dispatch - was EXTRACTED to _atomic_json instead, per WI-343 (F5 never covers a same-file copy), which also RETIRES the atomic-json census class and its distribution row. Guards (tests/test_generated_newlines.py, 5): two AST invariants - no write_text in a kit script, and every text-mode .open() declares newline= - plus a mutation proof that both predicates FIRE on the banned shapes and stay silent on the fixed form and on a BINARY write (a rule that banned open('wb') would be a different, wrong rule). The AST pair is what makes the fix stick, and it passes vacuously on a clean tree, which is exactly why the mutation proof is not optional. Then a behavioural guard runs REAL generators into a scratch tree and asserts no CR byte in what they wrote, scanning a directory or a file as appropriate - so the syntax rule is anchored to observed behaviour on whichever platform the suite runs. CORRECTION to the plan: gen_trajectory.py was NOT among the 17, so this change does NOT re-red perceptual-stale and no render critique is owed for it. `git ls-files --eol` shows no non-.ps1/.cmd/.bat file CRLF in the working tree.
