## Deliverable

Delivered 2026-07-26. The .cedge shaft and its marker head now read the same per-node --ring control token the focus ring uses, so the arrow's ink is computed against the fill it is drawn on instead of a fixed var(--accent). One constraint had to be designed around rather than styled around: marker content renders from the defs tree and CANNOT see the referencing node's custom properties, so a single shared head would still have been painted from one hue - the emitter now emits ONE MARKER PER RING INK (_cedge_marker) and each block references the one matching its fill, with the unsuffixed accent marker kept for theme-token (var(--surface)) fills where accent is already tuned as ink. RING_INKS declares that ink set as closed, since one-marker-per-ink is only total over a closed set. LLR-105 widened from 'the focus ring' to 'every control painted over a node's own fill'; TC-108 grew half (b), which resolves the CSS var() fallback the way a browser does and then checks the RENDERED artifact that each arrow's marker carries its host block's ink. Guard proven against the pre-fix code first: it failed at 1.0596:1 (#4f46e5 on #0369a1), the critique's measured value. Two sensors bit and were answered rather than silenced: the LLR-114 reflection sweep caught RING_INKS as an unclassified hex constant (the sweep now classifies by ROLE - a control-ink is floor-checked in the other direction and closed against _ring_ink's reachable outputs), and A4_FILL_TOKEN_ROLES gained --ring. Spec of record was the finding itself, docs/reviews/3-g2-WI-305-6f47/002-CRITIQUE-54cf50f.md - a review record, already in its permanent home, so closing clears the SpecRef without an archive move (docs/specs/README.md lifecycle).
