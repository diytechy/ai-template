## Deliverable

INTERFACES.template.md's rules bullet "Both sides reference the same IF-ID / use identical ids across repos" is replaced by the repo-local rule: each repo owns its own IF-### space, the two ends of one contract carry different local ids (as the template's own worked snippet always showed), a foreign seam is cited as the qualified pair (counterpart repo or REPO-### row + its local IF-### + pinned version) in Counterpart + Contract/Notes and never in the IF-ID column (trace.py's anchored integrity pattern rejects it), the coordinator case keeps CIF-### as the one global handle (MULTI_REPO.md section 3.3 linked), and the honesty caveat is stated: no tool validates the far side of a cross-repo reference - it is a text convention. No schema, script, or registry change - the wrong sentence was the whole defect.
