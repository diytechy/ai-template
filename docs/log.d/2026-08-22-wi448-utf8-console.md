## 2026-08-22 — WI-448 slice 2: the console guard gets its one home

Deferred open items: none — this slice is plumbing consolidation onto a
behaviour whose home slice 1 already chose and shipped; it made no design call
the owner has not already ruled (D-8/`OI-16`), and the one judgement it did
take (join the existing `config` theme rather than mint a `console` module) is
recorded below and reversible in one commit.

**Summary.** The 33 remaining local `_utf8_console` definitions across
`project-trajectory/scripts/*.py` are deleted; every kit script now resolves the
console guard to the single shipped `kitlib.config.utf8_console`. Item 1 of
WI-448's five owed items lands; items 2–5 stay owed and the row stays open.

**Why no new kitlib module, and why that is the smallest-total-code answer.**
The shape constraint is THEMED modules, never a generic `common.py`, and the
themes are already declared in `kitlib/__init__.py`. `config`'s declared theme
is *"declared-policy files **and console encoding**"* — the guard is named there
by slice 1, and `kitlib.config.utf8_console` has existed since slice 1, with
`bootstrap.py` already aliasing it. So this slice is not a placement decision at
all: it is 33 call sites arriving at a home that was chosen, documented and
shipped a fortnight ago. Minting a `console.py` would have added a module, a
`MAPPING` row, two `tests/test_bootstrap.py` list entries and a README line to
relocate seven lines of code that were already correctly themed — strictly more
total code for no separation gained. `MAPPING`, the bootstrap file lists and the
README kit-contents list are therefore all UNCHANGED, which is the outcome the
row's "the single line that is the whole downstream risk surface" worry wants:
the risky surface was not touched.

**Deliverables.**

- **32 scripts** take one import line in place of a local definition:
  `from kitlib.config import utf8_console as _utf8_console`, placed in the
  header import block (ruff `E402`) with a two-line comment naming the home.
  The module-local NAME `_utf8_console` is deliberately preserved, so the three
  cross-module call sites — `gen_trajectory.py`'s `ct._utf8_console()`,
  `gen_prompt_catalog.py`'s `prompts._utf8_console()`, `intake.py`'s
  `ac._utf8_console()` — and `agent_loop.py`'s
  `_utf8_console = agent_common._utf8_console` re-export need no edit at all.
  CLI behaviour is byte-identical: same function, same call order, same
  best-effort semantics.
- **`agent_common.py`** is the one exception to the import form, and on purpose.
  It already imports `kitlib.config` under the guarded
  `try/except ImportError` idiom the engines use, so it takes
  `_utf8_console = _kitconfig.utf8_console` (the `bootstrap.py` shape) rather
  than adding a second, UNGUARDED import of the same package beside a guarded
  one — which would have made the guard a lie in that module.
- **Two dead `import sys` lines** removed (`gen_cases.py`, `plan_round.py`): the
  deleted body was their only `sys` user. Found by `ruff check`, not by hand.
- **`bootstrap.py`'s pointer comment** corrected — it said the other 33 copies
  "are the consolidation program's next slice", which stops being true with this
  commit. Same line count, no size change.
- **`tests/test_rule_sync.py`'s module docstring** corrected. It listed
  `_utf8_console` among the helpers F5 licensed as "duplicated on purpose", in
  the present tense; the paragraph now reads that list as history and names D-8
  and this slice. This is the same stale-premise correction WI-448's spec
  demands for item 2's pin — done here because the sentence became false here.
- **The three copies that had drifted: none, materially.** All 33 bodies were
  diffed before the sweep. Every one was the identical seven-line
  `reconfigure`-with-`(AttributeError, ValueError)`-guard; the only variations
  were the docstring (fourteen different wordings of the same claim, plus three
  copies with no docstring) and ONE loop-variable name — `gen_open_items.py`
  spelled it `stream` where the other 32 spelled it `s`. The shipped
  `kitlib.config.utf8_console` also spells it `stream`, so the surviving
  behaviour is the majority behaviour and the majority spelling is irrelevant to
  it. No behaviour was chosen away.

**Deviations from spec.** One, and it is a null result rather than a departure:
the slice was scoped to allow "a small new themed module … if it's the
smallest-total-code answer". It was not — the theme already existed and already
held the function — so no module was added and, consequently, none of the
`MAPPING` / `test_bootstrap.py` / README registration work the scope names was
required. That registration path was still exercised as a CHECK (the scaffold
verify below imports all 32 shipped scripts out of a real bootstrap), which is
what the standing lesson actually protects against.
