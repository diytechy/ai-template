## 2026-08-18i — This repo turns the OKF knowledge-bundle layer off for itself (the kit still ships it)

**Why.** `docs/okf/` was **551 tracked files — 27% of the repo's tracked
tree** — carrying a second, generated copy of every SN/SR/LLR/TC cell. Nothing
in the repo read it except the dashboard's Knowledge tab, while every grep over
the spine paid for it: each fact answered twice, once from the registry that
owns it and once from its regenerated export, with the export's copy indexed,
diffed in review, and shipped to every clone. That is the exact cost the
one-home rule exists to avoid, spent on a view this repo does not use to work.

**What changed.** One dial and one directory:

- `docs/process.toml` `[checks] okf_export` = `true` → **`false`**, with the
  reason and the reversal recipe in the key's own comment.
- `git rm -r docs/okf/` — **551 files** deleted.
- `docs/declared-absences` gains a `docs/okf/` row (its own short section: this
  is a shipped layer switched off, not a retirement). Deliberately **unmarked**,
  so the materialize-guard stays armed — with the dial off nothing regenerates
  the bundle, so a `docs/okf/` that reappears is either a hand-added tree no
  freshness check gates, or the deliberate act of flipping the dial back, in
  which case deleting that line is part of the act.
- `README.md`'s dial table now reports this repo's value honestly; the two rows
  above it, which document what `gen_okf.py` *produces*, are kit-layer text and
  stand. `docs/repo-lock.md`'s historical citation census drops the `.md` from
  its one bundle path (matching the truncated form its neighbouring cells
  already use) so a record of a 2026-07 measurement stops reading as a live path.
- `docs/stack.ini`'s `[generated]` row for `docs/okf/` **stays**: it declares
  OWNERSHIP (the trunk lane owns that artifact when it exists), and the enforcer
  census in `tests/test_generated_freshness_wiring.py` reads the declaration,
  not the disk.

**The kit layer is untouched.** `gen_okf.py`, `check.py`'s `okf` step, the
pre-commit floor's `okf`, `trunk_step.py`'s `okf` regen and the dashboard's
Knowledge tab all ship exactly as before, and a scaffolded repo still gets the
bundle on by default. Verified here with the dial off: `gen_okf.py --check`
prints `off (docs/process.toml [checks] okf_export) — nothing to export` and
exits 0; `trunk_step.py --regen` skips the step with the reason printed
(`docs/okf/ absent`); and `check_doc_refs.py` is back to its 46-dangling
baseline — the six references the deletion staled are all reclassified or fixed.

**The trade-off, accepted.** This repo stops dogfooding a layer it ships, and
loses the Knowledge tab from its own dashboard — so a rendering regression in
that tab will no longer show up in the owner's daily surface, only in the
tests. The one test that read this repo's *committed* bundle
(`test_meta_okf_bundle_renders_the_knowledge_graph`) kept its property and moved
its subject: `gen_okf.emit()` is not dial-gated, so it now materializes the
bundle from the **live registries** into `tmp_path` and builds the graph there —
same spine, same ~220-concept scale, no committed copy — and additionally pins
that `know_graph(ROOT)` is `None` here, which is the self-omission the layer
promises a source-less repo. Every other OKF test already ran on tmp scaffolds.

**Reversible — one dial, but not one step.** *(Recipe corrected 2026-08-18,
review round, finding N11: the original said "reversible in one key", and
executing it literally on a copy of `HEAD` left three tests red. Each of the
three is a one-way ratchet written against the dial's CURRENT value, so a real
reversal has to unwind them by name.)* Measured worklist:*

1. `docs/process.toml` — `[checks] okf_export` back to `true`, and rewrite the
   key's comment, which currently argues for the off position.
2. `python project-trajectory/scripts/gen_okf.py` — writes the bundle back
   (`gen_okf: wrote 553 / pruned 0 -> docs/okf`; 553 files, not the 551 deleted
   — the spine grew since).
3. `docs/declared-absences` — delete the `docs/okf/` row. Deleting it is *part
   of the act*, by that row's own terms (it is deliberately unmarked so the
   materialize-guard stays armed).
4. `tests/test_rule_sync.py::test_the_shipped_template_declares_every_checks_dial_at_todays_default`
   — drop `okf_export` from its `OWNER_DIALS` map. That map pins this repo's
   divergence from the shipped default; with the dial back at the default the
   entry is the failure.
5. `tests/test_traj_panels.py::test_meta_spine_renders_the_knowledge_graph_at_real_scale`
   and
   `tests/test_traj_graph.py::test_meta_knowledge_and_when_wires_avoid_unrelated_boxes`
   — both open `assert gt.know_graph(ROOT) is None, "no bundle here — the tab
   must self-omit"` and then materialize a bundle into `tmp_path` to get their
   subject back. With a committed bundle present that assertion inverts; both
   can read `ROOT` directly again, which is what they did before this change.
6. `python project-trajectory/scripts/gen_trajectory.py` — the dashboard is
   STALE the moment the bundle exists (`gen_trajectory.py --check` exits 1); the
   Knowledge tab returns and the file grows back toward 2.6 MB.
7. `README.md`'s dial table — the `okf_export` row reports this repo's value and
   its reason; both change back.

Verified by doing it: steps 1–3 alone, on a `git archive HEAD` copy, give
`3 failed, 100 passed` over those three test modules, failing exactly the three
tests named in 4 and 5.
