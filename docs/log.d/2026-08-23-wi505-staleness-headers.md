**Exclusions from the sweep, with reasons (checked against the actual
readers before excluding, not assumed):**
- `docs/archive/work/**` (503 relocated closed/cancelled/partial specs,
  WI-504) — `kitlib.registry.parse_spec_frontmatter` requires the file's
  FIRST LINE to be the `+++` TOML fence, and `parse_spec_deliverable`
  requires the body (after frontmatter) to start with exactly
  `## Deliverable` (or be empty) — a banner line ahead of either breaks the
  parse with a hard `ValueError`, which `check_trajectory`/the registry
  reader surface as an R-A error. Confirmed by reading
  `kitlib/registry.py` `parse_spec_frontmatter`/`parse_spec_deliverable`
  directly, not inferred from the WI's warning alone.
- `docs/archive/last_approved/**` (8 files: the approval snapshot,
  `baseline_snapshot.py`) — this tree is byte-compared against the live spine
  registries to detect post-approval drift; a banner line on any of the 7
  TOML/CSV copies would desync every cell comparison and manufacture drift on
  every row. The one `README.md` inside is unaffected by the comparison but
  was left alone too, for the same "this whole directory is machinery"
  boundary the archive README already draws.
- `docs/archive/plans/2026-08-10-carrier-cutover.patch` — a literal git diff;
  a prepended line corrupts it as a patch record.
- `docs/archive/Links.rtf` — a binary-ish container format (`{\rtf1...`); a
  prepended plain-text line corrupts the RTF parse.
- `docs/ratify/` dated briefs and `docs/log.d/` fragments were never in scope
  — neither lives under `docs/archive/`. `docs/ratify/` dated briefs are
  additionally approval-immutable (`check.py approval_immutability` refuses
  edits to them regardless).
