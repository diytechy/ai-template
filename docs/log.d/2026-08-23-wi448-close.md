**Neither half was ever in the census population**, which is worth stating
because the census reads `0 / 0 / 0` on both sides of this commit. The keys are

**THE COPIES DISAGREED, and the pin was blind to it.** `bootstrap._toml_scalar`
escaped the backslash and the quote and nothing else; `wi_convert.toml_string`
escapes those plus every control character, `\uXXXX` for the ones TOML has no
shorthand for. So a cell carrying a TAB — which nothing in the shipped brief has
today, and any adopter editing the constant could add — made the scaffolder emit
a basic string `tomllib` then REFUSES: a scaffold writing a registry it cannot
read back. The retired pin compared only the KEY SET, so the emitter's
disagreement was outside what it looked at. Same shape as slice 3's `LLR_EXEMPT`
type and slice 4's false sync claim: the pin's text described a guarantee
narrower than its name.

### Where each half went, and why there

**The keys → the schema of record moved to `kitlib/spine.py`.** Not "OI-ID's
tuple" — the whole map, both halves and the composed `REGISTRY_KEYS`. Moving one
tier's keys would have split the schema of record across two files, which is the
defect class this program exists to remove, not an instance of removing it. The
placement is the module's own one-line thesis read at the row grain: `spine.py`
is "what one registry row's cells MEAN", and which keys a tier declares is that
statement made about the row instead of about a cell. It is the `station.py`
shape (a home that was correctly SINGLE and wrongly PLACED), not a consolidation:
the carrier READS registries, and the vocabulary it reads them in has readers the
carrier cannot serve. `bootstrap.py` is precisely that reader — it may import the
shipped package and no other sibling — which is why it restated the keys at all.

**The emitter → `kitlib.spine.toml_string` / `.toml_value` / `.toml_fields`,**
the careful version, with `wi_convert` re-exporting all three under the spellings
it has always used (`render_frontmatter` is `toml_fields`) and `bootstrap`
binding `_toml_scalar` to `toml_value`. `migrate_carrier.toml_scalar` STAYS and
that is a decision, not an omission: it promotes a long or newline-bearing cell
to a MULTI-LINE basic string, which is the only reason the spine's prose cells
are readable in the file. A different rule about the same syntax, one home, one
caller (the one-shot CSV → TOML conversion), and folding it in would put a
line-length policy inside the emitter every writer shares. Recorded in the shared
module's own comment so the next reader does not "finish the job".

**The refusal replaces the pin.** `append_stack_checklist` now keys its cells BY
the shipped schema, emits them in the SCHEMA's order rather than the literal's,
and RAISES on a key the tier does not declare. Drift made unrepresentable instead
of detected — the WI's stated preference, and the thing a pin structurally cannot
do. Byte-identical output: the brief's key order was already the schema's order
minus the four cells it does not fill, verified below.

### What was NOT taken, and why

* **`kitlib.evidence.render_fields` is not the emitter's home.** It is the same
  SHAPE (ordered fields, a value formatter, `k = v` lines) and slice 4 placed it
  in `evidence`. Two contracts differ where it matters — `render_fields` renders
  `(absent)` for a missing field, which a TOML row must never emit — so binding
  one to the other would have meant a flag argument. Left as a **finding for
  WI-483**: the joiner now has two homes with different absence rules, and if a
  third consumer appears the question is where the generic form belongs, not
  whether these two should collapse.
* **`gen_release_checklist.load_csv`** — slice 4 left this near-copy standing and
  handed it to "whoever takes item 2". It is still standing, and for slice 4's
  reason unchanged: adopting `kitlib.spine.load_csv` would CHANGE decode
  behaviour on a mis-encoded registry (crash → replacement character). That is a
  behaviour decision needing its own row, and this slice's rule was
  byte-identical CLI.
