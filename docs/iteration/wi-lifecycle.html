Where the code differs from the expected phases

  • No plan phase in the loop. The dual-plan round (two planners, cross-critique, two arbiter runs) runs only through agent_loop.py --dual-plan. The loop refuses a PlanMode=dual row at preflight.
  • No adjudication inside a work lane. The merge slot refuses an approval act from a work lane. Adjudication and observation re-judges are separate rows that intake mints on trunk after the merge, each run in its own lane later.
  • The refresh merges trunk into the lane (git merge --no-ff --no-commit), regenerates the derived views there, runs the full declared bar, and commits a Bar-Green attestation. Trunk never regenerates after the merge.
  • The lane closes itself. The builder moves its spec to its terminal folder inside the lane; the merge never moves a spec.
  • Merge and archive: the loop merges --no-ff and deletes the branch. Squash commits and archive/lanes refs are the coordinator's hand path only.

Dials that shape this run (this repo)

  • One lane at a time: docs/stack.ini declares no lanes.
  • review_rounds = 1: REVIEW-A only. adjudication_review = "when-minting".
  • human_approval_through = "DevStg-Boundary"; push = "human".
  • Retained adjudicator sessions are off (context_reset_pct = 0).
  • docs/work/pause is tracked, so the loop claims nothing until a reviewed commit deletes it.
