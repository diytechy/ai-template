Keeping a separate serial resume path beside the dispatcher was rejected: two authorities over one decision drift, and the divergence surfaces as a run that resumes differently depending on how it was started.

## SR-247 — An earlier kit's stored values reach the current vocabulary through a migrator

> **Requirement.** The delivered kit shall provide a migrator that rewrites, in place, the stored values an earlier kit vocabulary spelled differently and a current script still reads, and that changes nothing else in a file it rewrites.

> **Rationale.** The kit's vocabulary was unified so that one word names one thing, and the core scripts hold no reader of an earlier spelling. A repository that still stores one would then read as if the value were absent, so a purpose-built migrator is the path from an earlier kit and the one place the earlier spellings are known. It rewrites whole values in known places and proves each rewrite by parsing the file again, because a migration that guessed inside prose, or changed a cell it was not asked to change, would alter a record nobody reviewed. Its record step writes each copy equal to live, absorbing the drift then pending and naming each accepted cell it absorbs, which a record judged as whole files accepts. Once the record's act ledger lists the rows an act kept, each later copy is judged at the row, and a copy written equal to live would carry a kept row's text into the record with no act. So the migrator then writes no copy, and a record that still stores an earlier spelling stops the run whole: respelling the live registries beside an unrespelled record would leave the two in different vocabularies, and the current scripts would read an accepted live row as an acceptance the record does not hold. The way out is the one the re-sync guidance gives, running the migrator before the record's first row-by-row act.
