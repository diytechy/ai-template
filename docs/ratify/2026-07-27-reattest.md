## SR-127 — Requirement form: one testable obligation

_Baseline `a5052a913` (2026-07-25) — from `--since`._

### SR SR-127 — ADDED since baseline
- **SR-ID**: SR-127
- **Title**: Requirement form: one testable obligation
- **SN-Refs**: SN-002;SN-004
- **Requirement**: trace.py shall fail under --strict when a non-Draft requirement repeats its obligation keyword, uses a different modal in normative text, states an obligation with no actor, or uses an unfalsifiable or open-ended term.
- **Rationale**: Realizes SN-004 — when one row carries two obligations and only one holds, no id reports the failure, so the gate passes on a partially-met requirement. Undecidable wording fails differently and worse: an unfalsifiable adjective cannot be tested, so the row is signed on impression. Each rule is a LEXICAL proxy for a semantic property and is scoped to what it can actually decide — counting the obligation keyword catches the shape that recurred here and does not claim to find every multi-obligation row. A semantic check was rejected as out of reach for a stdlib checker, and a readability score was rejected as a proxy for the wrong property: it measures prose complexity, not whether a reader can tell what is binding.
- **AcceptanceCriteria**: A second `shall`, a non-`shall` modal, an actorless `shall be <participle>`, an unfalsifiable term, an open-ended escape clause, or a `shall` in an LLR Detail exits 1 under --strict; a Draft row, a zero-`shall` row, `must` as a project's own obligation keyword, and a multi-clause AcceptanceCriteria do not.

## SR-128 — Paraphrase advisory

_Baseline `a5052a913` (2026-07-25) — from `--since`._

### SR SR-128 — ADDED since baseline
- **SR-ID**: SR-128
- **Title**: Paraphrase advisory
- **SN-Refs**: SN-002
- **Requirement**: trace.py shall warn (never fail) when an SR Rationale re-words its own Requirement, or an LLR Detail re-words its parent SR Requirement, past a declared word-overlap threshold.
- **Rationale**: Realizes SN-002 — a child that restates its parent adds a second home for one fact and no decomposition, so the trace grows a level without gaining information and a later amendment updates one copy. It warns rather than fails because the detector is word overlap: a short, correct Detail legitimately shares vocabulary with the requirement it decomposes, and gating on a heuristic with a large legitimate majority produces a check that gets scrolled past. The two relationships named are the ones where the parent is unambiguous; a general child-cell rule was rejected because 'the parent' is not well defined for the rest.
- **AcceptanceCriteria**: An SR Rationale overlapping its own Requirement, or an LLR Detail overlapping its parent SR Requirement, past the declared threshold emits a stdout WARNING and a report line; the exit code is unchanged.
