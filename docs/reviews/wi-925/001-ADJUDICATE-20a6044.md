## Finding F1: the relink remap omits the spec-of-record archival pair

**What the plan does.** P5 (`docs/plans/WI-925/plan.md`, lines 562-590) builds `_relink_remap(entries)` from close pairs only: a `D` under `active/<branch>/` with an `A` of the same work-item id under a closed folder. The exemption drops a claim-copy change only when that copy's single `M` is exactly the inbound relink under that remap. A spec-of-record archival (`spec_move.py --archive docs/specs/<name>.md` to `docs/archive/specs/<name>.<date>.md`) is not in the remap. `spec_move.py`'s own docstring documents that archival as part of the close move, and `docs/specs/README.md` says a spec-of-record exists only while its work item is open. So if Y's Done-when links X's spec-of-record and that archival lands in the same delta, Y's relinked copy is still judged a change, and the landing is held. The finding's facts hold, and the coordinator does not contest them.

**Weighing it under §6.** The scenario is not contrived: the archival is a documented close route, and a Done-when link is ordinary text. So `out-of-scope` does not apply. Its weight is what decides the ruling:

- **It fails closed.** The miss holds a landing rather than releasing one. The recovery is the gate's own ordinary route, a done-when sitting that blesses the digest. Nothing is lost and nothing escapes judgement. The only cost of a miss is one extra sitting.
- **Its reach is unobserved.** Across all 221 work-item specs in `docs/work/` and `docs/archive/work/` that carry a Done-when section, none holds a markdown link to a spec-of-record. None links another work-item spec either: the parent scenario deliverable 3 exists for is itself "found by reading, not reproduced", which is why its Done-when makes the deliverable conditional on a reproduction.
- **It is not a Done-when gap.** The relink item (D8) is scoped to its fixture: row Y's Done-when links row X's spec, X closes through `spec_move`, and the squash landing is held before and passes after, a real edit beside the relink is still held, and one shared stage holds the reading. P0 to P5 cover that item exactly. The omission narrows deliverable 3's general wording ("a spec move the same staged delta carries") to the move that fixture exercises. It leaves no Done-when item uncovered and opens no fail-open path, so it is not convergence-class.
- **The fix costs more than the defect.** Extending the remap is a few lines in the code, but it widens an exemption to the Done-when hold, a surface where every added pattern needs its own exact-byte proof. It also needs a revision of a plan that is already at its cap, where only an accepted DISMISS lets the pass record be written. That spends an owner decision and a re-plan to remove a fail-closed, recoverable hold no repository content has ever produced.

**Advisory, not a condition of this ruling:** the lane can state this pair honestly as a bound rather than leave it silent. Deliverable 4's one residue list and LLR-307's bound sentence could name it, with its recovery: "a spec-of-record archival in the same delta is not in the relink map; a Done-when it relinks is held until blessed". If a Done-when link to a spec-of-record ever appears in practice, the single stage P4 extracts is where the pair goes, by the same 0-to-A-to-B rule.

RULING: F1 DISMISS not-worth-cost the omitted spec-of-record archival pair fails closed (a held landing the existing done-when blessing recovers), no Done-when section among 221 work-item specs links any spec, and D8's fixture-scoped item is fully covered, so a capped-plan revision widening the hold's exemption costs more than the rare, recoverable hold it removes
