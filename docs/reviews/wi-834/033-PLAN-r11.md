## R3 (O1): a test that arms the window from the real clock

- **Found** while running round 11's affected modules:
  `tests/test_run_devsetup.py::test_an_installed_hook_denies_with_an_older_python_first`
  (round 5) arms `now-1h..now+1h` and runs the installed hook through a
  shell as a subprocess, so the in-process clock patch
  (`agent_policy._utcnow`) cannot reach it. Windows start Monday to Friday
  only, so at Sat 2026-10-10 01:10 UTC no window was in force, the hook
  printed nothing, and `json.loads` failed.
- **Class:** a subprocess test that arms the blackout window relative to the
  real clock, so it passes or fails by weekday. Search:
  `rg -n "datetime.now|timedelta\(hours" tests/` over the lane's tests, then
  each hit that runs the hook or a launcher as a subprocess. One site, the
  one above. Not in the class: `test_blackout_window.py` (in-process, the
  `clock` fixture; its only subprocess is `git`), and `test_agent_loop.py:329`
  (a window 30 minutes ahead, inactive on every day).
- **No seam:** the guard reads its clock from `agent_policy._utcnow`, which
  no subprocess can set. A production override is the coordinator's call, and
  was declined, so the fix is test-only.
- **Construction:** on any day the hook command, run through the shell with
  the real `C:\Python38` first on PATH, exits 0 with no traceback and no
  `ModuleNotFoundError` (the pre-fix bare-`python` command fails this on any
  day: it raises `ModuleNotFoundError: No module named 'tomllib'`). The deny
  is asserted only when `agent_common.blackout_at`, run in the test process
  on the same declared value, says the window is in force; otherwise the
  hook printed no decision.
