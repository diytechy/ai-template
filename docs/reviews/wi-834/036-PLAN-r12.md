  `"C:/Projects/ai-template/.venv/Scripts/python.exe" project-trajectory/scripts/coordinator_guard.py status`.

    quoted string followed by a word is not a command without `&`.
  - In Git Bash it runs from this repository's root. Run from any other
    directory it fails: `can't open file '...\scratch\project-trajectory\scripts\coordinator_guard.py'`.

    scaffold ships the guard as `scripts/coordinator_guard.py`

  as typed in a supported shell.
- **Sites** (every reader of the producer,
  `rg -n "\bGUARD\b" project-trajectory/scripts/coordinator_guard.py tests`):
  - `INSTRUCTION`, the request-relaunch step;
  - `take`'s held-lease refusal (`release --reason`);

  - `hand_back`'s not-holder refusal (`release --reason`);

  the hook's own interpreter (`sys.executable`, D-019) and the guard's own
  file (this module's resolved path, so it runs from any working directory
  and in a scaffold), both with forward slashes.

    (letters, digits, `_ . / : -`), it emits one form, unquoted:
    `` `C:/.../python.exe C:/.../coordinator_guard.py status` ``. That runs as
    typed in Bash and in PowerShell.
  - Otherwise (a space, a parenthesis, `$` ...) it emits the two forms side
    by side, each quoted for its own shell (single quotes, with that
    shell's escaping of a single quote): `` `'…' '…' status` (Bash) or
    `& '…' '…' status` (PowerShell) ``.

    `{command}` field, so a brace in a path can never break the template's
    formatting.

  interpreter. It runs twice: once for this interpreter's plain path, and
  once for this interpreter reached through a link whose name holds a space
