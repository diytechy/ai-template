| ESLint: 'warn' never affects the exit code, 'error' exits 1, and warn is meant as a transitional level before error. | https://github.com/eslint/eslint/blob/main/docs/src/use/configure/rules.md — 'Configure Rules' (source of eslint.org docs), ESLint team, 2025; fetched 2026-11-05 (eslint.org not reachable) | This is typically used when introducing a new rule that will eventually be set to "error". | check.py's 'WARN-ONLY ALWAYS' classes (check.py:765-768, 911-912) are reports, not warnings, and belong in the trace report/dashboard rather than on the commit floor's stdout. |
| ESLint bulk suppressions (9.24.0) store a per-file, per-rule count — no line numbers — and exit non-zero when suppressions go unused unless pruned. | https://github.com/eslint/eslint/blob/main/docs/src/use/suppressions.md and lib/services/suppressions-service.js:24; version per https://github.com/eslint/rfcs/blob/main/designs/2025-bulk-suppressions-api/README.md, ESLint team, 2025; fetched 2026-11-05 | There are suppressions left that do not occur anymore. Consider re-running the command with `--prune-suppressions`. | The kit's complexity ratchet keyed by function name that FAILs on improvement (check_complexity.py:448-463) should become file(+rule) counts with a one-command prune/restamp. |
| rustc gives every lint a declared default level, the compiler default is warn, and lints in dependencies are capped so they cannot pollute the build. | https://github.com/rust-lang/rust/blob/master/src/doc/rustc/src/lints/levels.md — rustc book 'Lint Levels', Rust project, 2025; fetched 2026-11-05 (doc.rust-lang.org not reachable) | it will pass `--cap-lints allow` when compiling your dependencies, so that if they have any warnings, they do not pollute the output of your build. | Kit-owned rows and files inside an adopter's repo are its 'dependencies'; their advisories should be capped, not printed on the adopter's floor (check.py steps table). |
| Among rustc's built-in lints warn-by-default is the majority and deny-by-default a minority (measured). | https://raw.githubusercontent.com/rust-lang/rust/master/compiler/rustc_lint_defs/src/builtin.rs, Rust project; fetched 2026-11-05; command: grep -cE '^\s+(Allow\|Warn\|Deny\|Forbid),\s*$' | measured: Allow 38 / Warn 80 / Deny 37 / Forbid 0 over 6,056 lines (regex over declare_lint! blocks; approximate) | A declared default-level table per step, with warn as the common default, is the model for check.py:501 steps() instead of per-step prose. |
| #![deny(warnings)] is an anti-pattern because new lints and deprecations break builds that used to pass. | https://github.com/rust-unofficial/patterns/blob/main/src/anti_patterns/deny-warnings.md — Rust Design Patterns, 'Deny warnings', rust-unofficial, 2024; fetched 2026-11-05 (rust-unofficial.github.io not reachable) | All this conspires to potentially break the build whenever something changes. | Promoting whole advisory classes to failures at DevStg-Impl via --strict (check.py:577-622) makes every newly added advisory a gate failure for every adopter at that rung. |
| Ruff's default rule set is a curated correctness list that omits stylistic rules overlapping with a formatter. | https://github.com/astral-sh/ruff/blob/main/README.md:317-319 and crates/ruff_linter/src/settings/mod.rs:357 (DEFAULT_SELECTORS), Astral, 2025; fetched 2026-11-05 (docs.astral.sh not reachable) | omitting any stylistic rules that overlap with the use of a formatter | The floor's default set should be integrity/correctness steps; form and vocabulary advisories (need-form, vocab, Title length) default to opt-in or report-only. |
| flake8 ships a default ignore list for contested stylistic codes and an --exit-zero escape hatch. | https://github.com/PyCQA/flake8/blob/main/docs/source/user/options.rst — flake8 'Full Listing of Options', PyCQA, 2025; fetched 2026-11-05 (flake8.pycqa.org not reachable) | This defaults to: E121,E123,E126,E226,E24,E704,W503,W504 | A shipped default allow-list for form advisories (the kit's orphans-allow.template pattern) is the mature-linter norm, in place of per-row WARNs on every commit. |
| Betterer commits a results file that auto-updates when a result improves and fails only when it gets worse. | https://github.com/phenomnomnominal/betterer (README; website/docs/introduction.md; website/docs/results-file.md), Craig Spence, 2020-2024; fetched 2026-11-05 (phenomnomnominal.github.io not reachable) | If it gets better, the .betterer.results file will be updated with the new result ✅! | An improvement should auto-tighten the baseline, not FAIL the step as check_complexity.py:457-462 does ('RE-STAMP DOWNWARD ... in this same commit'). |

| RuboCop's generated todo file is a debt list to burn down entry by entry, with a regenerate command. | https://github.com/rubocop/rubocop/blob/master/docs/modules/ROOT/pages/usage/auto_gen_config.adoc — 'Automatically Generated Configuration', RuboCop team, 2025; fetched 2026-11-05 (docs.rubocop.org not reachable) | Then you can start removing the entries in the generated `.rubocop_todo.yml` file one by one | One kitlib.ratchet with --restamp/--prune serves all three kit baselines (complexity, flag-axis, module-size) instead of three implementations. |

| pre-commit runs hooks only on staged file contents and treats the whole-tree run as a CI step. | https://github.com/pre-commit/pre-commit.com/blob/main/sections/advanced.md (source of pre-commit.com 'Advanced features'), Anthony Sottile, 2025; fetched 2026-11-05 (pre-commit.com not reachable) | pre-commit only runs on the staged contents of files by temporarily stashing the unstaged changes while running hooks. | hooks/pre-commit:288 runs 25 whole-tree steps with no file scoping; only the ruff step (:326) is staged-scoped. |
| The whole-tree run belongs in CI (`pre-commit run --all-files`), with an option to check only changed files for speed. | same file as above (sections/advanced.md 'Usage in continuous integration'); fetched 2026-11-05 | adding `pre-commit run --all-files` as a CI step will ensure everything stays in tip-top shape. | project-trajectory/ci/check.yml already runs the full tier; the hook can drop whole-tree generators without losing enforcement. |
| lint-staged exists because whole-project lint runs are slow and irrelevant to the commit at hand. | https://github.com/lint-staged/lint-staged/blob/master/README.md — 'Why', Andrey Okonetchnikov et al., 2025; fetched 2026-11-05 | But running a task on a whole project can be slow | Extend check.py --path-triggered (hooks/pre-commit:287) so generator steps run only when their input paths are staged. |
| Google's presubmit runs only fast, reliable tests; slower or flaky work goes post-submit. | https://github.com/qiangmzsx/Software-Engineering-at-Google/blob/master/zh-cn/Chapter-23_Continuous_Integration/Chapter-23_Continuous_Integration.md — bilingual mirror of Winters, Manshreck, Wright, 'Software Engineering at Google' (O'Reilly, 2020), ch. 23; fetched 2026-11-05 (abseil.io not reachable) | Our general rule of thumb is: only fast, reliable ones. | History-dependent and whole-repo steps (approval-fresh, registry-integrity, open-items, trajectory-map) are post-submit/merge-slot class, not commit-hook class. |

| Copier composes several independent templates on one project through separate answers files. | https://github.com/copier-org/copier/blob/master/docs/configuring.md:1997 'Applying multiple templates to the same subproject'; fetched 2026-11-05 | You just need to use a different answers file for each one. | The core + unattended-station + domain-skills split proposed in the first pass (§7.2) has a worked precedent: each layer its own stamp and manifest. |

| An ADR captures a single decision and its rationale; the collection is the project's decision log. | https://github.com/adr/adr.github.io/blob/master/index.md (adr.github.io), ADR GitHub organization, 2025; fetched 2026-11-05; credits Nygard's 2011 post | An Architectural Decision Record (ADR) captures a single AD and its rationale | Owner rulings are architectural decisions; give each a record with a stable global ID (decisions.template.toml numbers D-NNN per run). |
