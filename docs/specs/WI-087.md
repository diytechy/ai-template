# WI-087 — Hierarchical, phase-aware When & How drill-down views

**Status: active — G1 batch drafted** (2026-07-12, phase v2; `SR-050` is the
requirement of record. The owner directed implementation in this session; its
separate Draft→Planned commit records attended ratification.)

## Goal

Give the dashboard's **What**, **When** (roadmap DAG), and **How-SW** (module)
views a
count-thresholded, click-to-explode hierarchy — "Simulink-style" blocks a viewer
clicks into — so a large project reads top-down (phase → workstream → work item;
component → module) instead of as one dense graph. Surface the delivery
**Phase** and current delivery frontier on the When view, and replace the
leaf-height icicle with a readable, complete multi-parent traceability flow.

The detailed design and block sequencing live in the root
`PROJECT_STATE_REDESIGN_PLAN.md`; this spec is the concise requirement handoff.
The subjective acceptance surface is the
[dashboard visual critique rubric](../rubrics/WI-087-dashboard-visuals.md).

## Builds on (the foundation already exists)

- **When:** campaign binning (WI-074) already renders collapsed `<details>`
  campaign containers with **campaign-crossing edges aggregated** to one deduped
  container-to-container edge. This WI adds tiers above/beside it.
- **How-SW:** component containment (WI-073) already renders a containerized top
  view (≤ 10 bound), expandable members, and **boundary-aggregated
  cross-component seams**. This WI generalizes the interaction.
- So "connections inherited for parents from children" is an **existing idiom**
  (edge aggregation to the container) — apply it at each new tier.

## Owner requirements (to ratify at G1)

**What view — readable traceability flow:**
- Four left-to-right dotted/tinted tier containers: SN → SR → LLR → TC.
- Uniform readable cards, explicit arrows, and every valid parent relationship
  (including secondary parents); Draft artifacts remain visible.
- Lower tiers may collapse to counts at overview and drill/selection reveals the
  complete neighborhood.

**When view — tiered, count-thresholded drill-down:**
- If **> 3 phases**: the view **starts at phase blocks**; click a block to
  explode it.
- If **> 3 workstreams** (within a phase, or at the top when phases ≤ 3): show
  **workstream blocks**; click to explode into individual work items.
- Bottom tier: the individual-WI DAG (today's view).
- **Parent connections inherited/aggregated** from children (the WI-074 idiom).
- Primary hierarchy: **Phase → Workstream → WI**. Campaign is an alternate
  grouping/filter, not another default nesting tier.
- WI phase derives from referenced SR Phase values and `[phase]-[gN]` anchors;
  mixed values are Cross-phase and absent values are Unphased.
- Phase uses grouping plus text badges. A `NOW · delivery frontier` represents
  phase/lifecycle state, not calendar time. Deferred WIs are parked, never next.

**How-SW view — tiered drill-down:**
- If **> 3 components**: **start at component blocks**; click to explode into the
  software-module items. Parent connections inherited from children (WI-073).

**Interaction:** keyboard-accessible in-panel drill with breadcrumb/back plus a
semantic static fallback, evolving today's native-`<details>` expansion.
Self-contained, byte-deterministic, `--check`-stable (the WI-070/073/074
discipline).

## Ratified design decisions

1. Phase → Workstream → WI is primary; Campaign is orthogonal/alternate.
2. Phase is grouping plus a text badge, not dominant card color.
3. Explode uses breadcrumb drill-in with a semantic static fallback.
4. The `> 3` threshold composes with, but never waives, `TOP_VIEW_MAX = 10`.
5. Declared `IF-###` seams remain the only How-SW architecture edges; no
   inferred import graph.
6. No Horizon/Sequence registry fields: the Now line is an honest delivery
   frontier derived from phase/lifecycle state.

## Verification

A generated view → a **Test** TC (deterministic render, `--check`-stable, the
tiering fires at the > 3 thresholds and is flat below them, aggregated parent
edges match the union of child edges). If an interaction/authored element resists
a data assertion, a **Critique** TC covers its fidelity (the WI-085 pattern).
