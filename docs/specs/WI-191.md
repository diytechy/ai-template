# WI-191 — Specs act on declared interface boundaries (IF citation + Proposed-with-rationale)

**Status: queued (filed 2026-07-16 from the owner feedback session).**

## Problem

PROCESS.md §8 already makes `interfaces.csv` the one home for every directed
seam, and WI-064 mechanized the cross-component-edge-without-IF rule at the
*architecture* level. But nothing binds a **spec-of-record** to that registry
at *filing* time: a spec can freely sketch its own slightly-different seam, and
each spec wanting its own variant is a duplication engine — the exact drift §8
exists to prevent, caught only later (or never). The owner's ruling: work items
should act on defined modules/LLRs or the interfaces that bind them, and the
seams a WI expects should be built out when the WI is constructed.

The dual failure mode is real too: **speculative seams** — interfaces defined
before a second consumer exists tend to be wrong, get bypassed, and re-invented.
The rule below is written to force *search* before *invention*, not to force
invention early.

## The rule

1. **A spec-of-record gains a required `Interfaces` section** (the spec
   template + the PROCESS_OPTIONS spec-of-record contract): every seam the
   spec's WIs act on is cited as an `IF-###` that resolves in
   `requirements/interfaces.csv`.
2. **A new seam enters the registry at filing** as a `Status=Proposed` row
   with contract text, and the spec's citation carries a **rationale naming
   the nearest existing IF-ID and why it does not suffice**. The forced
   search is the anti-duplication mechanism; `Proposed` rows stay cheap to
   revise until a second consumer pins them.
3. **Scope guards unchanged:** §8's scoping holds — seams *between* modules
   (or repos/external actors), never intra-module ceremony; single-module
   standalone projects keep skipping §8, and a spec whose WIs are genuinely
   intra-module states that in the section instead of inventing a seam.

## Enforcement (per the enforcement-audit ranking)

- **Harness (mechanical):** the checker (`check_trajectory` or a `trace`
  finding — pick the natural home at build time) verifies that a spec's
  `Interfaces` section cites only resolvable IF-IDs, and that a `Proposed` row
  referenced from a spec carries a non-empty rationale. Presence is checkable;
  vacuous-until-armed so existing specs and downstream repos stay green until
  they adopt the section.
- **Reviewer (semantic, the honest gap):** whether a rationale is *honest* and
  whether a `Proposed` contract is a near-duplicate of an existing seam is a
  judgment call — token-window duplicate detection (`check_dupes`) works on
  code, not contract prose. Record the gap in
  [enforcement-audit.md](../enforcement-audit.md) and add a **critique-rubric
  anchor** (`B#`: "proposes a near-duplicate of IF-### instead of consuming or
  amending it") so plan/spec critiques cite it — this anchor is what WI-190's
  plan rubric imports.

## Done-when

- [ ] The spec template and the PROCESS_OPTIONS spec-of-record contract carry
      the `Interfaces` section rule (+ the intra-module escape hatch), within
      byte budgets.
- [ ] `INTERFACES.template.md` / the interfaces template documents `Proposed`
      + the rationale expectation.
- [ ] The mechanical check exists (resolvable IF-IDs; rationale presence),
      vacuous-until-armed, with tests.
- [ ] The enforcement-audit row records the semantic near-dupe gap and its
      Reviewer-tier enforcer; the rubric anchor exists for WI-190 to import.
- [ ] The kit's own live specs pass the armed check (retrofit the section
      where a live spec still fronts open WIs — this file and WI-189/WI-190
      included).

## Non-goals

- No automatic semantic dedupe of contract prose.
- No new required work for single-module adopters; the section arms only where
  §8 applies.
- No retro-editing of *closed* specs (history stays history; only specs
  fronting open WIs get the section).
