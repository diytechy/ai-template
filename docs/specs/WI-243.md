# WI-243 — Re-arm the perceptual dashboard critique (re-fire on render-surface diffs + judge rendered pixels)

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-20 (owner directive,
from the 2026-07-20 quality-gap review) · **BuildTier:** strong ·
**SafetyClass:** high-risk (touches the Critique TC spine + the derived-gate
re-fire semantics).

## Why

The three `Verification=Critique` **perceptual** requirements — **SR-052**
(accessibility), **SR-053** (uniformity), **SR-054** (usability) — are all
coasting on a **single human critique from 2026-07-15**
([074-CRITIQUE.md](../reviews/074-CRITIQUE.md): *"APPROVE… approved as sufficient
for now… the graphic breakdown may need further iteration in the future"*). A
Critique TC that goes `Verified` once **never re-fires**, so perceptual quality
regresses silently across every later dashboard regeneration (the WI-218 file
split, WI-226/229/234/236, dozens of `gen_trajectory.py` runs since).

Concrete field evidence (owner, 2026-07-20): the live `PROJECT_STATE.html` ships
**multiple hard-to-read tabs** — exactly the **T1** (task findability within one
tab switch) and **T4** (label legibility — "no clipped, truncated, or
overlapping text") failures the [dashboard-usability rubric](../rubrics/dashboard-usability.md)
*already names*. It is not a rubric-content gap. It slipped because:

1. **The perceptual critique isn't re-triggered on change** — TC-055 is a
   frozen `Verified` stamp (2026-07-15), not a standing gate.
2. **Ordinary reviews structurally can't see it** — a `gen_trajectory.py` change
   gets a REVIEW-A/B pass against the *diff* ([code-review-adversarial](../rubrics/code-review-adversarial.md)),
   which reads source, never rendered pixels. Per the
   [render-dashboard-critique](../../project-trajectory/skills/render-dashboard-critique/SKILL.md)
   skill, agent critiques "historically judged ~790 KB of markup, never what a
   viewer sees." A clipped label is invisible in a diff.
3. **The Critique TC doesn't yet name the render recipe** — the skill flags
   itself as "the artifact recipe a *future* `Verification=Critique` TC would
   name." So TC-055's critic is handed the HTML artifact, not the PNG matrix.

## Scope

1. **Wire the render recipe into the Critique TCs.** TC-055 (and the SR-052 /
   SR-053 critique TCs) name `scripts/dashboard-shots/shoot.mjs` as their
   artifact recipe, so the critic receives the **rendered PNG matrix**
   (widths × themes × tabs, incl. the 390px mobile landing), not the markup.
   Update each TC's Method/Evidence accordingly.
2. **Re-fire trigger.** A change whose diff touches the dashboard-render surface
   (`gen_trajectory.py`, the dashboard template/CSS/JS it emits, `shoot.mjs`)
   knocks the three perceptual TCs back to needs-re-verify rather than coasting
   on `Verified` — i.e. a render-surface diff **re-opens the perceptual gate**.
   Design the mechanism consistent with the derived-gate model
   ([derive_gate.py](../../project-trajectory/scripts/derive_gate.py) /
   `check_trajectory`) — a Critique TC's `Verified` state is invalidated by a
   render-surface diff — and consistent with whatever **OI-7** rules for
   code-review cadence (**related, not blocking**: OI-7 governs *code* review
   cadence; this governs *perceptual-critique* re-fire).
3. **Make the render-based critique non-optional for a render-surface change**
   in this meta-repo (the runner is `scope: this-repo`, meta-only — no
   downstream install cost): a dashboard-render diff cannot reach a green gate
   without a fresh critique against the *current* PNGs. Downstream, the kit
   ships the perceptual-TC contract; the Playwright runner stays meta-only per
   the skill.

## Non-goals

- **No dashboard redesign** — a rendered defect becomes its *own* WI (the
  skill's "builds the eyes; it is not a redesign"), never an inline fix here.
- **No rubric enrichment** — raising the *bar* the critic judges against is
  WI-244 (taste-skill distillation); this WI re-arms the *firing*.
- **No downstream Playwright dependency**; **not blocked on OI-7** (designed
  consistent with it).

## Done-when

TC-055 (+ the SR-052/SR-053 critique TCs) name the `shoot.mjs` render matrix as
their artifact recipe and their evidence is a critique of the rendered PNGs, not
the markup; a diff touching the dashboard-render surface **demonstrably re-opens**
the three perceptual TCs (a test drives this — it fails on the pre-fix
"stays-Verified" behavior); a render-based critique is required before a
render-surface change reaches a green gate; the full suite + `check.py` at the
derived gate are green; any spine method/evidence edits are reflected in the
counts and any `PROCESS_OPTIONS.md` byte delta is reported within budget.

## Resolution — 2026-07-20 (owner ruling: FAIL-CLOSED)

Owner ruled **fail-closed** (after confirming the downstream blast radius is
near-zero — below). Implemented in `critique_staleness_findings` +
`check_trajectory.main`: the perceptual re-fire is **WARN at the commit bar,
ERROR under `--strict`** — and `check.py` adds `--strict` at **G2/G3** (not at the
pre-commit floor). So a plain commit is never blocked (fast WIP), but a **stale
render surface cannot reach a green G3 gate** — the agent-proof forcing function.
It rides the existing strict-promotable findings loop (the `run-state` precedent),
so `main()` gains no branch (C901 21 held). Tests:
`test_critique_staleness_fails_closed_under_strict` (exit 1 under `--strict`) +
`_warns_at_commit_bar_...` (exit 0 non-strict) + the vacuous/off-git/evidence-newer
cases.

**Downstream safety (verified):** the check is **vacuous without a
`Verification=Critique` SR**, and no shipped `registries/*.template.csv` carries a
non-example one (grep-verified) — so a fresh scaffold and any adopter not using the
Critique method pays nothing at either tier. The watched render surface is the
co-located `gen_trajectory.py` (a kit script the adopter doesn't edit) + the
meta-only `shoot.mjs` (absent downstream); and the whole checker is opt-out via
`docs/trajectory-check`. So fail-closed is effectively a *this-repo* gate decision,
not a downstream migration.

**Lands green now:** 076-CRITIQUE re-judged the current render, so the surface is
fresh vs the evidence — `check_trajectory --strict` exits 0. The gate reddens only
on the *next* render-surface change until re-critiqued (the intended behavior; e.g.
building WI-246/247/248 will then require a fresh critique). The 4 REVIEW-A MINORs
remain dispositioned as recorded (446d5ca).
