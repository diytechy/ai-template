# WI-200 — Restore status.md forward-only enforcement (parallel-dispatch robust)

**Status: queued (filed 2026-07-16 from the owner's status.md hygiene
finding).** Owner prompt: closed WIs were reappearing in `status.md` as a wall
of accreted history despite the file's forward-only contract — "I thought test
cases were built to ensure that status.md kept a clean format."

## Problem

The owner's memory is correct: `check_trajectory` R-D made a `done` WI id in
`status.md` a strict-tier finding, and the log shows it repeatedly forcing
done-id scrubs at close. **WI-180 retired R-B/R-C/R-D** on the rationale that
under parallel dispatch `status.md` becomes an *integrator-generated snapshot*
whose currency is enforced by generated freshness — but this repo (and any
downstream repo not running the parallel integrator) still hand-edits
`status.md`, so the rule silently regressed from Harness-tier to Prose-tier.
Prose failed within days: every session from WI-188 through WI-190 appended a
"CLOSED (…)" narrative, and the Current State spine counts went stale. The
2026-07-16 prune fixed the instance; this WI restores the **enforcer** so the
regression cannot recur.

## Design sketch (firm up at start)

Restore the done-id rule as a **mode-aware** check in `check_trajectory`, so it
is robust in — not reverted by — the parallel-dispatch world:

1. **Hand-edited mode (the default today):** a `done` WI id appearing as a
   token in `docs/status.md` is a finding — WARN plain, **ERROR under
   `--strict` (G2+)**, the pre-WI-180 severity. An explicit prose exemption is
   NOT offered (the log is the home for history; a legitimate historical
   mention belongs there).
2. **Generated-snapshot mode (the WI-180 direction):** when `status.md` carries
   the standard generated-block marker (the `gen_arch_map`/`gen_trajectory`
   marker idiom), the token rule yields to a **freshness** check — regenerate
   in memory and byte-compare, the `--check` idiom — because a generated
   snapshot cannot accrete prose. This keeps WI-180's rationale intact instead
   of reversing it: the retirement's promise (generated currency) becomes real
   before the prose rule stands down.
3. **Parallel-dispatch robustness:** the check is a repo-state rule evaluated
   at every commit/gate like R-A, not a staged-diff rule — under `--jobs N`
   only the serialized integrator publishes to the shared branch, so the
   invariant holds at every published tree; a worker that closes a WI scrubs
   its id (or the integrator's status write does) before publish, exactly as
   R-D forced single-lane sessions to do.
4. **Downstream posture:** same opt-outs as the rest of the trajectory check
   (`docs/trajectory-check: off`; vacuous on absent/placeholder registry).
   R-B/R-C (open ids copied into prose) stay retired — that half of WI-180's
   rationale was sound and is not the anti-bloat rule.

Also: restore the rule's row in `docs/enforcement-audit.md` (it currently
reads as an honest gap), and re-state the forward-only bar in
`STATUS.template.md` if the template's phrasing predates the retirement.

## Interfaces

Intra-module: the rule lands inside `check_trajectory`'s existing SSOT-rule
surface — **IF-023** already declares `check_trajectory` cross-reads
`docs/status.md` alongside the WI registry, which is precisely the join this
check performs; no new seam is minted.

## Done-when

- [ ] A `done` WI id token in a hand-edited `docs/status.md` is a
      `check_trajectory` finding (WARN plain / ERROR `--strict`), covered by
      tests for: clean status, done-id present, opt-out via
      `docs/trajectory-check`, and the vacuous registry case.
- [ ] The generated-marker exemption exists and is tested (marker present →
      token rule stands down; the freshness path is at minimum specified, and
      implemented if the snapshot generator exists by then).
- [ ] `enforcement-audit.md` re-maps the forward-only rule to its
      Harness-tier enforcer; the WI-180 retirement note in
      `check_trajectory`'s docstring is updated to name the restored,
      mode-aware form.
- [ ] The meta-repo's own gate run stays green against the pruned status.md
      (the rule must not flag the "Recently closed"-free, pointer-only form —
      including `deferred` ids named as deferred and OI-subject ids).

## Non-goals

- No R-B/R-C restoration (open-id prose copying stays retired per WI-180).
- No status.md auto-generation in this WI (that is the WI-180 snapshot path's
  own work; this WI only defines how the check yields to it).
- No prose-quality linting beyond the done-id token rule — length/format stay
  the session protocol's job.
