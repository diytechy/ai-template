# WI-325 — the re-attestation brief needs a freshness gate

**Status: queued** (`P1`, raised 2026-07-26 after the brief went stale twice in
one day).

## The observation

`docs/ratify/*.md` is a **generated** artifact — `trace.py --ratify modified`
renders it from the registries — and it is the surface a human reads *while
deciding whether to attest a spine row*. Every other generated surface in this
repo is freshness-gated and the gate is wired into the pre-commit floor:

| Surface | Gate |
|---|---|
| `PROJECT_STATE.html` | `gen_trajectory.py --check` |
| the `docs/status.md` snapshot | `gen_trajectory.py --status --check` |
| `docs/okf/` | `gen_okf.py --check` |
| `docs/open-items.html` | `gen_open_items.py --check` |
| `docs/architecture.md` code map | `gen_arch_map.py --check` |
| **`docs/ratify/*.md`** | **nothing** |

So the brief silently drifts behind the registry it summarizes, and the only
detector is a person remembering to look.

## Measured: it has drifted twice, in one day

| When | What the brief was missing | Consequence if unnoticed |
|---|---|---|
| at `121-CRITIQUE` | `LLR-105`, `TC-108`, `SR-054`'s later `AcceptanceCriteria` edit, and the `LLR-116/117` + `TC-121/122` rows added since | an owner blesses six `Modified` rows having seen four |
| at `123-CRITIQUE` | `LLR-118`/`TC-123`, then `LLR-119`/`LLR-120`/`TC-124`/`TC-125` | an owner blesses `SR-054`'s chain three rows shorter than the registry's |

Both were caught by a human noticing — the weakest enforcement tier in
[enforcement-audit.md](../enforcement-audit.md), and the one this kit exists to
replace.

## The design constraint that makes this harder than its siblings

**`--check` must compare against the baseline the file ALREADY DECLARES, not a
re-derived one.** The brief self-stamps its `--since` revision and reuses it
precisely because the auto-derived baseline is *not* stable: the auto rule is
"the newest revision where the row still read `Verified`", which for a
pre-regime amendment sits *after* the change and reports no delta.

This is not hypothetical. Re-deriving is exactly the
[122-REVIEW-A](../reviews/122-REVIEW-A.md) BLOCKER: a regeneration silently
collapsed 43 chain-row diffs to 18 **and `--check` certified the loss**. A
freshness gate that re-derives its own comparison basis would reintroduce that
defect at the one surface where it is least survivable.

So: parse the stamped baseline out of the existing file, regenerate against
*that*, compare, and fail on any difference.

## Fails closed

A stale brief is read by a human about to attest. Unlike the warn-first lints,
this one is an error — the same tier as the sibling `--check` steps it joins.

## Done-when

- [ ] `trace.py --ratify <scope> --check` compares the rendered view against the
      file at `--out` and exits nonzero on a difference, reusing the baseline the
      existing file declares.
- [ ] A test proves it bites on **both** drift directions — a row added to the
      registry after the brief was written, and a row whose cell content changed
      — and proves it does **not** re-derive the baseline (a brief stamped
      `--since X` still compares against `X` when the auto-derivation would pick
      something else).
- [ ] The step is wired into `check.py` and the pre-commit floor beside the other
      freshness gates.
- [ ] A brief whose `--out` file does not exist is a **no-op, not a failure** —
      a downstream repo with no `Modified` rows and no `docs/ratify/` pays
      nothing (the arming idiom the component checks use).
