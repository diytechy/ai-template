# WI-285 — the integrator's composed-tree bar never runs (stack.ini schema mismatch)

**WI:** WI-285 · **Status:** queued · **Priority 1** (integration-time gate
verification is silently OFF) · **Delivers:** SR-006-adjacent (the integrator's
combined bar) — harness layer, no new spine SR

## Problem

`agent_dispatch._run_combined_bar` — the composed-tree bar the serialized
integrator runs before publishing a train (spec §9, "combined bar always runs")
— reads the test command from `docs/stack.ini` **`[stack] test`**. This repo's
`stack.ini` has **no `[stack]` section**: it declares the harness under
**`[product] test = {py} -m pytest -q -n auto`** (with `[tiers] smoke = -m
smoke`), the form `check.py` reads and `{py}`/`{src}`/`{tests}`-substitutes.

Result (verified live, run `20260723T0202`): every integration in this repo
journals `integration-bar: "skipped (no declared test command)"` and treats it as
a **pass** — so **WI-275, WI-279, and every historical integration landed on
`llm/integration` without the composed-tree bar ever running.** Integration-time
gate verification is effectively disabled for the meta-repo (the per-commit
pre-commit floor still runs on worker commits, but the *combined* bar on the
merged tree — the one that catches cross-WI composition breakage — does not).

Two coupled defects:
1. **Schema mismatch:** the integrator's contract (`[stack] test`, raw
   `shlex.split`, no substitution) does not match the kit's own stack.ini schema
   (`[product] test` with `{py}` placeholders that `check.py` fills). The kit
   doesn't run its own integrator bar — a dogfood hole.
2. **Fail-OPEN default:** an absent command returns `(True, "skipped")` — a
   missing bar silently passes. For a walk-away integrator that is the wrong
   default when a command *should* exist.

## Approach

- **Run the harness the repo actually declares.** Make `_run_combined_bar` invoke
  the same bar `check.py` does — either read `[product] test` with the `{py}`/
  `{src}`/`{tests}` substitution (and choose the tier: at minimum smoke, ideally
  the gate bar `check.py --gate <derived>` on the composed tree), or shell out to
  `check.py` directly so the integrator and the commit floor share one definition
  (the WI-260 "one rule, read once" precedent).
- **Tighten the skip:** distinguish "no harness declared at all" (a genuinely
  stackless fixture → legitimately skip) from "a harness is declared but under a
  key I didn't read" (→ do not silently pass). Absent `[product] test` AND absent
  `[stack] test` = skip; either present = run it.
- **Dogfood + template decision:** decide whether the fix ships in the kit
  template (so downstream integrators run their declared bar too) and whether the
  template's stack schema needs a documented single test-command home; record it.
- Tests: a stack.ini with `[product] test` must cause the integrator bar to RUN
  (not skip); the stackless-fixture skip stays; a composed tree that fails the
  bar parks the train (not integrates).

## Interfaces

No cross-module seam — intra-module (`agent_dispatch._run_combined_bar` +
`check.py`/`stack.ini` reading, and tests). Nearest: SR-006 (gate/tier harness),
whose command home this aligns the integrator with.
