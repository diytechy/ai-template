# WI-394 — a Verified spine row can cite evidence that has never existed

**WI:** WI-394 · **Status:** queued · **Delivers:** a resolver, or a ruling —
the point of the row is that the current state claims a verification it does
not perform

## Problem

`TC-091`'s `Evidence` cell names
`tests/test_agent_loop_dispatch.py::test_unclassified_wi_fails_closed_without_stopping_others`.
That module was deleted on **2026-07-29** by `31ad569d` (*"Phase 5 item 1:
delete the parallel dispatcher … and its test modules"*). The row's `Status` is
still `Verified`, and every gate is green.

Found while closing WI-383, whose commit `b8c7cc21` repointed that same row's
`Evidence` at a renamed test and left the dead sibling entry standing.

### Driven evidence — nothing anywhere convicts an invented citation

The WI-383 reviewer replaced the entry with
`tests/this_file_has_never_existed.py::test_entirely_invented` — a path with no
file and no history — and ran every gate that could plausibly see it:

| Gate | Result |
|---|---|
| `trace.py --strict --no-placeholders --require-verified --strict-schema` | **rc=0** — `orphans=0 integrity=0 status-findings=0 schema-findings=0`, TC-091 still `Verified` |
| `check_trajectory.py --root . --strict` | **rc=0** — `clean (389 work item(s), …, graph acyclic)` |
| `check_doc_refs.py --root . --strict` | **rc=0** — `no dangling path or sym: references` |
| `pytest tests/test_trace.py tests/test_registry_checks.py` | **70 passed** |

So an `Automated=Yes`, `Status=Verified` test case can cite a file that has
never existed, and the whole harness reports a clean spine.

### The class is wider than `Evidence` — measured, not assumed

Same method, on `LLR-059` (the LLR of the very function WI-383 rewrote):

| Mutation | `trace.py --strict …` | `check_trajectory --strict` |
|---|---|---|
| `Module` → `project-trajectory/scripts/this_module_has_never_existed.py` **and** `CodeSymbol` → `entirely_invented_symbol` | **rc=0** | **rc=0** | <!-- path-ok: this spec QUOTES an invented path as its driven evidence; it does not exist BY CONSTRUCTION -->
| `TestRefs` → `(see TC-999)`, a TC id that does not exist | **rc=0** | **rc=0** |

(Also **113 passed** across `test_trace.py`, `test_registry_checks.py`,
`test_check_flows.py`, `test_check_stubs.py`, `test_modules_registry.py` and
`test_components_registry.py` under the `Module`/`CodeSymbol` mutation.)

**The boundary is crisp, and it is not "traced cells are unchecked".** A
control run says so: mutating `TC-091`'s `Verifies` to `SR-999;LLR-999` fails
immediately — `trace.py` **rc=1**, `FINDING (orphan): TC TC-091 references
unknown SR-999`. `Component` is joined against the component registry the same
way.

> A pointer into **another registry** is joined and validated.
> A pointer **out of the registries, into the code or test tree**
> — `Evidence`, `Module`, `CodeSymbol`, `TestRefs` — is not checked at all.

`Module` is *read* (the IF `ThisProject` endpoint join, `PB` `Refs`
resolution), but only as a join key among LLR rows: a `Module` no file backs
simply joins to nothing, warn-only.

**And the one check that DOES validate paths cannot see the citation shape.**
Writing this spec proved it accidentally: `check_doc_refs --strict` flagged the
bare `project-trajectory/scripts/this_module_has_never_existed.py` in the table <!-- path-ok: the same invented path, quoted a second time as evidence -->
above as dangling (correctly — it is quoted evidence, now marked `path-ok`),
while the `tests/this_file_has_never_existed.py::test_entirely_invented`
citation two sections up passed **silently**. Its PATH tier requires the token
to *end* in a known source extension, and a `::node` suffix does not. So the
kit already owns a path-existence checker; it is blind to registry evidence
cells for one tokenising reason, and it never reads the CSVs anyway (its scan
surface is root `*.md` + `docs/**/*.md`).

### Why this matters more than a stale string

The four unchecked cells are exactly the ones that carry the spine's claim to
be *grounded in the code*. `Evidence` is what an auditor reads to answer "how
do you know this is Verified?"; `Module`/`CodeSymbol` are what a maintainer
follows to find the thing a requirement governs. Every other link in the chain
is mechanized. This is the failure class this repo keeps paying for: a
verification asserted in a cell, with no enforcer, discovered only when someone
happens to look.

It also rots **silently and by default**: nothing in a deletion asks what cited
the deleted file, and `docs/okf/` republishes the dead citation as generated
prose (`docs/okf/test-cases/TC-091.md`).

## Two honest options — DO NOT let a builder pick

The owner rules this; the row exists because the current state is the one thing
that is definitely wrong (it implies a check nobody performs).

### (a) Build the resolver — make the cell mean what it says

Validate that each `Evidence` / `Module` / `CodeSymbol` / `TestRefs` pointer
resolves. **The cheap half is most of the value**: the FILE path is checkable
with `Path.exists()` today, stdlib-only, no pytest needed — that alone catches
this finding and every deletion-driven one like it. Only the `::node` suffix
needs pytest to adjudicate, and `CodeSymbol` already has an oracle in the
generated arch-map inventory that `check_doc_refs`'s symbol tier reuses.

- **Surfaces that change:** `trace.py` (or `check_trajectory.py`) gains a
  finding class; `docs/enforcement-audit.md` moves these rules from
  Prose/Reviewer to Harness; the existing dead citations must be triaged before
  it can gate (start warn-first, the `check_doc_refs`/WI-062 precedent — it
  reported 561 findings before the untraced split and 22 after).
- **Cost to weigh:** a new check is what §0 of `docs/concurrency-v2.md` warns
  about. The counter-argument is that this one does not *detect a bad state
  after the fact* so much as make a written claim honest — but that is an
  argument, not a ruling.

### (b) Rule that the cell is prose — and stop implying otherwise

If an `Evidence` cell is a human-readable pointer rather than a machine-checked
one, say so where it is defined and stop reading it as proof.

- **Surfaces that change:** the registry template header comments in
  `project-trajectory/registries/`, `PROCESS.md`/`PROCESS_OPTIONS.md` wherever
  `Evidence` is described, `EXAMPLE.md`, and `docs/enforcement-audit.md` (which
  must then record the gap **as accepted**, with its reason).
- **Cost to weigh:** `Automated=Yes` + `Status=Verified` beside an unchecked
  evidence pointer is a strong implication to leave standing on purpose. If
  this is the ruling, the honesty has to be written down, not just intended.

A third shape exists and is worth naming so it is not mistaken for (a): check
only the FILE half and rule the `::node` half prose. It costs almost nothing
and closes the whole failure mode this row was found by.

## Scope notes

- **`Evidence` is a TRACED cell** under `docs/concurrency-v2.md` §A5.1
  (WI-380) — `spine_cell_class('docs/test/test-cases.csv','Evidence')` returns
  `"traced"`. So repointing evidence arms **no re-attest window**, which is why
  this row is `ordinary` work and not spine. The same holds for LLR `Module`,
  `CodeSymbol` and `TestRefs`. Option (b) is different: it edits process prose
  and template headers, which may carry their own cost — weigh that when the
  option is chosen, not before.
- **Not in scope:** repairing the individual dead citations. That is a
  consequence of whichever option is ruled, and doing it first would hide the
  evidence this row is built on.
- **Related, deliberately separate:** `TC-091`'s `Description`/`Method` still
  name the `checkpoint` classifier input WI-383 deleted, and `SR-094`'s
  `AcceptanceCriteria` does the same. Those are RATIFIED cells and belong to
  **WI-390**'s program close (`docs/concurrency-v2.md` §A9.1).
