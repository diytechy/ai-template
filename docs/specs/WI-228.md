# WI-228 — Live-orphan taxonomy + ratchet for check_docs (repo-review-2026-07-18 M-07)

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (review M-07) ·
**BuildTier:** medium · **SafetyClass:** ordinary (doc navigability tooling).

## Why

`check_docs` reports 48 live orphan warnings. Most are *retained evidence* —
reviews, closed-WI specs, plan-round artifacts — that should stay live but
unlinked-from-navigation is the wrong frame for them; meanwhile genuinely
undiscoverable new docs hide in the same noise. Deleting or globally
ignoring would destroy history; indexing everything would bloat navigation
(§0 table). The census only ever grows silently — the same failure mode
WI-225 ratchets for complexity.

## Scope

1. **Taxonomy.** Classify the 48 into declared classes (e.g.
   `review-evidence`, `closed-wi-spec`, `round-artifact`, `genuine-orphan`)
   recorded where check_docs can read them — a small declaration file or
   path-pattern rules in the script's config surface, whichever the script
   already supports more naturally. Genuine orphans get linked or indexed;
   evidence classes are *expected*-live-orphans and stop warning
   individually.
2. **Ratchet.** check_docs fails (or warns loudly under `--strict`) only on
   **newly introduced** live orphans outside the declared classes — baseline
   the residue, never fail history. Downstream behavior unchanged unless the
   adopter declares classes (default = today's behavior; the kit must not
   surprise existing repos).

**Non-goals:** no doc deletions; no mass index page; no change to broken-link
semantics.

## Done-when

The 48 classified with zero unexplained residue (or each residue linked);
check_docs regression tests cover class declaration, expected-orphan
suppression, and new-orphan failure; kit scripts stay stdlib-only; smoke bar
green per commit, full suite at close; `docs/status.md`/README untouched by
the noise reduction (no navigation bloat).
