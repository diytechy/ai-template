# WI-065 — Active-seam TC citation: reconcile the trace `Verifies` vocabulary

**Status: deferred** (filed 2026-07-11 at the close of WI-057; parked until a
seam actually needs `Active` status — every current `IF-###` row is `Stable`).

## The tension (surfaced by WI-057, recorded in `docs/log.md`)

`check_trajectory.py`'s seam-TC-citation scan reads the TC **`Verifies`**
column for `IF-###` tokens, but `trace.py`'s orphan check flags any `Verifies`
token that is not a known SR/LLR id. So marking a seam `Active` and citing it
the documented way (`Verifies=SR-044;IF-009`) passes `check_trajectory` yet
**fails `trace --strict`** — the two checks disagree about the `Verifies`
vocabulary, and the seam-TC rule cannot be satisfied honestly.

## Done-when

- [ ] One ruled home for seam citations: either `trace.py` accepts `IF-###`
      tokens in `Verifies` (and joins them against `interfaces.csv`), or the
      seam-TC scan moves to a cell `trace.py` does not vocabulary-check —
      one rule, stated once, both checks agreeing.
- [ ] A TC citing an `Active` seam passes `trace --strict` **and** satisfies
      the `check_trajectory` seam-TC-citation warn, covered by a test that
      exercises both checks on the same scaffold.
- [ ] The seam-TC rule's documentation (PROCESS_OPTIONS "Intra-repo interfaces
      & the architecture graph") names the ruled citation cell.
