# WI-221 — Raise the dual-plan round-budget default to the field-proven value

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (gilbert crosscheck)
· **BuildTier:** quick · **SafetyClass:** ordinary.

## Why

`plan_round.DEFAULT_ROUND_BUDGET = 10` prices the happy path (8 sessions) plus
the two legal repair bounces — **zero headroom** for a single runtime-
nonresponse fallback or repair overrun. gilbert's log (2026-07-18): "the
10-session default has zero headroom for a single fallback/repair overrun
(**bit twice today**) — FLAG FOR KIT RESYNC as a default worth revisiting
upstream." They run `AGENT_DUALPLAN_BUDGET=14` in both launchers since, with
rounds completing normally.

## Scope

Raise `DEFAULT_ROUND_BUDGET` 10 → **14** (the field-proven value) in
`plan_runner`'s source of record `plan_round.py`, update its pricing comment
(happy path 8 + two repairs + fallback-relaunch headroom), and sync the one
place the default is restated (`AGENT_DUALPLAN_BUDGET` docs in
PROCESS_OPTIONS' dual-plan section, if it names the number). The env knob
stays the per-repo override. The budget-exhaustion PAGE semantics are
unchanged — this moves only where the cap sits.

This is an owner-dial default: if the owner prefers a different number,
the ruling supersedes this spec's 14.

## Done-when

The constant + its comment updated; any restated number synced; the
`plan_round` budget tests updated to the new default (cap-enforcement
behavior tests unchanged); smoke bar green.
