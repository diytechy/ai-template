# WI-364 — An LLR citing a superseded SR is an integrity ERROR

**WI:** WI-364 · **Status:** queued

## Problem

`trace.py`'s optional SR `SupersededBy` extension (WI-229) validates only the
link graph — targets exist, no self-links, no cycles
(`sr_supersession_findings`). Nothing in the shipped kit stops a *live* LLR —
one with active tests behind it — from staying grounded on a superseded SR.
Today that guarantee exists in this repo only as pinning tests
(`test_meta_supersession_rows_preserve_the_ratified_evidence_map` /
`test_phase5_...` in `tests/test_trace.py`), so a downstream adopter using the
column gets no guard at all. Owner ruling 2026-07-29: this is an **error**, not
a warn — the registry is the live surface only; the supersession history lives
in git, and an LLR must not exist against, or reference, a dead SR.

## Approach

- Extend the supersession validation in
  `project-trajectory/scripts/trace.py` (`sr_supersession_findings`, ~L522; the
  caller at ~L2092 already assembles the integrity floor and has the LLRs in
  scope) so any LLR whose `SR-Refs` names an SR with a populated
  `SupersededBy` cell produces an integrity finding, e.g.
  `LLR LLR-014 SR-Refs cites superseded SR-061 (SupersededBy SR-132) —
  re-ground on the successor or delete the LLR`. Integrity tier = fails
  `--strict` **and** `--strict-integrity`, wrong at any gate — the ruled
  severity.
- **TC citations of superseded SRs stay legal.** The TC-099/TC-133
  evidence-map pattern *requires* them: a non-draft superseded SR still owes a
  TC (`trace.py` ~L1855), and the citing TC is the retained evidence record.
  The error is scoped to LLR `SR-Refs` only.
- Registries without the optional column are untouched (absent/empty cells
  produce no edges — same compatibility contract as the existing validation).
- Update `sr_supersession_findings`'s docstring — the extension's one contract
  home — to state the new rule; add a Harness-tier row (or lift an existing
  one) in `docs/enforcement-audit.md` if the rule is recorded there.

## Interfaces

No cross-module seam — acts only within `trace.py` and its tests.

## Done-when

- [ ] `trace.py` reds (integrity tier) on an LLR whose `SR-Refs` cites an SR
      with a populated `SupersededBy`; message names the LLR, the dead SR, and
      the successor(s).
- [ ] Pinned both directions in `tests/test_trace.py`: a unit case on the new
      finding, a scaffold `--strict-integrity` exit-1 case (mirror the
      `SR-999` unknown-target case at ~L1244), and a clean registry stays
      clean.
- [ ] This repo's own registries stay green under the new check (the pinning
      tests already assert no LLR cites the superseded sets).
- [ ] Commit bar green; spec archived per `docs/specs/README.md`.

## Notes / open questions

The owner's broader observation — history belongs in git, not in two places —
could extend further: retiring superseded SR *rows* themselves once their
supersession record is attested (the TC-099 pattern and its pinning tests
would retire with them, and the ids would need a reuse guard). That is a
separate owner ruling with spine blast radius, deliberately **not** this WI;
this WI only hardens the live-surface rule the kit can enforce today. Note the
open Phase 5 window is unaffected either way: this repo is already clean under
the new check.
