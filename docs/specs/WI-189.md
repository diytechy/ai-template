# WI-189 — Dashboard render-critique loop (meta-only headless screenshots)

**Status: queued (filed 2026-07-16, owner-directed).** Agent critiques of
[`PROJECT_STATE.html`](../../PROJECT_STATE.html) have so far judged ~790 KB of
generated markup, not what a human sees. Agents *can* read images (the Read
tool presents PNGs visually); the missing link is render-to-pixels. This dev
machine has no browser binary (no Chrome/Chromium/Firefox in `/Applications`,
no Playwright cache), so nothing today can turn the dashboard into something an
agent can actually look at.

Owner ruling at filing: **dev-only tooling** — installed by/for this repo's own
dev setup, never the downstream-shipped `dev-setup.template.*` (a browser
download would violate the kit's install-nothing posture; same meta-only
scoping as WI-175 Rec 3).

## What

A repeatable render-critique loop for the dashboard:

1. **Pinned browser tooling, meta-only.** `npx playwright` with a pinned
   package + browser (chromium) version so screenshot output stays comparable
   across sessions. Installation is a documented step (or a warn-only probe) in
   the *meta* dev setup; the kit's stdlib-only rule governs shipped scripts and
   is untouched.
2. **A screenshot matrix runner** (a `this-repo` skill and/or small meta
   script): regenerate the trajectory dashboard, then capture it at a small
   declared matrix — e.g. narrow/laptop/wide widths × light/dark
   (`--color-scheme`), above-the-fold + full-page — into a gitignored output
   dir, printing the paths so an agent session Reads and critiques the PNGs.
3. **Artifact-recipe dual use.** The runner's command sequence is written to
   serve as the **artifact recipe** for a future `Verification=Critique` TC on
   dashboard quality (the critique-loop contract in
   [PROCESS_OPTIONS.md](../../project-trajectory/PROCESS_OPTIONS.md) requires a
   perceptual TC to name its render recipe) — build it once, serve both uses.

## Done-when

- [ ] Pinned Playwright + chromium versions recorded; install path documented
      for the meta repo only (no downstream template change; no new runtime
      requirement for any kit script).
- [ ] One command/skill regenerates the dashboard and emits the declared
      screenshot matrix to a gitignored location, deterministic in naming.
- [ ] The matrix definition (widths, themes, pages/tabs captured) is declared
      in the skill/script, not improvised per session.
- [ ] A session has exercised the loop end-to-end (screenshots produced and
      visually read back) and the result is recorded in the log.

## Non-goals

- No kit-shipped screenshot script and no downstream `dev-setup.template.*`
  change (stdlib-only, install-nothing posture unchanged).
- No CI screenshot job and no pixel-diff visual-regression baseline yet — a
  possible follow-up once the matrix stabilizes.
- No dashboard redesign in this WI; it only builds the eyes. Findings it
  enables are filed as their own WIs.
