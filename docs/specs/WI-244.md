# WI-244 — Distill taste-skill's legibility pre-flight into the dashboard-usability rubric

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-20 (from the 2026-07-20
external-skills review) · **BuildTier:** medium · **SafetyClass:** ordinary
(rubric prose + attribution; no control flow).

## Why

The [dashboard-usability rubric](../rubrics/dashboard-usability.md) (SR-054) has
good *task-level* anchors — T1 findability, T2 default-density legibility, T3
detail-in-context, T4 label legibility — but its legibility floor (T4) is a
single prose line. The 2026-07-20 external-skills evaluation found
**[Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)** (MIT) carries
a *mandatory, mechanical, legibility-first pre-flight checklist* — button/form
contrast (WCAG AA 4.5:1 body / 3:1 large), dark-mode **theme-lock** (one theme,
no mid-view inversion), **viewport-fit** / no-clip, readable-string audit — which
is exactly the "visual reviewer hat" bar the owner reports missing. Distilling
its **discipline** (not its Tailwind/aesthetic dogma) into concrete, checkable
anchors raises the ceiling the perceptual critic (WI-243) judges against.

This is the **enrichment** half; WI-243 is the **firing** half. A richer rubric
judged by a critique that never runs still ships hard-to-read tabs, so WI-243 is
the higher-leverage of the pair — but both are wanted.

## Scope

1. **Add stack-neutral mechanical anchors** to
   `docs/rubrics/dashboard-usability.md`, distilled from taste-skill, each with a
   checkable *Bad:* example in the existing house style — candidates:
   - a **contrast floor** on interactive/label elements in **both** themes;
   - a **theme-lock** anchor (no mid-view light/dark inversion);
   - a **viewport-fit / no-clip** anchor at the declared widths incl. 390px.
   Strip Tailwind-specifics (`bg-white`+`text-white`, `pt-24`) and aesthetic
   opinions (em-dash bans, no-3-equal-columns) — keep the stack-agnostic
   principle only.
2. **No duplication with SR-052.** Where WCAG contrast already lives in the
   accessibility rubric, the usability rubric **links** rather than restates
   (single-source-of-truth).
3. **Attribution.** Cite `Leonxlnx/taste-skill` (MIT) + a **pinned commit** in
   the rubric — the distillation is derived-from and MIT requires attribution;
   pin because taste-skill v2 is "experimental" / churning.

## Non-goals

- **No vendoring** of taste-skill or its tools — read-and-mine only (the kit's
  no-install stance; taste-skill ships `npx`/live-`--llm` runners).
- **No new SR** — this enriches SR-054's existing rubric.
- **No dashboard code change**; **no aesthetic dogma** adopted.

## Done-when

`dashboard-usability.md` carries the distilled stack-neutral anchors with
checkable *Bad:* examples and `taste-skill` MIT attribution (pinned commit); no
WCAG contrast duplication with the accessibility rubric (link, don't restate);
the rubric stays one-page house-style and link-reachable (doc-navigability
green); suite green.
