# WI-110 — Effort-level selection for agent sessions (deferred)

**Status: deferred** (filed 2026-07-12 at the WI-109 sitting, owner-directed:
"perhaps computing this could be a part of a future update and kept as a
deferred work item — add scripts or methods to select the proper effort level
when applying a claude-level agent").

## What stands today (the static pin, WI-109)

The ANTHROPIC rows in `docs/agents.csv` pin `CLAUDE_CODE_EFFORT_LEVEL=high`
via their `Env` cells — the owner's "high or very high as a good balance",
implemented as the documented-safe half (`high` is also the Opus 4.8 default,
so the pin declares it against default drift). Verified facts at filing time
(claude CLI): `--effort low|medium|high|max` exists, session-scoped, works
with `-p`; the env var additionally accepts `xhigh` on Opus 4.8/4.7. The env
route was chosen over the flag because an unread env var is a no-op on older
CLIs while an unknown flag fails the session.

## The deferred work

1. **Verify `xhigh` live** (the "very high" half): one gate-bearing session at
   `xhigh` vs `high` — wall-time, cost, gate outcome — before any dial-up; a
   failed experiment costs one session, a blind pin costs every session.
2. **Per-phase effort map** — an `AGENT_EFFORT_MAP`/`--effort-map` sibling of
   `AGENT_TIER_MAP` (the PROCESS_OPTIONS "Per-phase effort" paragraph, WI-049,
   already frames effort as a sibling routing knob and records the two
   evidenced cautions: *low effort fabricates → route hard work up*; only
   thin, replaceable effort wiring bites). Natural shape: effort as a
   per-phase declared value merged into the row Env at launch, so it composes
   with the pair-row model without a schema change.
3. **Computed selection (speculative — needs evidence first):** derive effort
   from session signals (gate-bearing vs docs-only WI, spec size, retry/escalation
   state — e.g. a lose-shift retry runs `xhigh`). Do not build until the
   iteration logs show phase-effort variance that a static map can't serve;
   that evidence threshold is the un-defer trigger.

## Un-defer when

- The xhigh experiment is worth a sitting (owner call), or
- iteration logs show sessions failing in ways plausibly effort-bound
  (fabrication at low reasoning depth, stalls on hard refactors), or
- a second provider exposes a comparable knob worth unifying behind one map.
