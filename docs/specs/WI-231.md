# WI-231 — Integrator regenerates generated artifacts instead of merging them

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (parallel-run field
finding 2) · **BuildTier:** strong · **SafetyClass:** high-risk (integration
composition — the one logical writer of SR-063).

## Why

Composition 3-way merges every path as opaque text: ANY textual conflict
parks the train `needs-re-review`
([agent_dispatch.py:930-942](../../project-trajectory/scripts/agent_dispatch.py#L930-L942)).
But `PROJECT_STATE.html` is *generated* — and nearly every WI regenerates it
(closing your own registry row forces it) — so two trains reserved off the
same base conflict on it almost deterministically. Field evidence (runs
`20260718T153937`/`190911`): both parked trains conflicted on the dashboard;
WI-219's park was that file *alone*, and each relaunch re-ran the same merge
and re-parked. Hand-merging a generated artifact contradicts the kit's own
generated-not-hand-maintained principle, and WI-220 already gave the
disposition paths sibling-generator regeneration — conflict resolution just
never uses it. The registry conflict has the same character at row grain:
the 2026-07-18 WI-228 park was two sides editing *different* WI rows that
line-level merge misread as a collision.

## Scope

**Slice A — generated set.** On a composition conflict, when every conflicted
path belongs to the known generated set (the artifacts the harness `--check`s:
`PROJECT_STATE.html`, the `docs/okf` bundle, the status snapshot block, the
arch map, the skills index), resolve by taking either side, re-running the
sibling generators against the merged sources (the WI-220 machinery), and
continuing composition; park only when a non-generated path conflicts.

**Slice B — registry union merge.** A WI-ID-keyed row-level merge for
`work-items.csv`: a row changed on one side only takes that side; a row
changed on both sides is a genuine conflict and parks as today. This
auto-resolves the disjoint-row case that line-level merging cannot.

**Non-goals:** no `.gitattributes` merge drivers (the kit stays stdlib-only
and cannot demand git config of downstream); no auto-resolution of any
source-file conflict; no change to the park/re-review state machine itself
(that is WI-232).

## Done-when

Regressions prove: (1) two trains off one base that both regenerate the
dashboard — the second integrates without parking and the regenerated
artifacts match the merged sources (`--check` green); (2) disjoint registry
row edits union cleanly; (3) a same-row both-sides edit still parks
`needs-re-review`; (4) a mixed conflict (generated + source) parks. The
integration suite stays green.
