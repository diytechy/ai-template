# WI-1006 — A ruled open item has action planned, done or handed on (spec of record)

**WI:** WI-1006 · **Status:** queued · **Delivers:** none named yet (the critique decides)

Filed on the owner's request, 2026-11-15. The row keeps its Context and
Done-when, which stay the one home of what closes it.

## Why

Ruling an open item takes it off `open-items.html`. What the ruling asked for
then lives only in the work items that cite it, and nothing checks that any
do. An item can be ruled and its action never planned, and every bar stays
green. The ruling sync (WI-790) holds only the ruling's own commit: it makes
that commit rewrite the Done-when of each open row whose `needs` cited the
item. A ruling with no citing row, or one whose follow-on work was filed
later as another open item, is never judged.

## Why text and not `needs`

In practice the ruling's commit drops the item from the citing row's `needs`
(OI-129's ruling, `0032ffdd8`: "both rows drop their needs on the item"). The
link that survives is the item's id in the row's text, because the
registry header asks the new Done-when to cite the item. So the check matches
`OI-<n>` (leading zeros ignored) in work-item spec text, not edges.

## The rule

A `ruled` item is **covered** when any of these holds:

1. A work item under an open status directory (draft, queued, active,
   deferred) or under `complete/` names it. Cancelled, partial and
   restructured rows do not count.
2. Another open item names it in any cell but the historical `wi_refs`, and
   that item is `pending`, or is `ruled` and itself covered. Follow the chain,
   and treat a cycle with no covered member as uncovered.
3. Its `follow_up` cell is set. The template documents it as
   `follow_up = "none — <why>"`, the same "none — why" form the log fragments'
   `Deferred open items:` line already uses.

Anything else is a finding, warn-only, naming the item and its title.

## Measured with a prototype

At `7fa851f33`, over this repo's 115 `ruled` items:

| Reading | Items |
|---|---:|
| a complete row names it | 91 |
| an open row names it | 15 |
| handed on through a later open item | 5 |
| uncovered | 4 |

The four uncovered items are OI-35 (carried out in its own ruling commit),
OI-79 (its only link is the historical `wi_refs` cell, naming WI-569), and
OI-89 and OI-90 (each confirmed things as they were). None needs work, which
is the case `follow_up` exists for.

## Bounds

- A text match counts any mention as cover, so 91 is an upper bound on rows
  that actually carried out a ruling. Whether a row does what the ruling said
  stays a reviewer's question.
- Rule 2 cannot tell a real follow-up from a later item that only mentions an
  earlier one. No `ruling_ref` names another item today (0 of 94), so the
  template's ask that a follow-up name its predecessor is what keeps rule 2
  honest.
- Reading rules 1 and 2 together with the open rows also gives an "answered,
  not yet applied" list. Rendering it is out of this row's scope.
