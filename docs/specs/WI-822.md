# WI-822 — Coordinator context guard (spec of record)

The design the owner agreed on 2026-10-04 for
[WI-822](../work/queued/WI-822-coordinator-context-guard.md). Its Done-when lives in
the work-item spec; this file holds what the row must achieve and why.

What Claude Code provides (its documentation, read 2026-10-04 through the
claude-code-guide agent):

- hook events (`PostToolUse`, `PreToolUse`, `Stop`, `SessionEnd`, `PreCompact`, ...),
  each given the session's `transcript_path` and `session_id`;
- a hook can add text to the model's context (`additionalContext`), and a
  `PreToolUse` hook can refuse a tool call;
- the transcript records each reply's `usage` (`input_tokens`,
  `cache_read_input_tokens`, `cache_creation_input_tokens`).

It does not provide a context percentage in hook input: the window size must be
declared or mapped from the model id. The auto-compaction threshold is undocumented,
so the guard fires well before it.

The design, as agreed with the owner:

1. **Monitor.** After each tool call, a stdlib-Python hook reads the newest usage
   from the transcript and computes occupancy against the declared window (this
   coordinator runs Opus 5.5 with a 1M window). Crossing the threshold (declared,
   50) injects an instruction once, and a short reminder at a bounded interval:
   start no new lanes or claims; bring in-flight rows to a safe point (land, close,
   or leave committed and recorded); write the handoff; request the relaunch.
2. **Enforce "no new lanes" at the tool call.** Past the threshold, a `PreToolUse`
   hook refuses a new claim (`integrate.py claim`) and a new lane worktree
   (`git worktree add`), naming the reason. In-flight work can still finish,
   land and close.
3. **Handoff.** The session-close set already in use: `docs/status.md`
   (forward-only), a handoff document carrying the session prompt, and a log
   fragment, plus a relaunch request naming the handoff.
4. **Relaunch at session end, never on a timer.** A `SessionEnd` hook, finding a
   relaunch request, launches a new session (a `.cmd` launcher on Windows, its
   POSIX sibling elsewhere) with the handoff's prompt. Two coordinators never
   overlap: the new one starts only after the old one has ended.
5. **Backstop.** If compaction fires anyway, `PreCompact` records it (the marker
   says the 50% path was missed), and the next handoff reports it. Blocking
   compaction is not relied on: whether a full session then stalls is
   undocumented.

**Scope: this repository's tooling.** The hooks register in a tracked
`.claude/settings.json`, the script lives with the repo's tools, and its state
(threshold flag, relaunch request) is untracked under `out/`. Whether it ships to
adopters is decided at the end, not assumed. It covers a Claude Code coordinator
only; a Codex-run coordinator would need its own mechanism (recorded, not built).
