## What Claude Code provides

Per its documentation (read 2026-10-04 through the claude-code-guide agent, and
checked by the review):

- **Hook events:** `PostToolUse`, `PostToolUseFailure`, `PreToolUse`,
  `UserPromptSubmit`, `Stop`, `SessionStart`, `SessionEnd`, `PreCompact`, and
  others. Each input carries `transcript_path`, `session_id` and `cwd`.
  `SessionEnd` also carries its reason: it fires on `/clear` and on an
  interactive `/resume` as well as on exit.
- **What a hook can do:** add text to the model's context (`additionalContext`),
  or refuse a tool call (`PreToolUse`).
- **Usage:** transcripts record each assistant reply's `usage`.
- **What is missing:** no context percentage is exposed, and the auto-compaction
  threshold is undocumented.
- **Project hooks also fire for subagents' tool calls**, and a subagent's
  transcript is its own file.

Treat each of these as a version-dependent claim. Fixtures carry the Claude Code
version they were taken from.

## The design

1. **Coordinator identity: one lease.** The coordinator session holds a
   coordinator lease: one record under the primary checkout's untracked
   `out/coordinator/`, found through the git common directory as
   `session_keep.store_dir` finds its path.
   - **Taken:** at `SessionStart` by a session started for coordination, either
     from the relaunch launcher or by an explicit take.
   - **Contents:** the session id, its transcript path and the repo root.
   - **Only the lease's session is measured or drained.** A hook call from a
     subagent, or from any other session in the repo, finds a different session
     or transcript and does nothing.
   - **Elapsed time never transfers the lease** (round 2's BLOCKER): a
     coordinator waiting on the owner, or on a long tool call, is silent but
     alive. The lease passes in exactly two ways:
     - at the holder's exit, to its relaunched successor (part 6);
     - by the owner's explicit release, recorded with a reason, e.g. after a
       crash that never reached `SessionEnd`.

     A session that finds the lease held by another session is not the
     coordinator: its claims refuse, naming the holder and the release command.
2. **Monitor.** Before each of the coordinator's tool calls (`PreToolUse`), and on
   its `PostToolUse`, `PostToolUseFailure`, `UserPromptSubmit` and `Stop` events,
   occupancy is read from the coordinator's own transcript, against the declared
   window. The `PreToolUse` reading is the one that matters for admission: it
   runs before the call executes, so a reply that crosses the threshold latches
   drain mode before its own first tool call (round 2's MAJOR).
   - **Which usage counts:** the newest assistant `usage` after the transcript's
     last compaction boundary, on the live branch. Occupancy is `input_tokens`,
     plus `cache_read_input_tokens`, plus `cache_creation_input_tokens`.
   - **Unknown is not 0%:** no valid usage since the boundary reads as unknown,
     and is reported as such.
3. **Drain mode is latched.** The first reading at or above the threshold
   (declared, 50) latches drain mode in the lease record.
   - **It stays latched** until ownership transfers: a relaunched session takes
     the lease, or the owner clears it explicitly, which is recorded. A later
     lower reading never unlatches it, whether after a compaction or a
     `/resume`.
   - **The guard injects its instruction once when it latches**, then a short
     reminder at a bounded interval: start no new claims; bring in-flight rows
     to a safe point (land, close, or leave committed and recorded); write the
     handoff; request the relaunch.
4. **Enforced at the admission boundary, not at command spellings.**
   `integrate.claim` (`integrate.py:650`) refuses while the coordinator lease is
   draining, naming the reason. It also reads the lease's transcript itself
   through the same occupancy reader, and latches if it finds the threshold
   crossed, so admission never depends on a hook having run first. A claim made
   with no lease held refuses, naming how to take one.
   - **One refusal covers every route to a claim:** a wrapper script, a helper
     that imports `integrate`, or the CLI.
   - **No `git worktree add` refusal:** a worktree for a lane needs a claim, so
     refusing the claim suffices. Verification worktrees (the end-of-session
     full suite) and close-out work pass: landing, archive, sweep, the
     scoped-unpause restore, worktree removal.
5. **Handoff and relaunch request.** The draining session writes the
   session-close set (`docs/status.md`, a handoff with its session prompt, a log
   fragment), then a relaunch request.
   - **Contents:** the requesting session id, the repo root (the launch's
     working directory), the handoff path, and its creation time.
   - **Written atomically:** temp file, then `os.replace`.
6. **Relaunch at true session end, with ownership transfer.** `SessionEnd`
   launches the next session only when all of these hold:
   - its reason is an exit reason, never `clear` or `resume`;
   - the ending session holds the lease;
   - a request exists from that same session, for this repo, naming an
     existing handoff;
   - the request is acquired atomically: renamed to a consumed name, so a
     second handler finds nothing.

   The launcher runs in the declared repo root (`.cmd` on Windows, a POSIX
   sibling elsewhere), with the handoff's prompt. The new session takes the
   lease at its `SessionStart`. Failure and foreign requests:
   - **A failed launch** restores the request and reports.
   - **A request from another session** is refused and reported, never
     launched.

   Two coordinators never overlap: only the lease holder's exit launches, and
   the lease passes to exactly one successor.
7. **Compaction telemetry.** `PreCompact` records the trigger (manual or auto),
   the last occupancy and the guard's state: latched or not, and the handoff
   requested or not. The next handoff classifies it: a missed threshold, a
   manual compaction, or compaction during a drain. It is telemetry, never a
   recovery path.

## Dials and scope

- **Dials:** the threshold and the window are declared in the one dial home
  (`docs/process.toml`). No expiry exists: ownership never transfers by time.
  - **Shipped template, too:** `tests/test_dogfood_sync.py` holds the template
    and this repo to the same keys, so the template gains them. Its threshold is
    0, meaning the guard is off. The key is an adopter-facing surface, with a
    RESYNC entry.
  - **The guard's script and hook registration stay this repo's tooling.**
    Whether they ship is decided at the end of the row and recorded.
- **Hook registration:** a tracked `.claude/settings.json`.
- **Coverage:** a Claude Code coordinator only. A Codex-run coordinator would
  need its own mechanism. That is recorded as a gap, not built.
