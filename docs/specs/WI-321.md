# WI-321 — A requirement states the system, not its own history

**Status: queued** (owner-raised 2026-07-26, reviewing the `Modified` batch).

## The observation

SR-049's requirement text had grown a parenthetical citation of `process.md`
section 7 and a `(WI-316)` tag. The owner's question is the right one: **a system
requirement should be stand-alone.** A reader — human, agent, or a downstream
adopter who has none of this repo's history — must be able to read one row and
know what the system shall do, without opening a process doc or looking up a
work item.

Provenance already has homes, and they are better ones:

| The fact | Its home |
|---|---|
| which WI delivered or amended a row | [`work-items.csv`](../requirements/work-items.csv) + [`log.md`](../log.md) |
| why it was decided that way | `log.md`'s Decisions |
| what verifies a clause | the LLR/TC chain — derived, never restated |
| which process rule governs the SHAPE of the row | `PROCESS.md`, which the row obeys rather than cites |

## Measured before filing (2026-07-26, 110 SR rows)

| Pattern in `Requirement` / `AcceptanceCriteria` | SRs | Verdict |
|---|---|---|
| a `WI-###` id | **4** — SR-026, SR-049, SR-054, SR-060 | **rot.** All four are history: *"(WI-210, one path — the serial resume loop is retired)"*, *"Modified (WI-316)"*, *"(WI-315, owner ruling)"* |
| a process-doc citation | **1** — SR-049 | **rot.** The row obeys the process; it does not cite it |
| a script filename (`trace.py`, …) | 65 | **legitimate — do not flag.** This kit's *product* IS its scripts, so the name is the system under specification |
| an artifact path (`docs/gate`, `PROJECT_STATE.html`) | 6 | **legitimate.** The requirement governs that artifact |
| a rubric / `CRITIQUE` reference | 5 | **legitimate.** For a `Verification=Critique` row the rubric is the *acceptance instrument* — naming it is what makes the row verifiable |
| a sibling `SR-###`/`LLR-###`/`TC-###` id | 14 | **mixed.** An SR bounding itself against a sibling SR is fine; an SR enumerating its own child LLR/TC rows is decomposition leakage — the chain already records it |

So the corpus is healthy: **five rows carry the defect, not fifty.** That is what
makes a mechanical rule affordable now rather than a mass edit.

SR-049 and SR-054 were cleaned when this was raised, because both already sat in
the open `Modified` window and fixing them cost no new attestation debt.

## Scope

1. **The rule, in `trace.py`'s schema tier** (warn-first, then gating at
   `--strict-schema`): no `WI-###` token, and no `process.md` / `process-options.md`
   citation, in an SR's `Requirement` or `AcceptanceCriteria`. Nothing else —
   deliberately narrow, because the measurement above shows every wider pattern
   has a large legitimate majority, and a rule that cries wolf on 65 rows is a
   rule that gets ignored (the `check_doc_refs` lesson, WI-062/WI-308).
2. **Clean the two remaining rows: SR-026 and SR-060.** Both are `Verified`, so
   each amendment flips it to `Modified` and joins the next sitting — which is
   why this is the owner's to schedule, not a drive-by edit.
3. **Collapse the live-anchor triplication.** The set of live SR-054 critique
   anchors is currently stated in three places: the rubric header, `TC-055`'s
   `Expected`, and (until this WI's prompt) `SR-054`'s `AcceptanceCriteria`. The
   rubric is the instrument the critic actually reads, so it is the single home;
   `TC-055` should name the rubric rather than copy its list. `TC-055` is
   `Verified`, so this too flips a row.

## Deliberately NOT in scope

- Flagging script names or artifact paths. See the table.
- A prose-quality heuristic (sentence length, readability score). The defect
  here is **categorical** — provenance in a normative row — and a categorical
  rule can be exact. A readability score cannot, and would be the kind of
  proxy this repo has repeatedly refused.
