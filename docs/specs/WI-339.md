# WI-339 — `check_vendored` hashes raw bytes, so a CRLF checkout reports false drift

**Status: queued** (`P2`, found 2026-07-27 auditing the other kit checkers for
[WI-337](../archive/specs/WI-337.2026-07-27.md)'s defect class).

## The defect

`check_vendored.py` compares the vendored copy against the fetched upstream by
hashing both:

```python
if (
    hashlib.sha256(local.read_bytes()).digest()
    != hashlib.sha256(remote).digest()
):
```

`local.read_bytes()` is the **working tree's** bytes. `.gitattributes` declares
`* text=auto eol=lf`, so the vendored docs are stored LF — but a working tree
can hold CRLF anyway (edit residue on Windows; WI-337 found 67 such files here).
Every vendored file then mismatches at once, and the message blames upstream:
*"differs from pinned upstream — re-vendor or re-pin"*. Re-vendoring "fixes" it
until the next Windows edit, and re-pinning records a hash of the checkout.

This is the same defect class WI-337 fixed in `check_dupes`: **a checksum of the
checkout used as a checksum of the content.**

## Why it is P2 and not P1

Unlike the census, nothing is currently red because of it:

- the step is **not wired** into this repo's `docs/stack.ini`, so no gate runs it;
- it is **network-gated** — it skips with a message when upstream is unreachable;
- it **WARNs** unless `--strict`.

So it misleads a human running it by hand rather than breaking CI. WI-337's
worktree restoration also removes the live trigger here for now, which is
exactly why this wants a guard: the trigger will come back.

## The fix wants care WI-337's did not

**A vendored file may legitimately be binary.** Stripping CR bytes blindly would
corrupt the comparison for anything that is not text — the opposite failure.
Normalize only what is declared text (or detect it), and say in the code which
rule was applied.

Both sides need the same treatment: the local bytes *and* the fetched remote,
which may itself be served with either ending.

## Done when

- [ ] The same content compares equal whether the local copy is LF or CRLF.
- [ ] Genuinely different content still compares **unequal** — the guard asserts
      both directions, or it is only half a guard.
- [ ] A binary vendored file is not silently mangled by the normalization (pin
      the chosen rule with a test, whichever rule it is).
- [ ] Mutation-proven: remove the normalization and the cross-line-ending guard
      goes red.

## Interfaces (§8)

Single-module: `check_vendored.py` and the upstream manifest it reads (a
`--manifest` path supplied by the adopting repo — this meta-repo vendors no
guardrails core of its own, which is part of why the defect went unnoticed).
The declared seams `IF-016` / `IF-036` are unchanged — this is an internal
comparison rule, not a change to what the module promises.
