# WI-227 — Run-menu trailing arguments: decide the contract, then quote it (repo-review-2026-07-18 M-06)

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (review M-06) ·
**BuildTier:** medium · **SafetyClass:** ordinary (launcher convenience
layer; not the dispatcher).

## Why

`run_menu.py:116` concatenates trailing user arguments into a shell command
string unquoted. An argument containing spaces or shell metacharacters
splits or executes differently than the user intended, and Windows
(`cmd.exe`) vs POSIX quoting rules differ, so a naive quoting patch is
unsafe without deciding what the contract *is*. The review deliberately left
this unfixed pending that decision (§0 table).

## Scope

1. **Decide the contract** (recorded in this spec as a ruling section,
   WI-223-style): either trailing arguments are a **trusted shell fragment**
   (documented as such — the user owns quoting; the kit passes it through
   verbatim on both platforms) or they are **data arguments** (the kit
   appends them as argv items with per-platform quoting, never re-parsed by
   a shell). The recommendation is data-arguments: menu entries are the
   trusted recipes; user-supplied trailing args are values.
2. **Implement** the ruled semantics explicitly — argv-append or documented
   passthrough — with tests covering spaces, quotes, and `&`/`|`
   metacharacters on both Windows and POSIX (skip-guarded like the suite's
   existing shell-dependent tests).

**Non-goals:** no menu-format redesign; no change to how the menu's own
recipe lines execute.

## Done-when

The ruling recorded; behavior implemented per ruling with cross-platform
regression tests proven failing pre-fix under the ruled semantics; smoke bar
green per commit, full suite at close.
