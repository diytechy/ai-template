# WI-283 — blocked-disposition must regenerate every floor-checked artifact

**WI:** WI-283 · **Status:** queued · **Priority 1** (wedges two lanes of the
live 2026-07-23 run) · **Delivers:** the dispatcher's §9 blocked-disposition
transaction (no spine SR change; the defect is in `agent_dispatch.py`)

## Problem

Live failure, 2026-07-23, train `3-g3-WI-273-b45e`: the worker blocked
correctly (SR-052 needs a family-heterogeneous CRITIQUE — the WI-243
fail-closed perceptual gate; §10 puts CRITIQUE in the serial coordinator pass,
so the worker rightly refused to self-author it). But the coordinator's
`blocked_disposition()` transaction then **failed its own commit,
deterministically, on every retry**:

- Flipping the WI row to `Status=blocked` changes the inputs of the GENERATED
  "pending owner-actions" projection in `docs/open-items.md` (a blocked row is
  an owner-action).
- The transaction regenerates the status snapshot (`generate_status`) and the
  `_regenerate_disposition_artifacts` set — but **not that projection** — so
  the pre-commit floor's `status-map` step (`gen_trajectory.py --status
  --check`) refuses the commit: *"pending owner-actions projection STALE"*.
- The train parks `state=error` (journal 07:00:35 + prior), the disposition
  never lands, and the coordinator **never reaches its SR-084 critique
  obligation** — the render-critique protocol stalls behind a bookkeeping
  failure. WI-272 will hit the identical wall when its block records.

## Approach

- In the staging worktree, before the disposition commit, regenerate the SAME
  artifact set the floor checks — reuse the existing `_regenerate_pending`
  path (the needs-human branch already calls it) or, better, derive the regen
  list from one shared home so the transaction and the floor cannot disagree
  again (the WI-260 "gate and scheduler read one rule" precedent, applied to
  disposition vs floor).
- Regression test: a fixture train whose blocked WI feeds the pending
  projection; `blocked_disposition()` must commit clean and the train must
  reach `blocked` (not `error`).
- After this lands, the parked `error` trains' dispositions retry and clear on
  the dispatcher's rescan; verify WI-273 (and WI-272 if blocked by then)
  transition to `blocked` with their BlockRefs, unblocking the critique
  dispatch.
