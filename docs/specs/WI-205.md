# WI-205 — Backlog-staleness warn: open WIs re-flagged when their cited spine rows change

**Status: queued (filed 2026-07-17, owner-directed — the 2026-07-17 sitting's
finding 2).**

## Problem

Ratifying amended SN/SR/LLR/TC content never touches the open WI rows that
cite it. The continuous checks are **referential only**: `SR-Refs` must
resolve (dangling → warn), `SpecRef` must resolve (R-E — ERROR at G2+
`--strict`), R-A, acyclicity — so a *deleted or renamed* spine row surfaces
immediately, but an open WI whose cited requirement **text** was amended after
the WI was filed is trusted as-is. Nothing — mechanical or prompted — drives a
re-evaluation of the incomplete backlog against the new requirement state; in
enforcement-audit terms, backlog semantic currency is enforced by **nothing**.
The ratification reviewer's mandate is batch-scoped (the ratified rows), not
backlog-scoped.

## Scope

A **warn-tier** finding in `check_trajectory.py` (the WI-129/132 house stance:
warn, don't gate, don't mutate) — the `check_docs --stale` idiom applied to
the WI↔spine join:

1. For each **open** (queued/active/blocked) WI, derive when its registry row
   last changed and when each cited source last changed, via `git blame` on
   the row lines (the per-line last-modifying commit) / `git log -1` for the
   `SpecRef` target file. Cited sources: each `SR-Refs` row in
   `system-requirements.csv`, and the `SpecRef` path.
2. If a cited source changed **after** the WI row's last touch, warn:
   `WI-###: cites SR-### amended after the WI was last touched — re-validate
   the WI against the amended requirement (or touch the row to re-affirm)`.
   Re-affirming is deliberately cheap: any reviewed edit to the WI row (even a
   date note) clears the warn — the point is a *driven look*, not ceremony.
3. Best-effort and silent off-git (the `--stale` posture): no git, a shallow
   clone, or an unparseable blame degrades to no findings, never a false
   fail. `deferred` rows are exempt (they re-enter via an owner un-defer,
   which is itself the driven look).
4. Tests: amended-SR-after-filing warns; WI touched after the amendment is
   quiet; SpecRef-target edit warns; off-git is silent; deferred exempt.

**No new SR** (the WI-129 precedent: a warn-tier checker feature). Un-defer
trigger: if this is ever promoted to a gating tier, that promotion drafts the
SR.

## Interfaces

Extends `check_trajectory`'s existing consume of the trajectory registries
(**IF-023** family) with a git read — the same degrade-silently git usage
`staged_findings` already has in-module. No new seam.

## Done-when

- [ ] The warn fires on the fixture cases above and stays warn-only (exit 0).
- [ ] The meta repo's own backlog is either quiet or its warns are triaged in
      the filing session's log entry.
- [ ] Full suite + `check.py` at the derived gate stay green.

## Non-goals

- No judgment of *whether* the WI is still valid (reviewer-class); this only
  guarantees the question gets asked.
- No gating, no auto-editing of WI rows, no new registry column.
