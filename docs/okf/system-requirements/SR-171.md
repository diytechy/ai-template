# SR-171 — Bounded retry on a declared transient model limit

**Requirement.** The delivered loop content shall retry a declared transient provider limit under a bounded backoff rather than ending the run, and shall surface the wait so a reader can tell a throttled run from a wedged one.

**Acceptance criteria.** A declared transient limit is retried under the declared backoff and the run continues; the wait is visible on the run surface rather than silent; a limit that is not declared transient ends the run with its own outcome code rather than retrying; the retry count and interval come from a declared value, never a literal.

**Rationale.** MINTED 2026-08-17 (Sol F12, applied). This obligation was live but stated ONLY in SR-026's acceptance cell, where it minted a requirement the shall never made. Deleting it would have dropped real behaviour, so it is stated here instead. Realizes SN-006 (a walk-away run survives the conditions it will actually meet - a rate limit is the ordinary one) and SN-025. The bound is what separates this from a retry loop: unbounded retry against a limit that is not transient is indistinguishable from a hang, which is the failure SN-006 exists to prevent. Surfacing the wait is the other half - a silent backoff and a wedged run look identical from outside.
