# SR-151 — Hosted CI runs the declared bar per trigger

**Requirement.** The shipped reference CI workflow shall invoke, for each declared hosted trigger (push, pull request, schedule) across its declared OS x Python matrix, the same documented harness entry point at the tier the declared moment-to-tier table assigns to that moment.

**Acceptance criteria.** The shipped workflow's trigger set and per-trigger tier match the declared moment-to-tier table, pinned by test; a workflow trigger absent from the table, or one invoking anything other than the documented harness entry point, is a finding; the declared OS x Python matrix cells appear in the shipped workflow; SR-019's acceptance cross-references this row rather than restating it.

**Rationale.** Realizes SN-005 — one definition of passing per moment, its acceptance's own words — and SN-004. The obligation existed but had no row of its own: it rode SR-019's acceptance cell (census finding F1). Attributed to B-05, the delivered package, on the DESIGN-CONTROL reading (owner ruling 2026-08-16): what this system delivers is a METHOD for a CI runner to invoke, and it holds no design authority over whether an external runner honours the configuration it is handed — so the obligation this row can actually carry is a property of the shipped workflow file, not of a hosted trigger arriving. The frame already reasons this way twice: REL-002 records that the generators ship as B-05 content while the workflow running them is adopted, and REL-003 lands the provider-surface obligation on "delivered loop content (B-05), exercised session-side" rather than minting a crossing for EXT-005. Stated artifact-shaped per §1R.6: the job files are a standing thing whose declarations are pinned by test. An adopter-edited workflow copy is outside this claim, exactly as SN-005 narrows it.
