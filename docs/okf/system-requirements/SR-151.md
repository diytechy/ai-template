# SR-151 — Hosted CI runs the declared bar per trigger

**Requirement.** The shipped reference CI workflow shall invoke, for each declared hosted trigger (push, pull request, schedule) across its declared OS x Python matrix, the same documented harness entry point at the tier the declared moment-to-tier table (docs/stack.ini [ci-tiers]) assigns to that moment.

**Acceptance criteria.** tests/test_ci_tier_declaration.py pins the shipped workflow's trigger set and per-trigger tier against the declared [ci-tiers] table; a workflow trigger absent from the table, or one invoking anything other than the documented harness entry point, is a finding; the declared OS x Python matrix cells appear in the shipped workflow; SR-019's acceptance cross-references this row rather than restating it.

**Rationale.** Realizes SN-005 — one definition of passing per moment, its acceptance's own words — and SN-004 at the hosted edge. The obligation existed but had no row of its own: it rode SR-019's acceptance cell (census finding F1), so the B-06 crossing was a frame nobody had stated an observable at. Stated artifact-shaped per §1R.6: the job files are a standing thing whose declarations are pinned by test. An adopter-edited workflow copy is outside this claim, exactly as SN-005 narrows it.
