# SR-029 — Coordinator lock auto-release

**Requirement.** The per-worktree coordinator lock shall be a kernel advisory lock the OS releases on process death, leaving no stale-pid wedge.

**Acceptance criteria.** After the lock holder dies, the next run acquires the lock; no stale-pid file blocks it.

**Rationale.** Realizes the dissolved edge expectation that a coordinator killed mid-session leaves the next run un-wedged — the dispatcher, each worker and an interactive sitting all take this lock, so a holder that dies without releasing it wedges every one of them behind an entry nobody can safely clear. A pid file plus a liveness check was rejected because it cannot decide the case it exists for: if the pid has been reused the check sees a live process and keeps a dead lock forever, and if it guesses the other way it clears a lock that is still held. A kernel advisory lock releases on process death by construction, so the question never arises.
