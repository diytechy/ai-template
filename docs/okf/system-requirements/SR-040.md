# SR-040 — Per-phase routing and review dial

**Requirement.** The unattended coordinator shall select the agent command template per in-process session phase (PLAN/BUILD/REVIEW-A/REVIEW-B/DESIGN-CHECK/CRITIQUE - the coordinator's own activity; the retired docs/run-phase file, deleted by SR-059, is not an input) via AGENT_CMD_MAP/--cmd-map, falling back to the single AGENT_CMD; surface the declared reviewer dial (docs/review-policy, default 1) at run start without enforcing it; and warn (never block) when a lane resume surface exceeds the declared size threshold.

**Acceptance criteria.** A mapped session phase invokes its own command template and the default template does not fire; a broken map entry fails preflight before iteration 1; the banner surfaces the reviewer dial from docs/process.toml [policies] review_rounds; an oversized status.md warns on stderr while the run proceeds; AGENT_STATUS_WARN_BYTES=0 silences.

**Rationale.** Realizes SN-006 and SN-016 — two samples of one model share blind spots, so a review by the family that built the change agrees with it for the wrong reasons; cross-family routing is what makes the second opinion independent, and one model for every phase was rejected on that basis. Dispatch stays keyed off the in-process session phase because the alternative, a per-phase code branch, makes adding a phase a code change and so discourages adding one. The resume surface's growth tripwire warns rather than fails because a growing resume surface is a smell and not a defect, and failing on a smell trains an operator to bypass the check.
