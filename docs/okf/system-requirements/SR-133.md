# SR-133 — Work-branch lane skip for freshness steps

**Requirement.** On a claimed work branch (one whose history holds a docs/work/active/<branch>/ claim) check.py's generated-artifact freshness steps shall SKIP with a stated trunk-lane reason - generated artifacts are trunk-only - while every non-freshness step still runs.

**Acceptance criteria.** on a claimed work branch the declared freshness steps SKIP with a §5.2 notice and exit code untouched while skills-sync, trajectory and registry-integrity still run; the closing commit and its successors keep the skip (the signal derives from branch history, not the working tree); the trunk lane never skips them.

**Rationale.** The skip is not a weakening: a work branch cannot commit generated artifacts at all (concurrency-restructure §5.2), so demanding their freshness there would force the very conflict the rule deletes; the skip is reported, never silent, and any signal ambiguity resolves toward the full trunk bar.
