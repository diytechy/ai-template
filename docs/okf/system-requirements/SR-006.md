# SR-006 — Gate/tier harness enforces required steps

**Requirement.** check.py shall run the active gate's required steps and fail the gate when a required tool is missing, reporting SKIP(missing) rather than silently passing; on a claimed work branch (one holding a docs/work/active/<branch>/ claim) the generated-artifact freshness steps shall SKIP with a stated trunk-lane reason - generated artifacts are trunk-only - while every non-freshness step still runs.

**Acceptance criteria.** check.py --gate GN runs that gate's steps; a required-but-absent tool fails the gate with guidance (never a silent pass), and --lenient degrades it to SKIP; --tier selects the declared step subset; on a claimed work branch the declared freshness steps SKIP with a §5.2 notice and exit code untouched while skills-sync, trajectory and registry-integrity still run.

**Rationale.** Realizes SN-004 (gates enforce their bar), SN-008 (no false green) and SN-014 (a missing tool fails, never skips). The work-branch skip is not a weakening: a work branch cannot commit generated artifacts at all (concurrency-restructure §5.2), so demanding their freshness there would force the conflict the rule exists to delete; the skip is reported, never silent.
