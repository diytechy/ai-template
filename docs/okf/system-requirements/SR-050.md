# SR-050 — Process reference view

**Requirement.** gen_trajectory.py shall render a Process reference tab in PROJECT_STATE.html beside the existing views, presenting how the project is built as three linked panels: (1) artifact lifecycle x gates - Vision -> SN (G1) -> SR (G1->G2) -> LLR + architecture (G2) -> TC (G2->G3) -> code+tests (G3), each stage linked to its process-doc section and annotated with this repo live tier counts; (2) the resume loop - the managed agent_loop flow (read status -> PLAN -> BUILD -> REVIEW -> INTEGRATE -> commit -> hook/gate -> repeat) with its escalation edges; (3) slices -> campaigns -> gates - a per-WI slice ends at the commit bar, a campaign closes at the gate bar, CI runs the same bar every push. Data-derived where a canonical source exists (docs/gate, the spine registries, work-items.csv); self-contained and byte-deterministic; a data-less repo renders byte-identically; --check freshness unchanged.

**Acceptance criteria.** The Process tab renders the three panels; the current-gate highlight reflects docs/gate and the tier counts match the registries; process-doc links resolve; a bundle-/data-less repo renders byte-identically; generation is byte-deterministic and --check trips on stale output.

**Rationale.** Realizes SN-010/SN-021 per the owner rulings 2026-07-12 (docs/specs/WI-085.md): the dashboard shows project state but not the method; a process view makes the gated process legible. Anti-duplication bounded: link out where a canonical home exists; restate in-view only relationships no single doc states. Generated is the ideal; a static-authored panel downgrades verification to Critique (the WI-068 vocabulary).
