# SR-050 — Professional hierarchical project-state diagrams

**Requirement.** gen_trajectory.py shall render the What view as a readable complete multi-parent SN→SR→LLR→TC flow and the When and How-SW views as count-thresholded keyboard-accessible hierarchical diagrams: Phase→Workstream→WI with Campaign as an alternate grouping and a lifecycle-derived delivery frontier; and Component→Module over declared IF seams, with parent connections inherited from children.

**Acceptance criteria.** What shows four bounded tiers, readable cards, explicit arrows, Draft artifacts, and every valid parent edge. When applies the >3 phase/workstream thresholds, derives phase from SR refs/anchors, distinguishes Cross-phase/Unphased/deferred work, labels the non-calendar delivery frontier, preserves Campaign mode, and aggregates parent edges exactly from children. How-SW applies the >3 component threshold without waiving TOP_VIEW_MAX, drills component→module, and aggregates declared IF seam IDs. All modes are offline, deterministic, mobile/keyboard accessible, geometrically non-overlapping on dense fixtures, and --check-stable; legacy/data-absent fallbacks remain honest.

**Rationale.** Extends the existing freshness-gated dashboard rather than adding another state surface. The hierarchy preserves the campaign, component, interface, OKF, and derived-gate contracts while making dense diagrams readable and honest.
