# SR-055 — Ingest and human-decision process loops

**Requirement.** The Process tab shall additionally render the project's two circular working
loops as linked flow panels:
(A) the intake loop - owner/agent intake -> triage into work items with spec
detail -> the scheduler-derived ready frontier in the WI registry (docs/work/)
-> build/review -> merge; and
(B) the human-decision loop - open-items population (including the
gate-ratification table) -> human review and ruling -> the log's Decisions
record -> merge
- with the LLM_Agent entry point rendered once and shared by both loops;
each stage links to its canonical home (status.md, the WI registry
(docs/work/), open-items.html, log.md);
the panels stay data-derived where a canonical source exists, self-contained,
byte-deterministic; a data-less repo renders byte-identically and --check
freshness is unchanged.

**Acceptance criteria.** The Process tab renders both loop panels with the shared LLM_Agent entry point appearing once; every stage's link resolves to its canonical doc; the gate-ratification stage appears in loop B; a data-less repo renders byte-identically; generation is byte-deterministic and --check trips on stale output.

**Rationale.** Realizes SN-010 and the dissolved edge expectation that a generated artifact drifting from its source fails its --check — the Process tab shows the artifact lifecycle, the resume loop and the slice cadence, but not how work ENTERS or how the human decides, which are the two circular flows that close the method's loop; without them a reader sees the machine and not the way into it. Folding them into the existing panels was rejected: they are loops, and a linear lifecycle panel cannot show a cycle.
