# SR-055 — Ingest and human-decision process loops

**Requirement.** The Process tab shall additionally render the project's two circular working loops as linked flow panels: (A) the intake loop - owner/agent intake -> triage into work items with spec detail -> the scheduler-derived ready frontier in work-items.csv -> build/review -> merge; and (B) the human-decision loop - open-items population (including the gate-ratification table) -> human review and ruling -> the log's Decisions record -> merge - with the LLM_Agent entry point rendered once and shared by both loops; each stage links to its canonical home (status.md, work-items.csv, open-items.html, log.md); the panels stay data-derived where a canonical source exists, self-contained, byte-deterministic; a data-less repo renders byte-identically and --check freshness is unchanged.

**Acceptance criteria.** The Process tab renders both loop panels with the shared LLM_Agent entry point appearing once; every stage's link resolves to its canonical doc; the gate-ratification stage appears in loop B; a data-less repo renders byte-identically; generation is byte-deterministic and --check trips on stale output.

**Rationale.** Realizes SN-010/SN-021 (owner intake 2026-07-13 item 1A): SR-050's Process tab shows the artifact lifecycle, the resume loop, and the slice/phase cadence, but not how work ENTERS (intake -> WIs) or how the human decides (open items -> ruling) - the two circular flows that close the method's loop; a facet SR of the SR-038/SR-050 dashboard family, per the WI-085-ruled new-SR pattern.
