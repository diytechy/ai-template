# SR-002 — Integrity floor for ids and CSV structure

**Requirement.** trace.py shall fail --strict-integrity on a duplicated or malformed registry id, a data row whose column count differs from its header, or a TC that pairs an LLR with an SR it does not decompose.

**Acceptance criteria.** --strict-integrity exits 1 on a duplicate/malformed SR/LLR/TC/PB/REPO/MOD/PART/ASSET/CMP/IF id, a mis-columned row, or an incoherent SR/LLR pairing in one TC, and 0 otherwise; orphans do not affect it. MOD is the legacy compatibility id for current REPO rows.

**Rationale.** Realizes SN-002 — a misaligned or duplicated id corrupts the join before the orphan rules can notice, so the report is confidently wrong rather than red, and an incoherent SR/LLR citation contradicts the LLR's own parent link, leaving two answers to one question. Checking only at a gate was rejected: these are wrong the moment they are written, and a gate-only check lets a broken join sit in the tree for days.
