# SR-130 — Serial trunk step compiles log fragments and regenerates authority

**Requirement.** A serial trunk step shall compile docs/log.d/ work-branch log fragments into
docs/log.md in merge order derived from git history.
It shall validate every fragment before any write, rebase relative links to the
log's home, delete compiled fragments, fail loudly at the first error, and never
commit.

**Acceptance criteria.** Two committed fragments compile in git-add order with links rebased docs/-relative and the fragments deleted; an uncommitted or malformed fragment blocks the whole batch with nothing appended; a fragment-free run is a clean no-op.

**Rationale.** The §5.1/§5.2 shared-surface rules (concurrency-restructure): no work branch writes log.md, so hand-merged logs become unrepresentable; the one deliberately serial actor stays tiny, idempotent and fail-loud (§5.5). The artifact-regen half is SR-134's obligation (one row, one obligation).
