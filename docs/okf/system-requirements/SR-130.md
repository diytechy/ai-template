# SR-130 — Serial trunk step compiles log fragments and regenerates authority

**Requirement.** A serial trunk step shall compile docs/log.d/ work-branch log fragments into docs/log.md in merge order derived from git history - validating every fragment before any write, rebasing relative links to the log's home, and deleting compiled fragments - and shall regenerate the declared generated artifacts in dependency order, failing loudly at the first error and never committing.

**Acceptance criteria.** Two committed fragments compile in git-add order with links rebased docs/-relative and the fragments deleted; an uncommitted or malformed fragment blocks the whole batch with nothing appended; a fragment-free run is a clean no-op; --regen skips absent artifact families with a notice and stops loudly at the first failing generator.

**Rationale.** The §5.1/§5.2 shared-surface rules (concurrency-restructure): no work branch writes log.md or commits generated artifacts, so hand-merged logs and stale-artifact merge conflicts become unrepresentable; the one deliberately serial actor stays tiny, idempotent and fail-loud (§5.5), and a red trunk lane halts claiming instead of merging staleness.
