# SR-046 — Run capability menu

**Requirement.** The launchers at the repository root shall present every major
capability an evaluator runs from a single launch declaration - one name = command line
(plus an optional name.desc line) per capability - reading it so that
no args gives a numbered interactive menu;
a named capability launches directly with exit-code passthrough;
and a machine listing emits a stable name<TAB>desc line per capability (the agent surface).
An absent or empty launch declaration prints the no-launch-command-wired-yet guidance
and exits 1.
The launch command is declared once and works on Windows and POSIX.

**Acceptance criteria.** run_menu.py --list prints one name<TAB>desc line per declared capability in declaration order; run_menu.py <name> runs that capability's command and returns its exit code; the no-arg menu launches a stdin-selected capability non-interactively and does not hang on closed stdin; an absent/empty [run] section prints guidance and exits 1; a name.desc row renders in the menu and list; the run.* launchers delegate to run_menu.py with no RUN_CMD; the scaffold ships run_menu.py plus the delegate launchers. Read off the current carrier, as the current set: the root run.cmd/run.sh/run.command delegating to a stdlib scripts/run_menu.py that reads docs/stack.ini's [run] section.

**Rationale.** Realizes SN-001 - the evaluator's rungs make running the product never depend on recalling a command, and the capability set is now declared once in docs/stack.ini instead of hard-wired and duplicated across the platform launchers. A new SR formalizing the launcher surface, which previously existed only as process prose.
