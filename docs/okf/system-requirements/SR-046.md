# SR-046 — Declared runnable capabilities reachable from the repository root

**Requirement.** The launchers at the repository root shall expose every declared runnable capability consistently to an interactive operator, to a direct caller naming one capability, and to automated discovery - from a single declaration, on Windows and POSIX alike.

**Acceptance criteria.** A machine listing prints one name-and-description line per declared capability in declaration order; a direct call naming a declared capability runs that capability's command and returns its exit code; the no-arg menu launches a stdin-selected capability non-interactively and does not hang on closed stdin; an absent or empty capability declaration prints guidance and exits 1; a declared description renders in both the menu and the listing; the platform launchers delegate to the one selector rather than carrying commands of their own; a fresh scaffold ships the selector and the delegate launchers.

**Rationale.** RE-VOICED 2026-08-17 (Sol F14, applied): the shall was a MENU SPECIFICATION - numbered interactive menu, direct named launch, machine listing, empty-declaration text, exit-code passthrough, and the name/name.desc declaration grammar - things that fail independently, which is a decomposition wearing a requirement's clothes. It now states the one capability-level decision: every declared capability is reachable, the same way, from one declaration, by three kinds of caller. Numbering, listing format, declaration grammar, fallback text and exit handling are LLR-047's and the acceptance's. Realizes SN-001 - the evaluator's rungs make running the product never depend on recalling a command, and the capability set is now declared once in docs/stack.ini instead of hard-wired and duplicated across the platform launchers. A new SR formalizing the launcher surface, which previously existed only as process prose.
