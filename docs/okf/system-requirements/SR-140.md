# SR-140 — Each acceptance is recorded by a copy riding its own approval commit

**Requirement.** The kit shall record each acceptance as a byte-identical copy of the accepted
registries riding the same reviewed commit as the approval itself - so the
commit, its date and its author come from git rather than from a cell, and the
transition accepted and the acting reviewer that accepted it are distinguishable
BY QUERY, an approval delegated to automation on a tier the declared ratification
level released from a human one.
It shall report text that has moved away from that recorded copy regardless of
any Status movement.
It shall refuse a recorded copy that is not byte-identical to the text it claims
to record in the commit that writes it, so the only path into the record runs
through the live registry first.

**Acceptance criteria.** An artifact whose normative text has moved since the copy that recorded its acceptance is reported whether or not its Status moved; a row claiming approval that no copy records, or whose copy reads at a status making no such claim, is reported rather than passing silently — an approval that never rode a copy; once a record exists, a registry absent from inside it is itself a finding, so the vacuous state is exactly one and it is "nothing has been approved yet"; an acceptance recorded with no acting reviewer, or one whose acting reviewer cannot be told apart from a human's by query, is a finding — releasing a tier delegates the review, it does not skip it; a commit that writes a recorded copy differing from its live counterpart is refused, which is the one comparison that catches a hand edit, a partial copy and a copy-then-amend-live alike; and the same rules hold for a stakeholder need, which has no Status cell for the amendment machinery to watch.

**Rationale.** Attestation STATE is already the row's own Status - derive_gate computes the gate from those cells and reads no other source - so a separate ledger was a second home for a fact the row already carried, and three of its seven columns duplicated cells outright (Decision=ratified|meaning IS Status; superseded IS SupersededBy). What the ledger got right is the BASELINE ITSELF: 'has this been ratified' was answered by walking git for the newest commit where a row read Verified, which is sound only while every amendment flips its row in the same commit - precisely the sanctioned path the staged-amendment guard deliberately ignores, and precisely what the D-9 ladder deletes, so the walk returns HEAD and the diff is empty BY CONSTRUCTION on exactly the rows a sitting exists to judge.
RE-BASED 2026-08-15 (log 2026-08-15d, owner in session) onto the mechanism that was RULED. The on-row anchor this row used to require - a digest of the row's own NORMATIVE cells, written on the row, never in a second registry, and refused when written in the same commit as the text it anchors - is SUPERSEDED AND NOT BUILT; repo-lock D-1's anchor half goes with it. The baseline is instead a whole-file copy of the accepted registries into docs/archive/last_approved/, riding the SAME reviewed commit as the approval (design plans/2026-08-15-baseline-snapshot-design.md §A2/§A3/§F3). Three things follow. First, the commit, date and author the digest design wanted written on-row come FROM the approval commit, so no cell has to carry them and no cell can lie about them. Second, the record is diffable by every git tool and by eye - a record only a script can read is a record only a script can audit. Third, THE SAME-COMMIT CLAUSE REVERSES SIGN, and the reversal is honest rather than a softening: under the anchor design a stamp written beside its own amendment HID the amendment, so it was an error; under copies the copy MUST ride the approval commit, because riding it is the only thing that makes "this copy is what was blessed" decidable. The anti-laundering property the old clause bought is carried instead by the MIRROR INVARIANT (§F3 - any commit touching the record must leave it byte-identical to its live counterpart, so the only way to write text INTO the record is to write it live first, in a reviewed commit) together with the SEED RULES (§A3 - the first copy refuses to create itself without an explicit seed, so the initial blessing cannot happen by accident, and an absent record is None rather than {} so it can never read as "re-bless everything with no diff shown").
