# SR-140 — An append-only attestation ledger anchors what was accepted

**Requirement.** The kit shall record each acceptance in `docs/requirements/attestations.csv` as artifact, decision and a digest of the row's NORMATIVE cells at acceptance time; shall report text that has moved away from its recorded anchor regardless of Status movement; and shall treat the ledger's own rewrite, removal or malformation as an error.

**Acceptance criteria.** An amend+flip the amendment seam reports as empty is caught by the ledger; a TRACED cell moving does not move the digest and the Modified->Verified flip is not itself drift; a ledger row anchoring an id that is not a current spine row is reported (a `superseded` decision is how one is retired without deleting a row); the ledger's deletion, rename or rewrite between two trees is an error, and its creation is not.

**Rationale.** Deriving "has this been ratified" from git history is sound only under the amend+flip regime — which is exactly the path the staged-amendment detector deliberately ignores, so the SANCTIONED way to amend an attested requirement reached no consumer. An SN has no Status cell at all, so prose had no anchor by any path. A ledger that can be deleted is not an anchor either: its absence silences the drift rung too, and every reader falls back to the derivation it replaced.
