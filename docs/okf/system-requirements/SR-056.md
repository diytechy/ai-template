# SR-056 — Decomposition render polish

**Requirement.** The tiered decomposition views shall render right-sized columns (a tier column no wider than its content requires within a declared bound); one horizontal parent-to-child arrow per containment edge, making containment explicit rather than implied by nesting alone; and a hover/focus highlight that persists on the last-hovered item until another takes it (no flash-on-exit); self-contained, byte-deterministic, --check freshness unchanged.

**Acceptance criteria.** Each containment edge renders exactly one parent-to-child arrow; column widths honor the declared bound; the persistent-highlight contract is present and keyed to the last-hovered node; a data-less repo renders byte-identically; deterministic; --check trips on stale output.

**Rationale.** Realizes SN-023 and SN-010 — the shipped tiering (SR-051) made large projects readable top-down, but a column-wasteful render, implicit containment and a highlight that vanishes on exit each cost the reader something on every visit. These have mechanically assertable outcomes, so verification stays a test; the residual look-and-feel is left to the rubric-adjudicated rows rather than asserted here.
