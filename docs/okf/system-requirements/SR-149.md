# SR-149 — Retired-vocabulary refusal in authored surfaces

**Requirement.** The harness shall report every occurrence of a retired process tag in a live authored surface, naming the file and line and the vocabulary that replaces it, at a severity that warns by default and fails under --strict; and it shall report none in a declared historical, generated or attestation-quoting surface, nor in a line or file marked as a declaration site.

**Acceptance criteria.** check_vocab.py reports a planted retired tag in a live authored file with its path and line, exits 0 under the default severity and 1 under --strict; reports nothing for a file under any declared carve-out class (archive, the project log, attestation briefs, closed and cancelled work-item specs, generated surfaces) including at arbitrary depth; reports nothing for a line carrying the allow marker or a file carrying the allow-file marker; and reports nothing for the word "gate" used to mean a check that can fail.

**Rationale.** Realizes SN-004 (the ladder's vocabulary is the one the project is held to) and SN-010 (docs stay honest). OI-21 made this check a CONDITION of the vocabulary conversion rather than a follow-up, on measured evidence: an earlier sweep removed a retired-tag construct from this repo's own open-items registry and it REGENERATED within days, caught only by an audit. A ~2,500-edit conversion held in place by attention is a conversion that comes undone. The carve-outs are as load-bearing as the rule: history is not rewritten and an attestation is never re-worded, because a swept sign-off makes a signed record claim something was signed that was not.
