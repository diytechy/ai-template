# SR-054 — Dashboard usability (rubric-adjudicated)

**Requirement.** PROJECT_STATE.html shall support its core reading tasks with low friction: a first-time reviewer finds the project state, the next work, and how the parts connect, each within one tab switch; views default to a legible density (start-collapsed per the greater-than-3 rule) and reveal detail without losing context; labels stay readable at default zoom with no clipped or overlapping text.

The RUBRIC is the acceptance instrument and the single home for which anchors are live: an anchor whose core has been bound to a test is retired there, and a verdict must not cite a retired anchor. This row therefore does not enumerate the live set - it would be a third copy of it, and the copy that goes stale. A clause of the requirement above that a test now holds is verified through the LLR/TC chain, which the registry already records, not by a verdict.

**Rationale.** Realizes SN-024 and SN-023 — task-level usability is perceptual (is this findable, is this legible), so a test can confirm an element exists and not that a reader can use it. Acceptance is adjudicated against a written rubric derived from the stakeholder intent rather than from the test, because a test written by the builder encodes the builder's own idea of usable.
