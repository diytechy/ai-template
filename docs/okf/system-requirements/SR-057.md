# SR-057 — WI-DAG frontier scheduling

**Requirement.** A stdlib schedule.py library/CLI shall derive the dependency-ready frontier from the tracked WI registry plus dispatcher reservations - never from prose - excluding blocked/deferred/reserved/protected-conflicting/exclusive-conflicting WIs, and shall order eligible traincars deterministically by (gate class, Priority desc, transitive downstream-dependent count desc, remaining hard-path length desc, first WI id), exposing ready --explain, ready --format json, and simulate --jobs N.

**Acceptance criteria.** On a fixture registry the ready set contains exactly the WIs whose hard predecessors are integrated done or accepted-on-train, excludes each blocked/deferred/reserved/exclusive-conflicting WI with a reason code, and orders identically across --explain, --format json, and the dispatcher; a soft edge never blocks; Priority outranks downstream-dependent count within one gate class; simulate --jobs 1 matches the serial order.

**Rationale.** Realizes SN-025 - readiness is derived and inspectable so the same scheduling decision is reproducible across validator, dashboard, dispatcher, and tests (docs/specs/parallel-wi-dispatch.md 4); retiring the hand-curated docs/next-wi requires a deterministic selector to take its place.
