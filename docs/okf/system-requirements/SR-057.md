# SR-057 — WI-DAG frontier scheduling

**Requirement.** A stdlib schedule.py library/CLI shall derive the dependency-ready frontier from
the tracked WI registry plus the active claims - never from prose.
It shall exclude blocked (queued + blockref), deferred, claimed,
protected-conflicting and exclusive-conflicting WIs.
It shall expose ready --explain, ready --format json and simulate --jobs N.

**Acceptance criteria.** On a fixture registry the ready set contains exactly the WIs whose hard predecessors are done, and excludes each blocked/deferred/claimed/exclusive-conflicting WI with a stated reason code.

**Rationale.** Realizes SN-025 and SN-006 — readiness read from prose is a decision nobody can reproduce, so the validator, the dashboard, the dispatcher and the tests each answer "what is ready" differently, and the disagreement surfaces as a WI dispatched against an unmet predecessor. Keeping the hand-curated pointer file was rejected: it encodes one person's ordering and goes stale the moment the DAG changes.
