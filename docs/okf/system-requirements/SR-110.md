# SR-110 — Per-module coverage floors

**Requirement.** check_coverage.py shall fail when a module listed in the coverage-floor census is below its declared per-module line-coverage percentage in the pytest-cov JSON report, or is absent from that report, so the global --cov-fail-under floor cannot hide a thin high-risk module; an absent report skips and an empty census is a no-op.

**Acceptance criteria.** A module below its floor exits 1 naming it; a declared module absent from the report exits 1; all floors holding exits 0; no coverage report (e.g. the smoke tier) SKIPs; an absent or empty census is a clean no-op; a malformed floor line fails loudly.

**Rationale.** Realizes SN-008 and SN-012 — one aggregate coverage number lets well-tested generators subsidize thin coverage at the security and process boundaries, so a green overstates confidence exactly where it matters most. Raising the single global threshold was rejected: it penalizes every module for the weakest one without ever naming it. Opt-in at the product layer, so a non-adopter pays nothing.
