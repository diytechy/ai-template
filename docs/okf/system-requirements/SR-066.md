# SR-066 — Dual-plan decomposition round

**Requirement.** A queued WI whose registry row declares PlanMode=dual shall be decomposed by a dual-plan round rather than a direct BUILD: two independent fresh planner sessions (routed to different model families where the enabled pool allows, else a recorded same-family degraded pair), a mechanical coverage pre-pass gating each plan, one cross-critique in which each plan is judged by the other hat's route, one bounded revision each against CHANGES-REQUESTED, and a position-swapped arbiter pair whose two runs must agree on the TRUE plan; the selected plan's rows are filed as queued WIs hanging off the round's parent. Hard caps bound the spend (one critique round, one revision each, one coverage repair per plan per stage, a round-budget session ledger); every cap breach, arbiter disagreement, runtime-nonresponse, or budget exhaustion shall PAGE onto docs/gate-policy's failure semantics rather than proceed. Briefs shall be assembled allowlist-only from system-requirements.csv + interfaces.csv so status.md/log.md/self-assessments are unreachable by construction; sessions run in the repo cwd on that redaction floor, with empty-cwd isolation an optional hardening. The worker assignment path shall refuse a PlanMode=dual row fail-closed (naming the --dual-plan entry); and for frontier auto-dispatch (deferred to the --jobs dual-dispatch WI) a PlanMode=dual row is ruled to classify as a single-WI traincar - the SR-058 high-risk/critique class derived from the PlanMode signal, never packed with other WIs.

**Acceptance criteria.** agent_loop --dual-plan over a fixture PlanMode=dual WI runs the full round unattended (plans, coverage, cross-critiques, both position-swapped arbiter runs agreeing) and files the selected rows as queued WIs the real check_trajectory accepts; the worker --wi path refuses a dual row naming --dual-plan and the flag refuses a non-dual row; a position-biased arbiter disagreeing across the swap PAGEs position-unstable with the attended NEEDS-HUMAN run-state; each hat brief carries registry material and never a status.md/log.md sentinel (redacted by construction); a cap breach, budget exhaustion, or arbiter disagreement PAGEs per docs/gate-policy.
