# SR-037 — Work-item registry validation

**Requirement.** check_trajectory.py shall validate the work-item registry — well-formed WI ids, resolvable predecessors and an acyclic dependency DAG — and exit nonzero on a violation, and additionally enforce the status.md-vs-registry single-source-of-truth rules: a WI's Deliverable is non-empty iff its Status is done (R-A, a hard error at every run), and under --strict every open WI is named in status.md (R-B/R-C), no done WI id appears there (R-D), and every open WI's SpecRef resolves to an in-repo target (R-E). A placeholder-only or absent registry passes vacuously, docs/trajectory-check: off silences the step, and an absent status.md leaves R-B/R-C/R-D vacuous.

**Acceptance criteria.** A valid registry exits 0; a malformed WI id, an unresolvable predecessor and a dependency cycle each exit nonzero naming the offender; a placeholder-only registry and docs/trajectory-check: off both pass; an open WI with a filled Deliverable or a done WI with an empty one fails at every run (R-A); under --strict a done WI id in status.md and an open WI with an empty or dangling SpecRef each fail while a compliant registry+status.md passes, and an absent status.md leaves R-B/R-C/R-D vacuous.

**Rationale.** Realizes SN-002 and SN-012 — the prospective roadmap is validated mechanically like the rest of the spine (THREAD_52_REVIEW.md F1 traced this layer's own code), and the opt-out keeps the layer free for a repo that does not use it; the SSOT rules (S1/WI-053) keep status.md forward-only and the Deliverable backward-only so a fresh session launches from a coherent handoff (R-A is the pre-commit floor; R-B..R-E gate under --strict at G2+), and every open WI names a resolvable SpecRef spec-of-record. Rides the pending G3 re-attestation.
