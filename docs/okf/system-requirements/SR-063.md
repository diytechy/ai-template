# SR-063 — Atomic serialized integration

**Requirement.** Integration shall have one logical writer against a dispatcher-owned refs/heads/llm/integration ref (checked out only in its integration worktree; the user's primary worktree stays on the selected development branch): for each ready train in deterministic order the integrator composes from the current integration HEAD, verifies reservation/scope/train-sequence/exact-head review, resolves overlap (re-reviewing any material conflict resolution including a verbatim one-side pick), regenerates the registry/log/status/artifacts, runs the combined bar (and the full/gate bar at a slice/campaign/gate close), and advances the integration ref by compare-and-swap; a worker-reported blocker uses a smaller serialized disposition transaction (Status=blocked plus BlockRef plus evidence, no review-pass claim); and after a successful integration CAS it publishes to the development branch only when that worktree is clean, guarded by a durable refs/llm/publish-intent ref (integration target + expected old development hash + development ref) written before the second CAS + fast-forward/reset sync and deleted only after the sync succeeds.

**Acceptance criteria.** Overlapping trains reach reconciliation and the combined bar; a clean 3-way apply integrates without re-review while any conflict resolution forces a focused re-review; the integration ref advances by CAS and a stale integration ref re-enters composition harmlessly; a blocker durably marks only its WI; a dirty user checkout is left untouched and reported while the integration ref advances; a durable publication-intent ref makes the publish crash-identifiable so a crash between the CAS and the worktree sync finishes idempotently; the singleton intent is retained as evidence and transactionally replaced on a failed CAS via an expected-old CAS on the intent ref (reused only when target + expected old hash + development ref all match, never silently overwritten), and a reset never fires unless both the index tree and tracked worktree are exactly at the intent's expected old hash (untracked files untouched, a checkout obstruction deferring rather than deleting).

**Rationale.** Realizes SN-025 and SN-008 - serialized atomic integration keeps the shipped branch trustworthy: no half-applied root, no done without the combined bar, conflict resolution re-reviewed, and a clean dispatcher-owned/user-projection split (docs/specs/parallel-wi-dispatch.md 5.2/9).
