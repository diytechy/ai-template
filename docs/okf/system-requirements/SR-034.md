# SR-034 — Kit scripts run on stdlib plus ledger-declared dependencies

**Requirement.** Every kit script shall run on a clean Python 3.11+ using the standard library plus only those non-stdlib dependencies declared as a reviewed row in the dependency ledger.

**Acceptance criteria.** An AST scan of scripts/*.py resolves every top-level import to stdlib, a local sibling, or a Kind=python row in docs/dependencies.md; an undeclared non-stdlib import fails the suite; every declared row names what it replaces, why hand-rolling is worse, and the ruling that admitted it; a shipped-tier row (one an adopter is forced to install) exists only with an owner ruling recorded in the ledger, stdlib remaining preferred there. Read off the current carrier, as the current set: docs/dependencies.md.

**Rationale.** Realizes SN-011 — the kit must impose no *unargued* dependency stack on a downstream repo to run its checks, but a blanket ban is itself a design constraint that can force a worse hand-rolled alternative than a well-chosen tool, so the bar is a reviewed argument per dependency (owner RULING-3, 2026-07-28), not abstinence. Leaving the row at "stdlib-only" was rejected: it had already drifted from the standing ruling, leaving the registry and the ledger giving two answers to one question.
