# SR-141 — Adopter-owned configuration survives re-sync

**Requirement.** A kit re-sync shall preserve an adopter-edited docs/config.toml byte-for-byte and run the converter for any retired source still present.

**Acceptance criteria.** A simulated re-sync onto a repo with an edited config leaves that file unchanged and converts any remaining retired source; a re-sync onto a repo with no config writes the template.

**Rationale.** The declared toolchain file already carries this property and adopters rely on it; a configuration file that a re-sync overwrote would make upgrading the kit cost an adopter their whole behavioural setup. Running the converter during re-sync is what stops an upgraded adopter meeting the mixed-source refusal unaided.
