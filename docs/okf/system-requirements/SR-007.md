# SR-007 — Declared stack profile, refused when it is broken

**Requirement.** check.py shall read the toolchain (format/lint/test commands, tiers, coverage, arch-map mode) from docs/stack.ini so a stack swap edits only that file, failing loudly on a malformed profile or a non-integer coverage threshold rather than proceeding on a bad one.

**Acceptance criteria.** check.py resolves each step's command from stack.ini; changing the profile changes the commands run, with no script edit; a malformed profile or a non-integer coverage threshold produces a clear nonzero failure at the relevant step rather than a run on a bad profile (a missing declared binary fails under SR-006, which states that clause).

**Rationale.** Realizes SN-003 — the kit is stack-agnostic; the harness is re-pointed by declaration, not by editing a kit script. ABSORBS SR-008, 2026-08-15: reading a declaration and REFUSING a broken one are one obligation, not two — a reader that proceeds on a malformed profile has not read it. SR-008 named a script and a mechanism, which is the census's demotion criterion, and `trace.py` had already been warning that its only child (LLR-008) "mostly re-words" it, the shape a row takes when it is a design detail wearing an SR id. Its third clause, a MISSING DECLARED BINARY, is not folded here: SR-006 already states it verbatim as its own ("fail that gate when a required tool is missing"), which is why LLR-008 now decomposes from both rows rather than one. SR-008 was `Verified`; the demotion overrides that attestation deliberately, under the owner's 2026-08-15 ruling, and is named in the log rather than ridden in quietly.
