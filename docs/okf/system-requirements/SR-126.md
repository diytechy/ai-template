# SR-126 — Spine stand-alone rule

**Requirement.** trace.py shall fail under --strict when any spine row's normative text cites a work item or a process doc.

**Acceptance criteria.** A WI id or a process-doc citation in an SR Title/Requirement/Rationale/AcceptanceCriteria, an LLR Title/Detail/Rationale, or a TC Method/Expected/Parameters exits 1 under --strict and names the registry, row and cell; a script name, artifact path, rubric or sibling spine id does not; pointer columns are out of scope.

**Rationale.** Realizes SN-010 — a row that cites a work item is unreadable to the audience that matters most: a downstream adopter, or an agent, with none of this project's history, who must resolve an id they cannot see before they know what the system does. A process-doc citation fails differently and just as badly: a row that cites the rule it is obeying inverts the relationship, so amending the process silently changes what the row appears to require. Warning instead of failing was tried and rejected: a warn nobody must act on is how 43 such rows accumulated before anyone measured them.
