# SR-148 — Autonomous loop phase order

**Requirement.** The unattended coordinator shall select work in this order — ready adjudication rows first, as a stable partition applied at admission rather than by renumbering the ruled rank table; then unresolved handback records; then the earliest incomplete spine tier in SN-to-SR-to-LLR-to-TC order; then implementation work after test-case layout is complete — applying human holds only from the declared ratification level and never admitting anything past a human-held stop.

**Acceptance criteria.** A ready adjudication row admits ahead of every other class, the ruled rank table unchanged (--explain still reports it) and non-adjudication rows keeping their relative order; an unresolved handback is selected before spine or implementation work, and processing it either resolves the record or mints a provenance-linked successor exactly once; with no unresolved handback, only the earliest incomplete spine tier is eligible; implementation work is ineligible while any required test case remains unlaid; at human_ratification_through = 0 no spine tier produces a human hold, levels 1 through 4 hold exactly their documented cumulative tiers, and a human-held attestation still drains and surfaces with the adjudication row waiting behind the stop; every selection records the chosen class, source identifier and hold decision.

**Rationale.** Without one precedence rule, the same repository can resume into implementation while returned obligations or prerequisite requirement tiers remain unresolved. That produces work against stale intent and makes repeated resumes select different next actions. A recorded selection class, source record and hold decision provide replayable evidence of the choice.
