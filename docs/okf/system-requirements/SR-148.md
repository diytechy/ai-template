# SR-148 — Autonomous loop work selection: what it derives from, and in what order

**Requirement.** The delivered loop content shall select the work an unattended run does next from the repository's tracked registries and git history alone — shipping no hand-curated next-work or run-phase pointer surface for any live instruction or executable surface to read, write, validate, generate or link, and deriving from no prose surface and no predefined track — in this order: ready adjudication rows first, as a stable partition applied at admission rather than by renumbering the ruled rank table; then unresolved handback records; then the earliest incomplete spine tier in SN-to-SR-to-LLR-to-TC order; then implementation work after test-case layout is complete — with the eligible set and its order deterministic, an item whose declared safety, policy or plan-mode inputs are missing, undeclared or contradictory failing closed for that item alone, human holds applied only from the declared ratification level, nothing admitted past a human-held stop, and the status surface a session reads generated and freshness-gated rather than hand-copied.

**Acceptance criteria.** A ready adjudication row admits ahead of every other class, the ruled rank table unchanged (--explain still reports it) and non-adjudication rows keeping their relative order; an unresolved handback is selected before spine or implementation work, and processing it either resolves the record or mints a provenance-linked successor exactly once; with no unresolved handback, only the earliest incomplete spine tier is eligible; implementation work is ineligible while any required test case remains unlaid; at human_ratification_through = 0 no spine tier produces a human hold, levels 1 through 4 hold exactly their documented cumulative tiers, and a human-held attestation still drains and surfaces with the adjudication row waiting behind the stop; every selection records the chosen class, source identifier and hold decision. Two resumes over the same tracked state select the same eligible set in the same order; an item with missing or contradictory declared inputs is excluded with a stated reason while disjoint classified work stays eligible; no prose surface participates in the derivation; the ordering and exclusion reasons are exposed for replay. A fresh scaffold ships no next-wi/run-phase pointer and is parallel-by-default; no live instruction or executable surface reads, writes, validates, generates or links such a pointer; a build-out lane's phase resolves from its branch name with no pointer file; the status snapshot regenerates mechanically and its freshness is gated.

**Rationale.** Without one precedence rule, the same repository can resume into implementation while returned obligations or prerequisite requirement tiers remain unresolved. That produces work against stale intent and makes repeated resumes select different next actions. A recorded selection class, source record and hold decision provide replayable evidence of the choice.
