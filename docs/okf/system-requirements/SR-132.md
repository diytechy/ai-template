# SR-132 — Local integrator: serial fail-closed merge queue

**Requirement.** The local integrator shall claim work via a serial trunk commit (queued spec to docs/work/active/<branch>/, branch cut from that commit, refused while docs/work/pause is present), merge each finished claimed branch --no-ff onto a candidate worktree with the trunk step folded into the merge commit, run the declared bar on the composed tree - refusing on a missing or empty check declaration and on any SKIP in the bar's own report - require the policy-dialed verdict artifacts with git-derived freshness, fast-forward the trunk only on green, and stop loudly on red.

**Acceptance criteria.** A claim moves the spec and cuts the branch in one serial trunk step and is refused when paused, dirty, name-unsafe, not-ordinary or not-ready; a finished branch is detected from its tree alone; an absent or stale or CHANGES-REQUESTED verdict refuses the merge; a missing stack.ini or empty [product] test refuses; a red bar parks the candidate and stops the queue; the RULING-6 window audit flags a non-merge product commit.

**Rationale.** The §1.2 seam's default backend: serial => composed-tree gating by construction; fail-closed against the dispatcher's recorded fail-open (a skipped bar merged 8 trains with zero gate-verified). Verdict freshness is git-derived because the WI-scoped §5.4 naming dropped the sha7 filename binding - without it a stale APPROVE clears the gate.
