# SR-109 — Spec-lifecycle close-side coherence

**Requirement.** check_trajectory.py shall flag a done WI whose SpecRef is non-empty and a live docs/specs file (scaffold README/-000 exemplars excluded) cited by no open WI, warning on every run and failing under --strict.

**Acceptance criteria.** A done row with a SpecRef and an uncited live spec each produce an R-F WARN with exit 0 on a plain run and exit 1 under --strict; a shared doc cited by any open (incl. deferred/blocked) WI stays clean; docs/specs README and -000 exemplars never flag.

**Rationale.** Realizes SN-002 and SN-012 — the open half of the spec-of-record lifecycle was enforced and the close half was not, so a repo accretes stale SpecRefs and orphan live specs (measured at 137 rows and roughly 60 files) until nobody can tell which spec is live. A prose close rule was rejected because it is the control that was already in place while that backlog accumulated: an unenforced rule is indistinguishable from no rule at the point it matters. Opt-in and vacuous on a fresh scaffold.
