# SR-147 — Exactly-once remediation for a red declared bar

**Requirement.** A red declared harness on a fully implemented trunk shall persist one failure event keyed by tree identity, failing step and failure fingerprint, and produce exactly one remediation draft for that key.

**Acceptance criteria.** One red bar produces one failure event and one remediation draft; a repeated identical failure produces no second draft; a different failing step or fingerprint produces a second draft; the draft carries the adjudicated effort, build tier and plan mode and enters the queue only through admission.

**Rationale.** A red bar that merely stopped the loop left the failure undiagnosed and unowned; a red bar that minted on every cycle would flood the queue with duplicates of one defect. Keying the event by the tree, the step and the fingerprint makes the identity a property of the failure rather than of the observer.
