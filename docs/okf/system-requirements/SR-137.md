# SR-137 — One policy home, with a checked shape

**Requirement.** The kit shall read every process policy dial from a single `docs/process.toml`, and shall REFUSE — never resolve by precedence — a repo in which any dial is declared both there and in its legacy one-word file. The file's line shape shall be a checked contract: one `key = value` per line under a bare `[section]` header, no dotted keys, no inline tables, no multi-line strings.

**Acceptance criteria.** A dial declared in both homes produces a refusal naming the key and both files, at every guarded entry point (the dispatcher's pre-claim preflight, intake's adjudication arm, the integrator's verdict gate); a dotted key, inline table, multi-line string or hook-read key under the wrong section is refused by the shape check AND still reads ON in both readers; the hooks' sh and `tomllib` return the same answer over the adversarial file table; a wrong-typed or out-of-range dial is refused rather than defaulted.

**Rationale.** Two grammars read this file — `tomllib` in Python and the three git hooks in pure sh, so a Python-less box still fails closed on a declared privacy gate (M-42). TOML is far more expressive than a `grep -E` can follow, so every shape only one reader understands is a silent flip of a security gate; the first cut shipped five such shapes, three of them fail-OPEN. Narrowing the shape and CHECKING the narrowing is what makes one file safe for two readers.
