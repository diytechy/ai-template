# SR-117 — Atomic traincar reservation and lane leasing

**Requirement.** The dispatcher shall reserve a selected traincar's constituent WIs atomically via refs/llm/reservations/WI-### (an off-history commit-tree metadata commit plus one update-ref --stdin zero-old-value transaction), leasing a linked worktree per train, rescanning on every release, completion, block, verdict and integration for dynamic refill, and honoring pause, blackout and model-capacity limits.

**Acceptance criteria.** The atomic reservation transaction claims all constituents or none; pause stops new reservations at the next boundary; a released lane is refilled without restarting the run.

**Rationale.** Realizes SN-025 — without an atomic claim two dispatchers reading the same frontier reserve the same WI and both build it, and a partial claim strands the constituents it did take. A lock file was rejected: it does not survive a crashed dispatcher, while a Git ref is durable and inspectable after the fact.
