# SR-115 — Deterministic ready ordering

**Requirement.** schedule.py shall order the eligible ready frontier deterministically by gate class, then Priority descending, then transitive downstream-dependent count descending, then remaining hard-path length descending, then WI id.

**Acceptance criteria.** Ordering is identical across --explain and --format json; Priority outranks downstream-dependent count within one gate class; simulate --jobs 1 matches the serial order.

**Rationale.** Realizes SN-025 — a frontier that is correct but unordered lets two readers of the same registry dispatch different work, so a rerun stops being reproducible and a scheduling bug cannot be replayed. Ordering by WI id alone was rejected: it ignores the critical path, so the chain everything waits on gets picked last.
