# SR-173 — Shared regeneration is ordered and leaves no partial result

**Requirement.** The delivered loop content shall regenerate the shared derived artifacts in declared dependency order, stopping at the first failure and leaving no partially regenerated set behind.

**Acceptance criteria.** Regeneration runs the declared artifact families in declared dependency order, with a producer before every consumer that reads it; a failure stops the run at that point and reports it rather than continuing; no partially regenerated set is left committed; an absent artifact family is skipped rather than treated as a failure. Read off the current carrier, as the current set: trunk_step.py --regen.

**Rationale.** MINTED 2026-08-17 (Sol F18, applied) out of SR-170, which merged three obligations that fail independently. This is the TRANSACTIONALITY half: ordering and all-or-nothing are one decision about a regeneration run, and they are not the same decision as who is allowed to write (SR-170) or how identity is allocated (SR-174). A regeneration that runs in the right order and still leaves half a set behind satisfies neither, which is what makes them separable. Realizes SN-008 - a first failure that stops loudly beats a half-regenerated set that reads as complete - and SN-010.
