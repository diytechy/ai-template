# SR-152 — One transaction owns every move into the queue

**Requirement.** Every transition of a candidate into the queued state shall run one trunk-side admission transaction validating identity, scope digest, predecessor acyclicity, current references and declared classification.

**Acceptance criteria.** A candidate failing any declared precondition is refused with that precondition named; a passing candidate is admitted with its verdict recorded; a direct write into the queued state without a verdict is refused by the strict trajectory check.

**Rationale.** Several producers writing directly into the queue means the preconditions are re-implemented per producer and drift apart, which is how an unclassified or stale row reaches a worker. One transaction makes the preconditions a property of the state rather than of whoever wrote it.
