# SR-144 — Durable final-review request

**Requirement.** A request for a full-spine human review shall persist as a tracked event that survives relaunch, surfaces in the owner decision view, and closes only on a recorded human decision.

**Acceptance criteria.** A recorded request survives a process restart, appears in the generated owner decision view, blocks the declared checkpoint, and closes only when a human decision event references it; the persistent always-review policy produces the same block without a request event.

**Rationale.** A one-shot review ask held in memory or in a launcher flag disappears at the next relaunch, which is precisely when an unattended loop would proceed past it. Persisting the ask as an event keeps transient state out of the configuration file without creating a second configuration source.
