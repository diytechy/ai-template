# SR-116 — Generated status and run-state surfaces

**Requirement.** The integrator shall generate docs/status.md as a freshness-gated reference snapshot never written on a worker branch, and docs/run-state as a four-valued dispatcher outcome (RUNNING|NEEDS-HUMAN|BLOCKED|DONE).

**Acceptance criteria.** status.md regenerates only on the integration branch after an integration and fails its freshness gate when stale; run-state's four values derive from dispatcher state.

**Rationale.** Realizes SN-010 — an agent-authored status surface drifts from the state it reports and is trusted anyway, and a worker branch writing it makes the snapshot describe one lane instead of the project. Letting each worker append its own status was rejected: it produces a file that conflicts on every integration and reports no coherent whole.
