# SR-059 — Retire next-wi; generated status surface

**Requirement.** The delivered scaffold shall ship no hand-curated next-work or run-phase pointer surface — the status surface a session reads being generated and freshness-gated, never hand-copied.

**Acceptance criteria.** A fresh scaffold ships no next-wi/run-phase pointer and is parallel-by-default; no live instruction or executable surface reads, writes, validates, generates or links such a pointer; a build-out lane's phase resolves from its branch name with no pointer file; the status snapshot regenerates mechanically and its freshness is gated.

**Rationale.** Realizes SN-025 and SN-010 — the WI DAG, gate class, Priority and the scheduler are together the complete ordering contract, so a second hand-curated pointer is a rival source of truth that silently wins wherever it is still read. Leaving the file in place as a deprecated no-op was rejected: a surface that still parses is a surface something still reads.
