# SR-059 — Retire next-wi; generated status and run-state

**Requirement.** The dispatcher migration shall delete docs/next-wi and docs/run-phase outright (fresh scaffold and migrated repo) and remove every live dependency - coordinator selection, prompt scope, telemetry/session labels, rework precedence, BuildTier pins, the ;-batch behavior, gate-first/check logic, trajectory/dashboard projections, launcher/bootstrap/process/skill surfaces, and their tests/generated outputs - translating no former next-wi content into Priority or any scheduling state; root docs/status.md shall become an integrator-generated, freshness-gated reference snapshot never written on a worker branch, and docs/run-state a generated dispatcher outcome (RUNNING|NEEDS-HUMAN|BLOCKED|DONE).

**Acceptance criteria.** A fresh scaffold ships no next-wi/run-phase and parallel-by-default; no live instruction or executable surface reads/writes/validates/generates/links next-wi; status.md regenerates only on the integration branch after an integration; run-state's four values derive from dispatcher state; a build-out lane's phase resolves from its {phase}-{gate} branch with run-phase absent.

**Rationale.** Realizes SN-025 and SN-010 - the WI DAG plus gate class plus Priority plus the scheduler are the complete ordering contract, so the hand-curated pointer and its scattered dependencies must go, and status/run-state become generated (not agent-authored) surfaces that cannot silently rot (docs/specs/parallel-wi-dispatch.md 10).
