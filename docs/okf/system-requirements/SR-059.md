# SR-059 — Retire next-wi; generated status and run-state

**Requirement.** The dispatcher migration shall delete docs/next-wi and docs/run-phase outright (fresh scaffold and migrated repo) and remove every live dependency on them — coordinator selection, prompt scope, telemetry and session labels, rework precedence, BuildTier pins, the ;-batch behavior, gate-first logic, trajectory and dashboard projections, launcher, bootstrap, process and skill surfaces, and their tests and generated outputs — translating no former next-wi content into Priority or any scheduling state.

**Acceptance criteria.** A fresh scaffold ships no next-wi/run-phase and is parallel-by-default; no live instruction or executable surface reads, writes, validates, generates or links next-wi; a build-out lane's phase resolves from its {phase}-{gate} branch with run-phase absent.

**Rationale.** Realizes SN-025 and SN-010 — the WI DAG, gate class, Priority and the scheduler are together the complete ordering contract, so a second hand-curated pointer is a rival source of truth that silently wins wherever it is still read. Leaving the file in place as a deprecated no-op was rejected: a surface that still parses is a surface something still reads.
