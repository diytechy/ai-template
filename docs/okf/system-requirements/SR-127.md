# SR-127 — Requirement form: one testable obligation

**Requirement.** trace.py shall fail under --strict when a non-Draft requirement repeats its obligation keyword, uses a different modal in normative text, states an obligation with no actor, or uses an unfalsifiable or open-ended term.

**Acceptance criteria.** A second `shall`, a non-`shall` modal, an actorless `shall be <participle>`, an unfalsifiable term, an open-ended escape clause, or a `shall` in an LLR Detail exits 1 under --strict; a Draft row, a zero-`shall` row, `must` as a project's own obligation keyword, and a multi-clause AcceptanceCriteria do not.

**Rationale.** Realizes SN-004 — when one row carries two obligations and only one holds, no id reports the failure, so the gate passes on a partially-met requirement. Undecidable wording fails differently and worse: an unfalsifiable adjective cannot be tested, so the row is signed on impression. Each rule is a LEXICAL proxy for a semantic property and is scoped to what it can actually decide — counting the obligation keyword catches the shape that recurred here and does not claim to find every multi-obligation row. A semantic check was rejected as out of reach for a stdlib checker, and a readability score was rejected as a proxy for the wrong property: it measures prose complexity, not whether a reader can tell what is binding.
