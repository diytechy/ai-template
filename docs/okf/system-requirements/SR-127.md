# SR-127 — Requirement form: one testable obligation

**Requirement.** trace.py shall fail under --strict when a non-Draft requirement states more than one obligation or states it in undecidable terms.

**Acceptance criteria.** A second `shall`, a non-`shall` modal, an actorless `shall be <participle>`, an unfalsifiable term, an open-ended escape clause, or a `shall` in an LLR Detail exits 1 under --strict; a Draft row, a zero-`shall` row, `must` as a project's own obligation keyword, and a multi-clause AcceptanceCriteria do not.

**Rationale.** Realizes SN-004 — when one row carries two obligations and only one holds, no id reports the failure, so the gate passes on a partially-met requirement. Undecidable wording fails differently and worse: an unfalsifiable adjective cannot be tested, so the row is signed on impression. A readability score was rejected — it is a proxy, and this defect class is categorical, so the rule can be exact instead of approximate.
