# IF-110 — Interface

**Contract.** reads the requirement spine through the CARRIER (IF-102) instead of csv.DictReader, so the LLR/TC rows the unified mint reads to place a new row answers whichever of TOML/CSV is live and the rows arrive under today's column names either way. The mint reads the spine to decide what already exists. It also WRITES Status back (the Modified->Verified flip), so this seam is the read half of a read-modify-write and the carrier must answer both consistently.
