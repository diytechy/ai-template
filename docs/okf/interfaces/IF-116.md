# IF-116 — Interface

**Contract.** reads the id watermark so BOTH of this module's mints count from the RECORD, not from the live tree (the IF-101 seam, second consumer): read_watermark(root) -> {space: int}, raising on an absent or malformed mark rather than degrading to zero, and bump_watermark(root) to raise the marks in the same act that writes the artifacts. allocate_round_dir mints max(live DP directories, DP mark) + 1; file_selected_wis mints max(live spec ids over both homes, WI mark) + 1. Shared rather than duplicated for IF-101's reason - the mint and the checker must agree on what an id is - and the bump sits on the CALLER's side by construction: bump_watermark reads the live tree, so it runs only after the directory or the specs exist, or it records a number nothing holds.
