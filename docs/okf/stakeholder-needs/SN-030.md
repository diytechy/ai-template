# SN-030 — The unattended loop's priority order is ratified prose the tests pin, not an eme

**Need.** The unattended loop's priority order is ratified prose the tests pin, not an emergent property of the tick loop — and the loop names the contradictions its registries already state.

**Why it matters.** A walk-away loop's order of business is a policy, and a policy nobody wrote down is whatever the code happens to do. Two orderings in particular are judgements: an unjudged claim (a lane's partial close, an amendment that may have moved meaning) must be disposed BEFORE anything builds on the premise it might overturn, because a ratification is the one act this loop cannot cheaply take back. And a work item recorded done whose test case is not green is a contradiction the registries state plainly and nothing was reading — the sort of thing a human notices and a loop must be told to notice.

**Acceptance intent.** Admission prefers adjudication rows over all other ready work, as a stable partition at admission rather than by renumbering the ruled rank table; the idle census names a TC left red under a CLOSED implementation as its own class and routes it to an adjudicator with a tier estimated from measured breadth, never a default mint; two OPEN work items that overlap (near-identical titles, a shared requirement, one spec of record) are made VISIBLE, warn-only, because overlap is frequently correct and a checker that cannot tell a legitimate split from a duplicate must not block on the difference.
