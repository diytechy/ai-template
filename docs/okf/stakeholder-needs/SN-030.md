# SN-030 — One deterministic planner decides what the unattended loop does next, in a decla

**Need.** One deterministic planner decides what the unattended loop does next, in a declared order, and a red bar becomes owned work rather than a stop.

**Why it matters.** Two readers of one tree must dispatch the same work or an unattended run cannot be trusted or reproduced; ordering the decision in ambient code reaches different answers on identical trees. And a claimed-complete branch whose harness is red currently stops the loop, which leaves a real defect undiagnosed and unowned instead of turning it into scheduled work.

**Acceptance intent.** A pure planner returns one typed decision per cycle in the declared precedence — outcome adjudication, prose adjudication, queue vetting, human checkpoints, current-stage spine work, other ready work, red-bar remediation — touching nothing; a spine batch admits as one exclusive unit partitioned by graph connectivity; and a red declared bar persists one failure event keyed by the failure itself and mints exactly one remediation draft.
