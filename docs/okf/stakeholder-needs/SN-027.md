# SN-027 — A team gets more than one piece of ready work moving at once: ready work fans ou

**Need.** A team gets more than one piece of ready work moving at once: ready work fans out across bounded parallel lanes, while mutation of the integration branch stays serialized and gated.

**Why it matters.** Admitted concurrency, structurally justified: the WI DAG already encodes what may proceed, so a frontier bounded to one lane idles ready work for no reason; and parallel *integration* is precisely how a reviewed process ships an unreviewed tree — so fan-out is admitted only because it narrows back to a single serialized, gated seam before anything lands. REWORDED 2026-08-17 (C-PRF-1, hat.PERFORMANCE; sitting-3 §0.4 item 8 ruling): the cell led with "Throughput:" — a quantified-speedup claim no instrument here measures, flagged unfalsifiable as written by three independent derivations. The structural claim is the honest justification; the observability the speed claim lacked is SR-177's utilisation report, minted the same day.

**Acceptance intent.** A launch with independent ready WIs runs up to the configured worker ceiling (default 2) concurrently in isolated worktrees; every finished branch lands through one serial, fail-closed integrator that runs the declared bar on the composed tree; --jobs 1 preserves the serial semantic; a declared pause stops claiming and drains what is already in flight; a crash at any lifecycle boundary recovers from Git history alone, without double-assignment or half-integrated authoritative state.
