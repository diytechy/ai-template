# SN-040 — Scope: template (adopters + this repo). A stakeholder can obtain a repeatable ex

**Need.** Scope: template (adopters + this repo). A stakeholder can obtain a repeatable explanation for why the system was divided into its chosen components, based on the system's declared inputs, outputs and internal signal trade-offs rather than an unrecorded model judgment.

**Why it matters.** A component breakdown invented free-form by a model (or a person) leaves no record of the alternatives weighed, so the next reviser cannot tell load-bearing boundaries from accidents. Deriving the partition from the system's own declared inputs and outputs, against a declared objective, leaves evidence the choice can be re-examined against.

**Acceptance intent.** A decomposition run records the candidate partitions considered, the declared objective and constraints they were scored against, the selected partition, and a comparison a reviewer can reproduce; the human names the components and rules the final choice; the record is kept with the architecture, not in session prose.
