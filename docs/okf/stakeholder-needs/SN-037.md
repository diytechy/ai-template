# SN-037 — Scope: template (adopters + this repo). A stakeholder can see where each promise

**Need.** Scope: template (adopters + this repo). A stakeholder can see where each promised system behavior enters or leaves the system, and the architecture changes with those promises instead of being invented afterward.

**Why it matters.** A requirement whose inputs and outputs cannot be located at a declared system boundary cannot be verified or assigned to a responsible component. Updating requirements and architecture separately also leaves periods in which each tells a different story.

**Acceptance intent.** Every system-requirement input and output references a declared interface; every referenced interface identifies its boundary endpoints and whether its signal is discrete or variable; every declared component-boundary crossing has an interface row; unresolved references, uncovered crossings and incompatible signal types are mechanical findings. A reviewed change that alters one side of the requirement/interface relationship must include or explicitly justify the corresponding change on the other side.
