# SN-028 — One validated file controls how the process behaves — harness, automation policy

**Need.** One validated file controls how the process behaves — harness, automation policy, model routing and prompt selection — and a kit upgrade never overwrites it.

**Why it matters.** Behaviour is currently spread across a toolchain file, five one-value policy files, two routing files, three launchers, environment variables and CLI maps, so nobody can answer "what will this repo do?" from one place, and each surface carries its own parse convention that can disagree with the others. A single validated authority also makes an upgrade safe: the adopter's answers are theirs, and the kit's defaults are the kit's.

**Acceptance intent.** docs/config.toml is the only editable source for behaviour; a strict loader refuses an unknown key, a wrong type or an unsupported schema version by name; a detector proves no retired source still affects behaviour, and a tree carrying both refuses rather than picking a precedence; the kit ships a template plus a converter, bootstrap and re-sync run the converter automatically, and an adopter-edited file survives a re-sync byte-for-byte.
