# LLR-141 — Work-branch lane signal + freshness skip

**Detail.** On a claimed work branch the _TRUNK_FRESHNESS_STEPS set SKIPs with a §5.2 notice, exit code untouched; the plan listing still names every step. The claim signal answers in two stages - docs/work/active/<branch>/ on disk (the fast path), else the branch's own committed history (git log -1 -- docs/work/active/<branch>) - so the closing commit that archives the claim, and every commit after it, keep the skip. No git, a failing git, or an empty answer all read as the trunk lane: a false work-branch positive would switch the freshness gates off on the one branch that owns regenerating them.

**Rationale.** A false work-branch positive would relax the trunk's freshness bar, so every ambiguity resolves toward the trunk lane.
