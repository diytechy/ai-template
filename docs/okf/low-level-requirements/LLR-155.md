# LLR-155 — The config layer: one reader, checked shape, one comparison

**Detail.** `process_config` parses `docs/process.toml` once; `declared_policy` reads a dial through it with the legacy file as fallback; `process_shape_findings` refuses every line shape the hooks' sh cannot follow; `config_conflicts` returns refusal STRINGS (never raises — `dispatch.run` sits in the tick loop's caller, where an exception would rewrite an exit-code contract) covering the double-declaration, the wrong type and the out-of-range value; `ratification_level` + `human_holds` are the ordinal and the ONE comparison every consumer makes.

**Rationale.** Five entry points read policy without passing through `agent_loop.main`, so the refusal has to live where the value is read. The comparison is stated once for the same reason the shape is checked: the failure modes here are silent, and a rule restated at four call sites is four chances to state it differently.
