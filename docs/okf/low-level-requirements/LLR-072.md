# LLR-072 — Two-hat planner pair + runtime-nonresponse fallback

**Detail.** Pure two-hat planner routing (WI-196, DP-001 plan P3; no session launching - seams stay IF-044/IF-045, no file I/O beyond agent_route's reads). planner_pair routes the two planner hats via select(): the second hat prefers a different Family than the first, yielding PAIR_TWO_FAMILY (not degraded) when the enabled pool allows; when only one family is available (or every different-family row is cooling) it degrades AT SELECTION to two fresh same-family sessions with the recorded PAIR_SINGLE_FAMILY reason, and an empty pool yields PAIR_NO_MODEL. planner_fallback is the entry the coordinator calls when a routed family proves nonresponsive at launch after failure_action()'s retries are exhausted: it HARD-excludes the failed family (select()'s exclude_families only deprioritizes) and returns two fresh same-family sessions from the responding family with the degraded-availability reason PAIR_RUNTIME_FALLBACK, or PAIR_NO_RESPONDER when nothing else responds. PlannerSession carries object-identity freshness (the returned picks are new objects, never the failed one reused, distinct from each other even when sharing a model_id) and PlannerPair surfaces the machine-readable reason code + detail as data (no printed side effects) for round artifacts/telemetry.
