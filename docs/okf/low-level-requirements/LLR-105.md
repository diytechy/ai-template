# LLR-105 — Interactive-control contrast in both themes (T5 core)

**Detail.** The MECHANIZED core of usability anchor T5 (docs/rubrics/dashboard-usability.md), split out of LLR-055 under the (f) decomposition ruling and delivered (116/117-CRITIQUE corroborated, 118-CRITIQUE MAJOR, 119-CRITIQUE MAJOR): EVERY control painted over a node's own fill (the interactive controls T5 extends A4's arithmetic to) clears the WCAG 3:1 UI-boundary floor against EVERY node fill declared in STATUS_FILL/TIER_FILL/OKF_TYPE_FILL/SW_NODE_FILL/PHASE_ACCENTS, in BOTH themes -- computed per-fill (white or near-black, whichever contrasts more), not a single fixed hue that vanishes on whichever fill happens to match it (the phase-3/--accent collision measured 1.00:1). WIDENED from the descend/hover/focus ring ALONE to the set of such controls, because the ring was fixed while the containment/descend ARROW (.cedge shaft + its marker head), drawn inside the same block over the same fill and the very control a reader must find to descend a tier, kept the fixed var(--accent) and measured 1.06:1 light / 1.99:1 dark on the phase-1 #0369a1 -- the identical failure mode one control over. The arrow now derives from the same per-fill --ring token; its marker head takes a per-ink marker because marker content is rendered from the defs tree and cannot see the referencing node's custom properties (a constraint recorded in _arrow_markers), and RING_INKS is the closed ink set that makes that one-marker-per-ink emission total. SCOPE: a control's contrast against its host fill, arithmetic like the sibling A4 tests. Whether the affordance otherwise reads as inviting stays perceptual under LLR-055/TC-055.
