# LLR-178 — The mirror invariant: the record is only ever written by copying live

**Detail.** MINTED 2026-08-18 by the SR-140 split: SR-179 is the anti-laundering half, and its mechanism is a sibling of LLR-158's comparison basis rather than a part of LLR-173's record. staged_snapshot_findings(root, base, head) is a whole-commit rule, not a per-row one: in ANY commit that touches the last_approved record, every touched file must be byte-identical to its live counterpart AS OF THAT SAME COMMIT. One comparison is what makes a hand edit, a partial copy and a copy-then-amend-live all fail, and it is why no separate co-mutation guard is owed - the abandoned on-row anchor design would have needed one. It reads the INDEX and the commit-ish alike (matching _spine_revs' prefix contract), so it fires at the hook where the act happens rather than after the fact. THE DELETION ARM is the half a first reading misses and is deliberately asymmetric: _snapshot_survives is the two-line tree probe that separates a registry removed WHILE THE REST OF THE RECORD STANDS (refused - deleting the copy deletes exactly the evidence the unanchored rule reads, which is cheaper laundering than forging one) from the record going away WHOLE (silent - retirement and a wholesale replacement are both legitimate, and a rule that fired on them would make its own design undeployable). The prose README inside the record is exempt: it is not a recorded registry, and holding it to a live counterpart that does not exist would red every signing. It joins the failure set at check_trajectory's main aggregation, so unlike LLR-173's advisory unanchored arm this one is a real gate today.

**Rationale.** The record is worthless if anything but a copy can write it, and "only a copy writes it" is a claim no per-row check can make - a per-row rule sees the row it is given and never the commit that wrote it. Placing the invariant on the COMMIT is what converts a convention into a decidable property. It lives in check_trajectory rather than in baseline_snapshot because the writer must not also be the judge of its own writes: the module that copies has every reason to believe its copy is faithful, and the guard exists for the cases where it is not.
