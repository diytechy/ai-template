# LLR-161 — The close ritual and the disposition it owes

**Detail.** `close_partial` writes the report FIRST (it is the event's identity), refuses when one already exists, and restores EVERY report this call wrote on any refusal — so a multi-spec lane cannot half-close. `intake._close_drafts` titles the disposition on the report PATH and nothing else, and says so LOUDLY when a terminal spec has no report rather than minting zero rows quietly.

**Rationale.** The path is the only token in the event's identity that cannot move. An earlier cut folded the report's `claimed_outcome` in as well, which re-read a MUTABLE field on every sweep, so one edit minted a second disposition for the same close — the starvation class returning through a new proxy.
