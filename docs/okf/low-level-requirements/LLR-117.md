# LLR-117 — Theme-lock: one theme mechanism and no mixed-family surface/ink pair (T6 core)

**Detail.** The mechanized core of usability anchor T6 (docs/rubrics/dashboard-usability.md). The measurable content is FAMILY PAIRING, not the absence of literals: a fixed status swatch carrying fixed white ink is theme-locked CORRECTLY, since neither side flips. A page inverts mid-view in exactly two ways and this row forbids both. (1) A SECOND THEME MECHANISM below :root — the document declares exactly one prefers-color-scheme block, targeting :root, and one color-scheme, also at :root. (2) A MIXED PAIR — a theme-varying ink on a theme-invariant surface, or the reverse. The two families are DERIVED from the emitted document (the dark block's override set IS the definition of theme-varying), never hand-listed, and the dark block may not override a token :root never declares. Applied to CSS rules declaring both a background and an ink, to every emitted SVG node pairing an inline rect fill with an inline text fill, and to CSS-declared SVG text fills paired against the family their host nodes actually paint in. SCOPE and its deliberate narrowings: --ring is excluded because it is stamped FROM the host fill (LLR-105 owns its floor); the JS-composed badge idiom pairs background and ink at runtime from the invariant vocabulary, where LLR-114's arithmetic owns it; and the page CSS has exactly ONE rule declaring a classifiable background AND ink today (body), so that half is prospective while the sweep's weight sits on the node and text-fill halves. Whether the chosen palettes are PLEASANT stays perceptual.

**Rationale.** A per-component theme override is a seam the reader crosses while scrolling, and a mixed pair reads correctly in the theme it was authored in and inverts in the other — both are invisible to the author working in one theme. Forbidding colour LITERALS was the obvious rule and is the wrong one: it fails a correct fixed-on-fixed pairing and passes a varying-on-invariant one, so it would flag the safe case and miss the defect. Deriving the families from the emitted document rather than listing them means a new token joins a family by existing.
