# LLR-047 — Run capability menu reader

**Detail.** load_capabilities parses the docs/stack.ini [run] section (configparser, interpolation=None, case-preserving optionxform; declaration order kept; a name.desc row attaches to its command and an orphan or empty-value command is dropped) into an ordered (name, command, desc) list; --list prints name<TAB>desc per row; direct(name) launches by exact-match name (exit 2 on an unknown name) and launch() runs the shell line via subprocess shell=True, passing the child exit code straight through; interactive_menu prints the numbered menu, reads a pick from stdin, and returns EOF-safe without hanging; an absent or empty [run] prints guidance and exits 1. The run.* launchers are thin delegates forwarding their args to run_menu.py.

**Rationale.** The command being run is the user's own declared line, so shell=True is the same trust boundary the declaration already establishes rather than a new one. EOF-safety is load-bearing: a menu that blocks on a closed stdin turns an unattended invocation into a hang, which is the failure this launcher exists to avoid.

**Code.** `project-trajectory/scripts/run_menu.py` — `load_capabilities/interactive_menu/direct/launch`
