# LLR-159 — Admission order and the red-TC census

**Detail.** `_judgement_first` is a STABLE PARTITION over the frontier, applied inside `_admission` before the surface/dispatch split so it can never move work past a human-held stop. `red_tc_census` rides the existing finding-string seam with a distinct prefix; `_red_tc_line` and `parse_red_tc` sit adjacent because the grammar is a contract between two modules, and `intake` routes on the parser rather than re-splitting prose. red_tc_census names, as its own class, a test case that is not green while every requirement it verifies is cited by a work item recorded done — Verified, Draft and Modified test cases are exempt, an open, partial or cancelled citer makes nothing red, and a test case verifying a mix of claimed and unclaimed targets is not red; each named line routes to an adjudication row whose suggested tier is estimated from measured breadth, never defaulted; the census line's grammar has exactly one reader (parse_red_tc).

**Rationale.** The alternative to the partition — renumbering `schedule._KIND_RANK` — would change ordering for every downstream repo for a rung that belongs to admission. The alternative to the parser is prose carrying control flow, which is the exact defect the typed `suggested_tier` field replaced.
