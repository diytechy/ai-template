# LLR-164 — The generated prompt catalogue and its freshness gate

**Detail.** `render` is PURE — it takes no arguments and reads only the shipped templates — so `--check` and the write path cannot disagree about what "current" means. `--check` compares on NORMALIZED line endings, for the same reason the digest is taken that way: a CRLF checkout is not a stale catalogue. The file is declared in `docs/stack.ini [generated]` as kind `promptcatalog`, so the trunk lane owns it and a work branch never commits it.

**Rationale.** A generated artifact nobody re-generates is a document that lies, and a lying catalogue is worse than none: it invites the operator to conclude the wrong thing about the session they are debugging. Same contract `gen_arch_map --check` and `gen_skills_index --check` hold.
