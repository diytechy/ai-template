# LLR-101 — Non-pruning SVG container roles (A2 core)

**Detail.** The MECHANIZED core of accessibility anchor A2 (docs/rubrics/dashboard-accessibility.md), split out of LLR-053 under the (f) decomposition ruling and delivered: no emitted <svg> declares the CHILDREN-PRESENTATIONAL role=img over a FOCUSABLE descendant, and any svg that does declare role=img carries its own accessible name (aria-label, or a first-direct-child <title> - per SVG-AAM a <title> nested in a <g> names the <g>, not the svg). Focusable means tabindex in any quoting OR a native SVG <a href>, which is tab-ordered without a tabindex; a tabindex-only predicate wrongly passed the loops diagram (9 linked stage cards) and was caught by adversarial review, not by the first test. The role is chosen from the emitted BODY by _svg_role, so a future emitter adding focusable nodes cannot silently reintroduce the conflict. SCOPE - and no wider: the container-role invariant as PROVEN by TC-104, i.e. over the artifact this repo ships plus the tiered fixture, plus the predicate's own unit cases. It is NOT a proof over every reachable emitter configuration: an emitter no rendered artifact exercises is unguarded. Name QUALITY is no longer perceptual: LLR-108/TC-113 assert every focusable element and role=img graphic HAS a name, that it is never a bare registry id, and that navigation landmarks are distinct.
