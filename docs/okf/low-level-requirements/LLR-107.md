# LLR-107 — One interaction idiom per node role (U4 core)

**Detail.** The MECHANIZED core of uniformity anchor U4 (docs/rubrics/dashboard-uniformity.md), split out of LLR-054 under the (f) decomposition ruling. Two node roles exist and each is spelled ONE way in every emitter that renders it: an IDENTIFIED node (icicle .cell, flat-DAG .wi, knowledge .knode) advertises its registry id through `data-id`; a DETAIL-BEARING drill node (.block, in both the When and How-SW drills) advertises its detail-map key through `data-node`; and a node of either role is made focusable the same way, `tabindex="0"` on the group. Neither role ever carries the other's attribute, so one node is never addressed two ways. SCOPE (the narrowing the ruling accepted explicitly): ATTRIBUTE parity, not runtime behaviour parity - proving that two emitters' handlers BEHAVE alike needs a browser harness, so what is proven here is that they are wired through one vocabulary.
