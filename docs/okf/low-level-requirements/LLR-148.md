# LLR-148 — Derived next phase as an output mode

**Detail.** --next-phase prints max(Phase over non-draft spine rows) + 1 - the basis line's phase=N derivation exposed as an output mode (no second parse, docs/gate never written), bare so the intake mint helper and any agent can int() the answer when a confirmed scope change opens a new phase; a Draft row's phase is not yet scope and never bumps the answer; an unphased spine is the implicit foundation (1), so it prints 2. The boundary it serves is ruled (owner 2026-08-01): a phase increments on an adjudication-confirmed scope change or a ratified draft-SN batch, never on the raw derived-gate drop.

**Rationale.** One derived call keeps the boundary number mechanical - hand-picked numbers drift, and a spurious Modified window must not burn a phase number (the counterexample: 19 traced cells once flipped 11 SRs with no scope moved).
