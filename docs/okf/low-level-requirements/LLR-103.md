# LLR-103 — Uniform node/edge/legend/highlight styling (U3 core)

**Detail.** The mechanized core of uniformity anchor U3 (docs/rubrics/dashboard-uniformity.md): the hover/focus highlight ring resolves to ONE shared per-fill `--ring` custom property across every SVG emitter (drill/icicle/flat-DAG/knowledge) rather than a different hue per emitter, and the When tab's phase-accent key renders through the SAME `.legend`/`<i>` component every other legend in the document uses rather than a bespoke inline-chip idiom. SCOPE: highlight-token equality and legend-component equality, asserted structurally against the emitted CSS and markup. Spacing and exact visual weight belong to LLR-110/TC-115.

**Rationale.** A highlight that changes hue between views teaches the reader a different interaction language per tab, and a legend built twice drifts in one copy while the other stays right. Per-emitter hues were the shipped state (an accent token in the drill views, a hardcoded amber elsewhere) and were rejected precisely because nothing held them equal: sharing one token means a change lands everywhere or nowhere.
