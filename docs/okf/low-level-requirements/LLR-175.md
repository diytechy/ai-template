# LLR-175 — Consecutive no-progress stall guard

**Detail.** Declared progress is a moved git HEAD: note_session resets the stall counter on a commit and increments it otherwise, so the window is consecutive and interleaved progress is never ended by the limit; a throttled (WAITING) session bypasses the counter entirely, and a timed-out one counts (it produced no commit). At --stall-limit consecutive no-commit sessions (a declared flag, default 3) the loop stops with EXIT_STALL (4) - its own exit code, distinct from success and from the error/config exits - under a STALL banner pointing at the latest iteration log. Which banner (the all-ERROR agent-unavailable wording vs the generic work stall) is stall_verdict's fork and LLR-028's home under SR-028; this row owns the counter, the declared limit and the distinct exit.

**Rationale.** The counter reads committed evidence (HEAD movement), not session prose, so a session cannot talk its way out of the guard - and the reset-on-commit is what keeps the limit a stall detector rather than a slow-progress killer.
