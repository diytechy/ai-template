# LLR-158 — The one comparison basis an amendment is measured by

**Detail.** RE-POINTED 2026-08-15 (log 2026-08-15h) onto the mechanism that SURVIVED. This row used to describe a DIGEST engine (normative_text/sn_normative_text/digest/current_digests); the last_approved snapshot deleted it whole, because an approval that records what it blessed by COPYING the registries needs no canonical text to hash, no separator that cannot occur in a cell and no second exclusion list. The obligation is unchanged and is discharged by split_changed_cells(csv_path, id_col, head, row) -> {"ratified": {cell: (before, after)}, "traced": {...}}: the id column and Status are excluded STRUCTURALLY - the id is the join key rather than content, and folding Status in would make every flip read as an amendment and every amendment invisible behind its own flip - and the remainder is split by spine_cell_class, the SAME classifier the amend-without-flip guard reads, so the two can never disagree about what normative means. It is PUBLIC for exactly one reason: baseline_snapshot.is_drifted reads it as the drift basis (LLR-173), so the snapshot comparison and the staged-amendment guard are one rule with one home rather than two rules that agree until they do not. _RATIFIED_TEXT names the two Status values whose row TEXT is ratified (Verified, Planned) and requires the SAME one on both sides, so prose rewritten under a Planned row is no longer invisible. It returns the before/after PAIRS a brief has to render anyway, which is why it replaced a hash rather than being wrapped by one. Needs are covered by the whole-file copy rather than by a per-need projection: the three need tables have different shapes, and a projection would have hashed the garbling.

**Rationale.** A ledger that does not parse is not an anchor at all, and every reader then falls back silently to the git-history derivation it replaced. The copy-based baseline removes that failure mode rather than hardening it: the record is a file a human can open and `git diff`. What had to be kept is the DEFINITION of a change - which cells count, and which of them are ratified rather than merely traced - and that is one function, cited by both readers, rather than a hash whose inputs each reader re-derives.
