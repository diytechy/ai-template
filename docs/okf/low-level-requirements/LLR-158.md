# LLR-158 — The digest that anchors an attestation

**Detail.** normative_text() joins a row's RATIFIED cells in header order with a unit separator, reusing spine_cell_class rather than a second list so the digest and the amend-without-flip warn can never disagree about what normative means; the id and Status are excluded because neither is content - the id is the key the digest is looked up BY, and folding Status in would make every flip look like an amendment and every amendment invisible behind its own flip. sn_normative_text() takes the RAW table line for a stakeholder need rather than a parsed projection, because the three need tables have different shapes and a projection would hash the garbling. current_digests() is the one reader that joins both halves. The WRITER and the co-mutation guard are not here yet: which cells hold the anchor depends on the registry carrier, ruled separately (OI-12).

**Rationale.** Integrity is hard because a ledger that does not parse is not an anchor at all and every reader silently falls back to the git-history derivation it replaces. Removal was the gap: it silenced all three rungs at once, so the strongest form of rewriting was the one form the guard could not see.
