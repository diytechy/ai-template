# LLR-134 — Requirement form rules

**Detail.** form_findings applies six rules — one obligation per requirement, no non-obligation modal, no actorless passive, no unfalsifiable term, no open-ended clause, no obligation keyword in an LLR Detail — skipping Draft rows, and joins the --strict failure set via exit_code. The negative set holds: a Draft row, a zero-obligation row, a project's own declared alternate obligation keyword, and a multi-clause AcceptanceCriteria are not findings — stated keyword-free here deliberately, since the rule cannot distinguish a mention from a use.

**Rationale.** A row carrying two obligations reports neither when one fails, and undecidable wording is signed on impression rather than evidence — that is the failure all six rules exist to prevent. Draft is skipped because a Draft row is exempt from the child-completeness rules elsewhere in this harness and is by convention the state a requirement occupies while still being written, so an unfinished acceptance criterion is expected there rather than defective; flagging it would make the state unusable for the drafting it exists to allow. This cell says "obligation keyword" rather than quoting the keyword itself because the rule cannot distinguish a mention from a use, and an exemption a checker cannot see is one an author can reach for.
