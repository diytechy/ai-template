# LLR-170 — Need-form checker

**Detail.** Reads the needs registry through spine_carrier.load_needs (either carrier answers; an unreadable registry REFUSES loudly rather than scanning as empty), and a registry that is PRESENT but yields zero scannable need cells - an empty file, or real rows with no need field - is reported VACUOUS rather than clean, while an absent registry stays the pre-scaffold clean skip and a -000-only scaffold registry stays a blank form (REVIEW-A round 1 drove the hole: at DevBar-Reqs an emptied registry hard-failed nothing else in the harness). The three token classes are data (CLASSES), labelled with SN-033's own vocabulary so a finding names the class the acceptance names. Two scope decisions are deliberate and documented in the docstring: SN-### is NOT a process citation (the SN registry is the stakeholder's own document, so a need pointing at a sibling need keeps the reader at the stakeholder tier - the live SN-025 case), and a single-slash, dot-free token is a path only when it RESOLVES in the scanned tree (docs/archive names a real directory and reports; English either/or pairs like subjective/perceptual resolve to nothing and stay exempt - review round 1 narrowed the original blanket exemption). URL spans - scheme:// and scheme-less www. forms alike - are suppressed whole, so a path-shaped tail inside an external address never reports under any class; the span stops at prose delimiters (comma/semicolon) and the www. form requires a multi-label host, so a genuine token abutting a URL and a local www.assets/logo.png both still report (round 3); a sentence-final token's trailing full stop is stripped before the phrase is judged or reported, so its reviewed exception matches (round 2). One finding per token: a later class re-matching inside an already-reported span is the same phrase to rewrite. The exception list (docs/need-form-allow) requires the ' — <reason>' separator per entry, the literal em-dash with spaces (ALLOW_SEP) - a line authored with a plain hyphen, or with no separator at all, declares nothing, so a malformed entry can only ever fail LOUD, never silence a finding. Wired as check.py's need-form step at every bar with NO --strict promotion, deliberately unlike check_vocab's severity ladder: promotion is an owner ruling, and the wiring says so.
