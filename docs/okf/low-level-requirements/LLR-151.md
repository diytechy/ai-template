# LLR-151 — Dispatch-lock claim rung + the spine batch claim

**Detail.** The §A4.1 authority flip's integrator half (docs/concurrency-v2.md §A4.1): _claim_refusal's safety_class != ordinary arm is DELETED (admission is the dispatcher's decision) and the claim REQUIRES the dispatch lock (agent_common.dispatch_lock_path, out/agent-loop.lock - the lock a live dispatcher holds for its process lifetime), acquired at ONE site (_dispatch_lock, mirroring _slot's one-site discipline for the merge slot's own lock) with the ladder run before it so the clean-trunk rung never refuses over the lock's own file: a hand claim on an idle station works, a hand claim during live lanes is unrepresentable, and the dispatcher's in-process claim passes dispatch_lock_held=True. claim/_claim_refusal/_abandoned_claim/_claim_delta are batch-aware: a spine batch is ONE claim commit moving every batched spec (subject joins the ids; the single-WI subject stays byte-identical), and integrate() takes an optional branches= restriction so the dispatcher merges each lane's branch as its own refresh completes.

**Rationale.** A constraint instead of a check: the state the old refusal guarded against (a claim written beside live lanes) is now unrepresentable, and the batch makes N spine changes cost one re-attest window (§A4).
