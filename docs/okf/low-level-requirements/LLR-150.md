# LLR-150 — Lane mechanics: worktree, worker subprocess, §A2 refresh subprocess

**Detail.** One lane's mechanics extracted from the dispatcher (docs/concurrency-v2.md §A4.2): ensure the lane worktree (integrate.lane_worktree, the one home both the worker and the refresh agree on), build the worker argv with the plain launch's session dials forwarded explicitly, launch the worker subprocess (spawn_worker non-blocking for the lane table; run_worker its blocking form and the default worker seam), and run the §A2 station refresh as the lane's OWN subprocess (spawn_refresh - the invoker's integrate.py refresh CLI under the harness interpreter) so N lanes' bars overlap instead of queueing at the dispatcher (§A4.3). Reports outcomes, decides none: the tree signal (specs moved out of active/<branch>/) plus exit codes are the whole protocol - no state file, no back-channel.

**Rationale.** The §A4.2 split keeps the deciding half (dispatch.py) apart from the running half, so at lanes=1 the dispatcher degenerates to the serial loop and the concurrency is a table size, not a second code path.

**Code.** `project-trajectory/scripts/lane.py` — `ensure_worktree/worker_argv/spawn_worker/run_worker/spawn_refresh`
