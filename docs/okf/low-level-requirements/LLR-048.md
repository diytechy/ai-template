# LLR-048 — Critique loop dispatch + lax-TC ratchet

**Detail.** In managed mode load_critique_srs reads the Verification=Critique SR ids (empty = vacuous); a committing build whose commit-subject WI ids (build_scope_srs, joined through work-items.csv SR-Refs) deliver a Critique SR schedules a CRITIQUE phase before the next build, independent of the review dial. The critic routes provider-heterogeneous (agent_route.select, prefer-different from the implementer, strong tier by default, tier-up-never-down) with critique_prompt = the embedded CRITIQUE_PROMPT (or a --prompt-map CRITIQUE FILE) slotting the redacted critique_brief (rubric text + SN/SR intent + the TC Parameters artifact recipe, never the implementer self-assessment) and {verdict}; the verdict lands at docs/reviews/NNN-CRITIQUE.md, parsed by score_reviews.parse_verdict. CHANGES-REQUESTED loops BUILD<->CRITIQUE preserving the per-scope round count until APPROVE or AGENT_CRITIQUE_MAX (default 3, env-overridable, min-1 fallback) trips agent_route.failure_action(gate-policy) - attended stops NEEDS-HUMAN, autonomous schedules a design-check. check_trajectory.critique_ratchet_findings adds the --staged warn when a Critique WI closes under a CHANGES-REQUESTED verdict with no TC/tests/docs-rubrics delta. Absent the enable-list or any Critique SR, byte-for-byte today's behavior.
