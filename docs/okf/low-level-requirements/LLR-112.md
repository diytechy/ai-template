# LLR-112 — Keyboard reachability of every wired control (A1 core)

**Detail.** The MECHANIZED core of accessibility anchor A1 (docs/rubrics/dashboard-accessibility.md), split out of LLR-053 under the WI-300 (f) ruling and delivered by WI-313: every element the emitted page WIRES an interaction to is keyboard-focusable. The wired set is DERIVED from the document's own querySelectorAll calls and then classified - a control selector (its matches receive per-element click/focus/dblclick/keydown listeners) may match only elements carrying tabindex=0 or natively tab-ordered (a button; an SVG a-with-href, the LLR-101 lesson), and each non-control selector records why its matches are not focus stops. A newly wired selector fails the owning test until classified, which is the closure the earlier per-element A1 tests (drill leaves, the WI-273 tablist) never gave. The rubric's 'sensible order' clause is narrowed to what is assertable, per the ruling's recorded recommendation: document order IS emission order, no positive tabindex may reorder the walk, and tabindex=-1 is legal only on the WI-273 roving tablist buttons. REWORKED same day after adversarial review refuted two claims: (1) the derivation read only single-quoted querySelectorAll, while the emitters already used querySelector('nav.crumbs') and closest('[role=tab]') - it now reads EVERY DOM-selecting API (querySelector/querySelectorAll/closest/matches, any quote style) and fails loudly on a non-literal selector argument, which the static read cannot classify; (2) the first pass dropped the ruling's KEY-HANDLER half claiming it needed a browser - it does not: a control-selector wiring loop that attaches click/dblclick must attach focus or keydown beside it, statically asserted, so mouse-only wiring cannot ship. SCOPE - and no wider: focusability, order-integrity and activation PAIRING of the wired set over the shipped artifact plus the seven-fixture emitter sweep. Runtime behaviour equivalence (that the focus handler DOES what the click handler does) is still not driven - that needs a browser harness - and whether the order FEELS sensible stays a reader-experience judgement, deliberately dropped. Runtime-created controls (the breadcrumb buttons) are native <button>s, keyboard-operable by construction, and out of the static walk's reach - a recorded limit.
