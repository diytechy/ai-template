# LLR-165 — The spine carrier converter (markdown + CSV -> TOML)

**Detail.** convert() walks the four tiers and returns (findings, written_paths), so the caller decides whether a lossy conversion writes. rows_to_toml emits `[<table>.<ID>]` with the id PREFIX RETAINED and BARE - TOML allows `-` in a bare key - because ~6,400 hand-authored citations use the prefixed token and a numeric key buys no type change (TOML keys are always strings, and `001` and `1` are two legal DIFFERENT keys, which is a near-miss the prefixed form does not have). cell_to_value types by COLUMN, not by guessing: REF_COLS become arrays, INT_COLS become ints, an empty cell becomes an absent key, and everything else stays a string - this is a carrier change, not a schema change. toml_scalar emits multi-line basic strings for anything long or newline-bearing (tomllib is read-only by design, so the kit emits its own, as it already does in wi_convert.toml_string and bootstrap.set_process_key). sn_to_toml keeps the edge-case tier's own lifecycle/scenario/expected fields as THEMSELVES and writes kind= from the heading, retiring section-as-state. compare() re-reads what was emitted and diffs it against an {id: {key: text}} projection built from either carrier, so ONE comparison serves both instead of a second copy that drifts.

**Rationale.** The round-trip check is the requirement, not a convenience - and a check that cannot fail would be the false green SN-008 forbids, which is why the loss detector is driven against real corruption classes rather than only against a clean run. Ref cells compare on the TOKEN LIST because the conversion re-joins them with the canonical separator and the original spacing was never part of the meaning; comparing raw text there would report a loss that is not one. The edge-case fold that traj_parse._sn_fields performs is a PRESENTATION rule the markdown table forced, so it stays in the exporters - baking it into the carrier would make the exporter's reading the only reading there is.
