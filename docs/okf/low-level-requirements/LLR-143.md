# LLR-143 — Plain-launch drive loop (claim->build->integrate)

**Detail.** The serial scheduling front end a plain agent_loop.py launch runs: each cycle re-derives the ready frontier (schedule.frontier), refuses on the tracked pause and on a dirty trunk at the cycle top, resumes a parked claimed branch else claims the next queued WI in build order (integrate.claim, branch name check-ref-format-validated), launches one worker session on the claimed branch's worktree (agent_loop.py --worktree --wi with the session dials forwarded), drains the serial merge queue (integrate.integrate) counting merges from finished_branches, and stops loudly on any composed refusal - stranded claims (active specs with no branch ref) refuse by name, NEEDS-HUMAN propagates as exit 7, a stall aborts, an empty frontier drains to exit 0. The session-config preflight applies only when work needs a worker. Never pushes.

**Rationale.** Ordering only, no new authority: every refusal stays where it already lives, and the driver is ~400 lines of composition against the 4,042-line dispatcher it replaces.
