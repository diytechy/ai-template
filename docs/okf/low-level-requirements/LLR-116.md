# LLR-116 — Viewport-fit by scale-to-fit with a legibility floor (T7 core)

**Detail.** The mechanized core of usability anchor T7 (docs/rubrics/dashboard-usability.md). Every emitted SVG (all three wrappers: _svg_wrap for dag/sw/know, the icicle panel, _drill_layer_svg) carries width:100% + max-width:<natural> + min-width:<natural x SHRINK_FLOOR> instead of a FIXED pixel width, so a diagram fills its container and scales down as the viewport narrows. SCOPE and its deliberate narrowing: a view whose natural width exceeds 390 / SHRINK_FLOOR still scrolls horizontally WITH its cue — the row's own fallback rule made mechanical. Closing that remainder needs a narrow-width re-layout (stacked columns), which is not this row.

**Rationale.** A fixed pixel width pins the rendered size whatever the container does, which is why every narrow view demanded sideways scroll and one graph clipped a component label mid-word. A viewBox alone cannot fix it — the fixed width still wins. The legibility floor exists because pure scale-to-fit TRADES this anchor for T4: a 900px graph squeezed into 390px shrinks a label past readable, so the floor stops the fix from creating the defect it is next to.

**Code.** `project-trajectory/scripts/traj_render.py` — `_svg_fit_style/SHRINK_FLOOR`
