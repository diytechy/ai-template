# LLR-166 — The spine carrier's one reader, and the dual-home refusal

**Detail.** PURE like trace_text (text in, rows out; no git, no argv) except resolve()'s existence check, because the dual-home refusal is the one rule that must not be duplicated. rows_from_toml presents rows under TODAY'S COLUMN NAMES via SPINE_COLUMN - the exact inverse of migrate_carrier.KEY - so the carrier change is data plus a loader rather than a sixteen-module rename; SPINE_TABLE is keyed on the ID COLUMN, not on a path, because a path carries a carrier suffix and therefore moves. An absent key stays absent rather than becoming "", and a decode error returns None rather than {}. resolve() RAISES when both carriers exist rather than picking by precedence, and load() raises on a carrier that exists and will not parse. carriers() returns BOTH paths so an applicability test spans the cutover.

**Rationale.** None-vs-{} and absent-vs-empty are the same defect twice: {} says the registry had no rows, which for a baseline read means re-bless everything with no diff and for a gate means nothing to check, so a carrier that cannot be read must be ABSENT rather than empty. The dual-home REFUSAL follows the rule bootstrap --migrate-config already applies to the policy dials: a precedence rule lets a half-finished migration keep working while quietly reading the stale half, so the conversion is never finished and nobody finds out. ONE HOME for the vocabulary is an owner ruling (2026-08-10, repo-lock D-6) amending F5: duplicating a vocabulary fails silently - the copy that has not learned a column returns a row missing that cell, which every consumer reads as "the cell is empty".
