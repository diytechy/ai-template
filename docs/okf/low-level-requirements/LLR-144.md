# LLR-144 — Terminal lane outcomes (handback + quarantine)

**Detail.** close_partial: commits the lane's work as-is, moves each claimed spec to the TERMINAL partial/ (nothing re-claims it, so nothing strands) and writes ONE IMMUTABLE per-close report under docs/handbacks/ naming the claimed outcome, the reason, the commit range and the keep/discard split. The report is the close EVENT's identity — immutable so it never moves, unique so a second close is a second document — which is what dissolved the starvation class five mutable-proxy dedup mechanisms died on. A second close is refused rather than overwriting the first, and any refusal restores every report the call wrote (schedule reads queued+blockref as blocked) and the driver cannot claim and return it forever. quarantine: the ruled red arm - reverts the product paths to the merge base and keeps the failing diff as a bar-inert .patch under docs/work/handback/, reading `git diff --name-status -z` as three-field RECORDS so a rename cannot revert the wrong path, checking every git return code, and restoring rather than reporting when a revert step fails. Both leave the branch finished, so integrate.branch_outcomes reads the outcome off the spec's DIRECTORY - complete/=merged, cancelled/=cancelled, any open folder=handback - and every lane ends in a merge.

**Rationale.** Making the outcome the directory leaves no fourth answer and no state file that could hold one; partial work lands in trunk where a future WI can find it instead of on a branch nobody will look at.
