# LLR-156 — The legacy converter, and the one word that is not a rename

**Detail.** `set_process_key` answers THREE states (`wrote`/`unchanged`/`missing`) and the write decides the delete; `add_if_missing` makes the write total. `gate-policy` gets its own arm because its single word expands to three dials, so it cannot be a one-key `LEGACY_CONFIG` row. `LEGACY_RATIFICATION` is F5-duplicated from `agent_common` (bootstrap imports no kit sibling — it must run standing on nothing but the kit directory it copies FROM) and pinned equal by `test_rule_sync`.

**Rationale.** This is duplicated POLICY, not plumbing: a migrator and a reader disagreeing about what `single-ratify` meant would let a repo scaffold with one posture and run with another — which is the shadowing defect the ordinal was introduced to remove, returning through the migration path.
