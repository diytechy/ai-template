## Method and limits

The map reads the five TOML carriers at the evidence revision. For each SN it follows `SR.sn_refs`, then `LLR.sr_refs`, then both direct and LLR-mediated `TC.verifies`. For each SR it performs the same downward join. A test family is a distinct `tests/test_*.py` path cited by the linked TCs’ `evidence` cells. This proves declared linkage only: a citation or import does not prove that the test exercises every acceptance clause. The interface appendix folds every `consumers` and `requestors` endpoint by `(owner, channel)` and keeps each IF data clause visible; it does not infer error semantics from an import.

Reproduction used the committed tree, insulating the census from concurrent workspace edits:

```sh

from pathlib import Path
import re, tomllib

    for sr in row.get("sr_refs", []):

linked_tc = set()
for sr in rows["SR"]:
    linked_tc |= tc_by_ref[sr]

        linked_tc |= tc_by_ref[llr]
surfaces, endpoints = set(), set()
for iid, row in rows["IF"].items():
    surfaces.add((row["owner"], row["channel"]))
    for consumer in row.get("consumers", []) + row.get("requestors", []):

print("linked", len(linked_llr), len(linked_tc))
print("interface", len(surfaces), len(endpoints))

for key in ("SN", "SR"):
```

### Proposed classes

- **core:** a cross-adopter outcome or always-on assurance needed for a working traced and gated process.
- **advanced capability:** behavior needed only when a declared optional layer is enabled, including autonomous agents, parallel lanes, perceptual review, dashboards, and opt-in measurements.
- **migration-only:** compatibility or conversion behavior needed only across a supported upgrade window.
- **retirement candidate:** a mechanism-specific or repo-internal promise whose underlying stakeholder property must be remapped before an owner may retire it.

Classification applies to responsibilities, not whole files: shared approval, privacy and source-reading behavior remains core even when a consumer belongs to an advanced layer. No current capability is disabled by this table.

All 27 approved needs remain either core or advanced. No stakeholder need is proposed for retirement. Four approved SRs are retirement candidates; that label preserves their current Approved status and creates a decision requirement rather than changing it.

Proposed totals are 19 core and 8 advanced SNs; 43 core, 27 advanced, 2 migration-only and 4 retirement-candidate SRs.
