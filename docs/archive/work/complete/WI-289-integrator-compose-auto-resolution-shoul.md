## Deliverable

Fixed 2026-07-24. Both files now auto-resolve through the EXISTING declarative [generated] mechanism rather than a hardcoded special case: two new kinds, `dupes` (regenerate the fingerprinted census from the merged tree via check_dupes.py --emit-census, preserving the hand-authored comment header and replacing only the fingerprint body) and `linecounts` (re-stamp `"<module>.py": <int>` baselines to the merged tree's ACTUAL counts, rewriting ONLY the numbers so every rationale comment survives - those comments are the ratchet's audit trail). Both are handled IN-PROCESS (_INPROCESS_REGEN) because neither has a generator that writes the file: --emit-census prints to stdout and a baseline re-stamp is a text transform, not a generated document. Key design point: `tests/test_module_size_ratchet.py` is DECLARED in docs/stack.ini, not built in, because tests/ is this repo's own suite and never ships downstream - the kit ships the MECHANISM, a repo declares its paths; stack.ini.template documents both kinds so adopters can opt in. The rationale is recorded where it belongs: these differ from the four document kinds because a merge leaves BOTH sides stale (the composed tree is bigger than either), so taking a side is always wrong and only a measurement from the merged tree is right. Four tests: the merged-actuals re-stamp (asserting it lands on neither side's value, that comments survive, and that a baseline naming an absent module is left alone not guessed), CRLF preservation, census header-kept/stale-body-dropped, and an end-to-end declaration+resolve that was confirmed to PARK with the new kinds removed. Size ratchet re-stamped 3768 -> 3889; complexity ratchet untouched (both new functions under MAX_COMPLEXITY). Full suite 1480 passed, 7 skipped. The row's open design call is deliberately NOT taken: both-add import-block conflicts still PARK for human eyes, since a code conflict is not derived data.
