## Deliverable

Fixed 2026-07-24. `_archive_closed_specs` now calls a new `_relink_archived_specs` (agent_dispatch.py), so moving a spec and redirecting its inbound links are one indivisible ritual - no caller can do half of it. Resolution is by resolved PATH, not by pattern: each inline link target is resolved relative to the file that holds it and compared against the moved source, so `](../../../work/complete/specs/WI-n.md)` from docs/log.md, `](../../../work/complete/docs/specs/WI-n.md)` from the repo root and `](../../../work/specs/WI-n.md)` from docs/reviews/ are all caught by ONE rule instead of the three regexes the row proposed; the replacement is re-relativised to each linking file's own directory. Repo convention honoured: link TEXT untouched, only the TARGET redirected; `#fragment` carried over; external URLs that merely CONTAIN the archived path, and bare `#anchor` links, left alone. Line endings preserved (read+write with newline='') so a CRLF checkout is not silently relaid to LF (WI-234 splice discipline). Two tests: test_wi288_archival_relinks_inbound_links_from_every_depth (the live WI-281 failure - a train's own log entry linking the spec it closes - plus all three depths, the fragment case, and the two must-not-touch cases) and test_wi288_relink_preserves_crlf_and_skips_unrelated_files (CRLF preserved; a non-linking file stays BYTE-identical).
