# WI-233 — Dispatcher `git()` drops stderr: failures park with blank details

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-233** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). ## Why

`agent_common.git()` returns `(returncode, stdout-stripped)` only
([agent_common.py:470-480](../../../project-trajectory/scripts/agent_common.py#L470-L480)),
but git reports hook rejections and fatal errors on **stderr** — so every
dispatcher error detail built from a failed `git()` call is blank. Field
evidence (gilbert, 2026-07-18, runs `20260718T100744` / `20260718T163343`):
the first ordinary train (WI-006) parked twice as
`integration-parked detail="integration commit failed: "` — empty after the
colon — because the pre-commit floor rejected the integration commit
(trajectory-map freshness; upstream-fixed for that cause by WI-220's
`_regenerate_disposition_artifacts`) and the hook's entire report went to
stderr. Diagnosing it required replaying the merge + commit by hand in the
staging worktree to recover the discarded stream. The same masking is latent
at every `git()` failure path upstream — e.g. the integration-commit detail
([agent_dispatch.py:1001](../../../project-trajectory/scripts/agent_dispatch.py#L1001)),
merge-conflict journaling, reservation CAS failures — any of which can fail
stderr-only (hooks: secrets floor, message scan; fatal ref errors). An
unattended process whose terminal states carry empty reasons violates the
written-terminal-state posture: the human pages in with nothing to act on.

## Scope

On nonzero exit, append the stripped stderr to the returned text (newline
join when both streams are non-empty); the success path returns stdout alone,
byte-identical to today. Callers unchanged — every `detail=out[:200]`
truncation now carries the real reason. Downstream gilbert already runs this
one-function patch in production (2026-07-18); upstream it as-is.

**Non-goals:** no structured (code, out, err) triple — no caller wants it and
the churn would touch every call site; no change to success-path parsing
(`rev-parse`, `status --porcelain`, trailer reads all parse stdout of
successful calls); no re-plumbing of hook output routing.

## Done-when

Regressions prove: (1) a commit rejected by a hook parks with the hook's
failing check named in the detail (fake hook printing to stderr and exiting
nonzero); (2) a stderr-only fatal (`rev-parse --verify` on a missing ref)
returns non-empty text; (3) a successful call with stderr chatter (e.g. a
warning) returns stdout only, unchanged; (4) the existing suite stays green —
demonstrating no failure-path caller parses `git()` output structurally.
