## Problem

`check_dupes.py --src project-trajectory/scripts` (the G3 `[step:dupes]` gate)
fails at clean HEAD — verified with the WI-191 working tree stashed, so it is
**not** caused by any current change:

```
check_dupes: duplicate block (~31 tokens):
  project-trajectory/scripts/gen_release_checklist.py:162 ==
  project-trajectory/scripts/trace.py:1342
```

Both blocks are the identical `in_phase(row)` SR-phase filter helper WI-188 added
to **both** scripts (each independently filters SRs by the derived `Phase`
column):

```python
def in_phase(row):
    tag = (row.get("Phase") or "").strip()
    if phases is None or not tag or tag in phases:
        return True
    n = phase_num(tag)
    return n is not None and n == foundation_phase
```

This is **F5-sanctioned small-helper duplication** (the kit's scripts stay
independently copy-able — small helpers are duplicated, not hoisted into a shared
module; the census records them, it does not fight them). WI-188 added the helper
to both scripts but did not add the pair to the census `docs/dupes-allow`, so the
gate went red. CI (which runs the derived G3 gate) never flagged it because the
branch is unpushed (OI-3).

## Fix shape

Add the `gen_release_checklist.py == trace.py` pair to `docs/dupes-allow` (the
default `--allowlist`), annotated as the WI-188 `in_phase` phase-filter helper —
the same class as the ~50 F5 pairs already in the census. **No code change** (the
duplication is sanctioned, not to be eliminated — hoisting a shared module would
violate F5).
