# WI-203 — agent_loop dirty-tree signal excludes the owner-only scratchpad

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-203** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Status: queued (filed 2026-07-17). Extends WI-076 (the dirty-tree resume
note) — a signal-hygiene fix, not a new surface.**

## Problem

`working_tree_dirty(root)` (agent_loop.py) returns every `git status
--porcelain` line, and the loop uses it two ways:

1. **Resume-note trigger** (`start_dirty`, agent_loop.py near the run entry):
   when non-empty on the FIRST session it prepends `RESUME_RECONCILE_NOTE` —
   "the working tree carries uncommitted changes … reconcile them … discard
   what is not part of the scoped work."
2. **Done-detection guard** (agent_loop.py): a dirty tree returns `None`
   ("committed evidence only — a dirty tree is not done").

`OWNER_SCRATCHPAD.md` is a tracked file the owner edits continuously (it is
owner-only by standing rule — CLAUDE.md; `check_docs.py` already exempts it
entirely under FB3/WI-072). Because it is *tracked*, it shows in
`git status --porcelain` as ` M OWNER_SCRATCHPAD.md`, so the working tree is
**perpetually dirty at loop start**. Two consequences:

- The WI-076 reconcile note — designed to flag *genuine interrupted-session
  residue* — fires on **every** resume, degrading a rare, meaningful signal
  into permanent noise and pointing an autonomous driver at a file it must
  never touch (the note literally says "discard what is not part of the scoped
  work").
- The done guard can read a tree whose *only* dirt is the owner scratchpad as
  "not done", when no worker deliverable is outstanding.

(Note: `git status --porcelain` does not list git-ignored paths, so no
gitignore filter is needed — the exemption is specifically the FB3 owner-only
set, the same one `check_docs` already drops.)

## Scope

1. Exempt the FB3 owner-only path(s) from the dirty-tree signal so a tree whose
   only changes are owner-only reads as clean for the loop's purposes. Prefer a
   single shared exempt set (a module constant) that BOTH `check_docs` and
   `agent_loop` consume, so the two never drift — SSOT over a second hand-copied
   list. If a shared home is disproportionate, mirror the one path with a
   comment linking the two.
2. Apply the exemption at both call sites — the resume-note trigger and the
   done-detection guard — since an owner-only edit is never the loop's or a
   worker's business in either case. The done-guard change carries its own test:
   a tree with a *real* uncommitted deliverable must still read "not done".
3. Keep `working_tree_dirty` honest for any caller that wants the raw list; the
   exemption is a filtered view (e.g. `substantive_working_tree_dirty`), not a
   silent change to the primitive.

## Interfaces

Intra-module: the fix lives inside `agent_loop.py`'s working-tree helpers and
their two callers; no seam crosses a module boundary. The only cross-file
concern is the shared FB3 exempt set (scope item 1) — if hoisted to a shared
constant, that becomes a small declared dependency between `check_docs` and
`agent_loop`, filed as a `Proposed` seam at build if it warrants one.

## Done-when

- [ ] A working tree whose only change is `OWNER_SCRATCHPAD.md` does NOT fire
      the WI-076 resume-reconcile note, and does NOT flip the done guard to
      "not done".
- [ ] A tree with a genuine uncommitted deliverable STILL fires the note and
      STILL reads "not done" (tested both ways).
- [ ] The owner-only exempt set is single-sourced (or the mirror is annotated
      with a link to `check_docs`'s FB3 exemption).
- [ ] Full suite + `check.py` at the derived gate stay green.

## Non-goals

- No change to the reconcile behavior itself (WI-060, deferred — the loop still
  never stashes/cleans/blocks; this only narrows what counts as dirt).
- No general "ignore arbitrary paths" mechanism — the exemption is the declared
  owner-only set, nothing more.
