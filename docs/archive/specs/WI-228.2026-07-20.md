# WI-228 — Live-orphan taxonomy + ratchet for check_docs (repo-review-2026-07-18 M-07)

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-228** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (review M-07) ·
**BuildTier:** medium · **SafetyClass:** ordinary (doc navigability tooling).

## Why

`check_docs` reports dozens of live orphan warnings — measured **63** on the
integration tree at filing (2026-07-18); it was 48 when this WI was first
drafted on `dualplan-routing-fix`, and the drift is the point: the census is a
*moving target by construction*, so no fixed count belongs in the acceptance
criterion (see Done-when). Most are *retained evidence* — reviews, closed-WI
specs, plan-round artifacts — that should stay live but unlinked-from-navigation
is the wrong frame for them; meanwhile genuinely undiscoverable new docs hide in
the same noise. Deleting or globally ignoring would destroy history; indexing
everything would bloat navigation (§0 table). The census only ever grows
silently — the same failure mode WI-225 ratchets for complexity.

## Scope

1. **Taxonomy.** Classify the current live orphans into declared classes (e.g.
   `review-evidence`, `closed-wi-spec`, `round-artifact`, `genuine-orphan`)
   recorded where check_docs can read them — a small declaration file or
   path-pattern rules in the script's config surface, whichever the script
   already supports more naturally. Genuine orphans get linked or indexed;
   evidence classes are *expected*-live-orphans and stop warning
   individually.
2. **Ratchet.** check_docs fails (or warns loudly under `--strict`) only on
   **newly introduced** live orphans outside the declared classes — baseline
   the residue, never fail history. Downstream behavior unchanged unless the
   adopter declares classes (default = today's behavior; the kit must not
   surprise existing repos).

**Non-goals:** no doc deletions; no mass index page; no change to broken-link
semantics.

## Done-when

**The acceptance criterion is count-independent** — the census is a moving
target (48 → 63 already, before this WI even landed), so the requirement pins
the *invariant*, not the number: **every** live orphan on the meta tree is
classified — **zero unexplained residue** (or each residue linked). That
invariant is mechanized by a regression test that runs check_docs against the
repo's own tree under `--strict-orphans` and requires exit 0, so it goes red the
moment an unclassified orphan lands — dogfooding the ratchet on the kit itself,
whatever the census count is at the time. check_docs regression tests also cover
class declaration, expected-orphan suppression, and new-orphan failure; kit
scripts stay stdlib-only; smoke bar green per commit, full suite at close;
`docs/status.md`/README untouched by the noise reduction (no navigation bloat).
