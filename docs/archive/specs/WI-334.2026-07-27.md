## The observation

`[step:dupes]` (`check_dupes.py --src project-trajectory/scripts`, census
`docs/dupes-allow`) reports **90 duplicate blocks that carry no
census line**. It was **green on 2026-07-25** in the all-17 `RESULT: PASS` run,
so all 90 accumulated since.

Same mechanism as [WI-333](WI-333.2026-07-27.md): `dupes` is a **G3-only** step, and from
2026-07-26 the open `Modified` re-attestation window held the derived gate at
**G2**, which drops it from the bar. The work that landed inside the window —
the `trace.py` → `trace_text.py` decomposition (WI-329), the render batch, the
`gen_open_items` build-out — never met this check. Closing the window brought it
back in one lump.

## Two different findings wearing one number

The census is **fingerprinted** (WI-276): a sanction covers the block whose tokens
hash to `<fp>`, so it is line-number-free but **sensitive to every token in the
block**. That means the 90 are a mixture, and the triage is the work:

- **Genuine new duplication** — a real copy-paste between two files, or a new
  file that arrived carrying a block another file already had. Example, confirmed
  by reading it: `gen_open_items.py:748` == `:769`, the
  `stamped = BASELINE_RE.search(...)` / `since = ...` baseline-reuse pair, once in
  `--check` and once on the write path. That one is real and extractable.
- **Census drift** — a block that WAS sanctioned, edited by a token, and so no
  longer matches its `<fp>`. The sanction is stale, not the code.

A count alone cannot tell these apart, and treating all 90 as either would be
wrong in opposite directions.

## The rule this WI must not break

**A census line IS acceptance of the duplication.** The standing rule (status.md,
from the 2026-07-25 close): *never reach for a sanction to green a step* — the
four `agent_dispatch.py` blocks that fired then were **extracted**, not
sanctioned. A blanket re-stamp of 90 lines would turn a quality gate into a
rubber stamp in one commit, and it is exactly the shortcut this repo has already
ruled against.
