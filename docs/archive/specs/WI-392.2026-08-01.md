# WI-392 — a driven figure carries its command, and a check re-derives it

**WI:** WI-392 · **Status:** queued · **Delivers:** a convention + a check (no SR
change expected at rung 1)

## Problem

This repo's records are dense with **driven figures** — "2 failed, 7 passed",
"109 links", "two false positives", "634 s", byte counts, test counts. They are
the evidence a reviewer's APPROVE rests on, and they compile into `docs/log.md`,
which is permanent. Nothing checks them. Today the only enforcement is a
reviewer reading closely, which is the weakest enforcer tier the
[enforcement audit](../../enforcement-audit.md) recognises.

**Three false figures in one session (2026-08-01), all caught by luck or
diligence rather than by machine:**

| Figure | Where | How it was false | What it cost |
|---|---|---|---|
| `2 failed, 7 passed` | WI-380's mutation ledger (spec + log fragment) | true when measured; false the moment round 1 added a test that also reds under the mutant. The *pass* count coincidentally held at 7 while selection went 9 → 10, so the stale line still read plausible | a **full REVIEW-A round** (WI-380 round 3) to bless the correction |
| `109 links` | WI-391's filed title | unreproducible at review; re-measured to 154 occurrences / 101 markdown link targets | a re-measurement inside another WI's round |
| "two false positives" | WI-384's composed-tree paragraph | the reporting sentence itself falsified the count it reported | a **full REVIEW-A round** (WI-384 round 5) |

The pattern is not carelessness. A driven figure is **evidence only at the
revision it was driven on**, and the record does not say which revision that
was, or what command produced it — so nobody, human or machine, can tell a stale
figure from a live one without re-running something they have to guess at.

`docs/stack.ini`'s own re-measure note already asks a human to re-derive its
declared numbers. That request has no enforcer.

**A fourth case, one level up, found while filing this row.** WI-378's own
census was wrong — not in a figure but in its **population**: it measured the
four branches its session brief named rather than the 20 the predicate had
governed, and drew a *universal* ("these are the only two") from a sample. Its
REVIEW-A round 1 caught it and the corrected figure is 3 of 13. The instructive
part is that WI-378 explicitly refused to inherit two *figures* from the same
brief and re-derived both — so scope is the harder half, and a provenance
convention that records only "what command produced this number" already carries
the fix: the command here (`git log --grep="^integrate: merge"` filtered by
`merge-base --is-ancestor`) enumerates 20, and running it is what exposes a
hand-picked four. **Whatever this row builds must cover the population a figure
was computed over, not just its value.**

## Provenance, stated with its bias

Proposed by WI-386's REVIEW-A reviewer, who disclosed the bias explicitly: *"I am
a reviewer arguing for less review of a finding class I raised."* The
round-capping half of that proposal (a round whose diff touches only record
surfaces at zero code tokens could close on a re-driven measurement rather than a
full adversarial round) was **measured and deliberately not filed** by WI-378:
across all 20 merged branches only **3 of 13** staled APPROVEs came from a
record-only edit, so capping rounds addresses 23.1 % of the cost while weakening
the gate — and **two of those three rounds caught a false claim**, which is the
argument against capping them at all. This row is the other half — the one that
does not weaken anything.

## Approach

Two rungs. **Rung 1 is the row; rung 2 is named so it is not accidentally
assumed.**

**Rung 1 — the figure carries its provenance, and a check verifies the *shape*.**
A convention for a driven figure in a declared record surface: it names the
**command** that produced it and the **revision** it was driven at. A check
(stdlib, cross-platform, in the shipped set) reads the declared surfaces and
flags a figure-shaped line that carries neither. It checks *presence*, never
truth — which is cheap, has no false-truth risk, and would have flagged all
three rows above.

The hard part is not the check, it is **what counts as a figure**: a regex over
digits will drown in ids, dates, section numbers and byte budgets. Likely shape
is an opt-in marker on the line rather than detection (the kit's usual move —
declare, don't infer), which makes the check's honest claim "declared figures
carry provenance", not "all figures do". Decide that trade at build time and
state it plainly in the check's own docstring.

**Rung 2 — re-derivation (NOT assumed by rung 1).** A `--re-derive` mode that
runs the recorded command and compares. Three real obstacles, all of which rung
1 leaves untouched: (i) running commands read out of documents is an execution
surface and needs an allow-list; (ii) most figures are **historical** — true at
the revision driven, legitimately different now — so re-derivation is only valid
against the recorded revision, which may not even be reachable; (iii) some
commands are expensive (`tests+coverage` is 634 s) or non-deterministic. Rung 2
is worth a separate decision after rung 1 has shown how many figures actually
declare a re-runnable command.

## Interfaces

Single-module at rung 1: one new check script (or an arm of `check_docs.py` — a
`Proposed` IF row is owed only if it becomes a new seam). Rung 2 would introduce
a real seam (command execution) and must file one.

## Done-when

- [x] The convention is stated **once**, in the process text that owns record
      surfaces, and linked — not restated per surface.
- [x] **A declared figure records the POPULATION it was computed over, not only
      its value** — satisfied by the recorded command when that command
      enumerates the population (`git log … | wc -l` does; a hand-listed set
      does not, and must name its selection principle). This is an acceptance
      bar, not extra build: rung 1 stays presence-only. It is in Done-when
      because a constraint stated only in prose does not bind — and because the
      case that forced it (WI-378's four-of-twenty census) was a figure whose
      *value* was right for the sample and wrong for the world.
- [x] **A figure DERIVED from a declared figure is itself declared** — the
      remainder, the percentage, the "twelve staled nothing". WI-378 got its
      re-derived census right and then miscounted its own complement in the
      same paragraph; a convention that covers only measured numbers would have
      passed that sentence.
- [x] A check enforces the above over the declared surfaces, warn-first, with
      its honest claim ("declared figures carry provenance") in its docstring.
- [x] The three figures in the table above are used as the fixtures: each would
      have been flagged.
- [x] `docs/stack.ini`'s re-measure note points at the check instead of asking a
      human.
- [x] Rung 2 is either filed as its own row or explicitly declined with a reason.

## Notes / open questions

- **Is a warn enough?** A false figure has never blocked a merge; it has bought
  review rounds. A warn that a reviewer reads is already stronger than today's
  nothing, and an error risks a check that everybody learns to suppress.
- **Scope creep to watch:** this is not a claims-verifier for prose. It is
  provenance on numbers. A row that starts trying to verify sentences is the
  wrong row.
