# WI-230 — Publish under disjoint dirt

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-230** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-18 (parallel-run field
finding 1, owner-selected Option 1) · **BuildTier:** strong · **SafetyClass:**
high-risk (publication CAS + primary-worktree sync).

## Why

Publication ends in `git reset --hard <target>`, so `publish_integration`
defers on *any* tracked dirty path
(`agent_dispatch.py:1250-1260`)
— including files the publish diff never touches. Two such files are dirty in
normal operation: `OWNER_SCRATCHPAD.md` (owner-only by contract, edited at
arbitrary moments — workers never touch it, so it can never intersect a
publish diff) and `docs/run-state` (the dispatcher's own end-of-run generated
rewrite — self-inflicted dirt). Field evidence (run `20260718T153937`):
WI-227's integration sat unpublished on `llm/integration` behind a dirty
scratchpad; the recovery choreography was restore + stash + relaunch + pop,
and the obvious wrong move — committing the scratchpad to clean the tree —
creates diverged integration/dev heads and lands in WI-220's NEEDS-HUMAN
stop. The guard protects the worktree by blocking the exact workflow the
scratchpad exists for.

## Scope

Replace the blanket dirty-at-outset defer with a disjointness rule: intersect
the dirty tracked paths with `git diff --name-only <dev_head> <target>`.
Empty intersection ⇒ proceed, syncing the checkout with a mechanism that
carries the dirty paths forward unchanged (`merge --ff-only` semantics /
`read-tree -m -u` — git's own machinery already refuses when it would
clobber); non-empty ⇒ defer exactly as today. Apply the same rule to the two
§11 recovery branches: the already-at-target worktree-diverges case
(`agent_dispatch.py:1207-1233`)
and the post-CAS verified sync
(`agent_dispatch.py:1319-1331`) —
the exact-old-hash hard reset stays for the mechanically-stale case; the
disjoint-dirt case syncs around the preserved edits. The never-stash /
never-reset-user-edits contract is unchanged; intersecting dirt still defers.

**Non-goals:** no change to the publish-intent ref CAS protocol or its
recovery evidence; no publication when dirt intersects the diff; no
path-name allowlist (disjointness derives what a list would hardcode).

## Done-when

Regressions prove: (1) a dirty tracked file disjoint from the publish diff no
longer defers — publication lands and the edit survives byte-for-byte through
the sync; (2) dirt intersecting the publish diff still defers untouched;
(3) the idempotent replay paths (intent present, crash between CAS and sync)
preserve both properties; (4) the run-state end-of-run rewrite alone can no
longer strand a publication. Existing publish/recovery suite stays green.
