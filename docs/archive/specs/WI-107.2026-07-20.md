## Goal

The meta-repo's walk-away loop currently runs the minimal legacy path: one
provider, one tier (`AGENT_CMD` = Claude CLI, `AGENT_MODEL=opus`), no phase
routing, `attended` gate authority. Wire the declared-config layer the kit
already ships so `agent-resume.*` boots a managed, consent-explicit run with
**one human attestation point per phase batch** (`single-ratify`).

## Deliverables

1. **`docs/gate-policy`: `attended` → `single-ratify`**, in a reviewed commit,
   **with the deviation register** (`docs/gate-policy.md`, the
   `bootstrap.py --gate-policy` shape) recording the deviation from the §4
   default and its compensations. Per the policy file's own rule the value is
   hand-set and changes only in a reviewed commit; the owner's review of this
   WI's landing commit *is* that review. Composes with the derived gate
   (gate-advance skill): the human ratifies each phase's queued batch once at
   its `[phase]-[g2]` close; autonomous after.
2. **`docs/agents.csv`** seeded on the pair-row model (`Id,Family,Model,
   Version,Tier,CmdTemplate,Env,Notes`) with the Claude line the launcher
   already uses — e.g. `CLAUDE-OPUS` (strong), `CLAUDE-SONNET` (medium),
   `CLAUDE-HAIKU` (weak); `CmdTemplate` = today's `AGENT_CMD` string; `Env`
   empty (ambient). Same `Family` for all three — single-provider review
   rounds are the documented degraded-legal mode (fresh context is the
   invariant); add cross-provider rows only when those CLIs are actually
   installed, never speculatively.
3. **`docs/agents-enabled`** — the consent surface whose *presence* turns
   managed routing on: the three ids in preference order, `#`-commented header
   stating exactly that.
4. **`docs/run-phase`** seeded `BUILD` (the backlog is specced and sequenced;
   comment header per the declared-policy idiom).
5. **`docs/guardrails-policy`**: prefer a weak-tier token (e.g. `haiku`) so
   guardrails guard exactly the tier they exist for — which requires the
   vendored `docs/guardrails/core.md` (from the guardrails sibling repo,
   drift-checked by `check_vendored.py`). If vendoring doesn't land inside this
   WI, ship `off` with the reason recorded here — an inert *guarding* token
   would draw the loop's guardrails-inert warning every run.
6. **Launcher maps filled** ([`agent-resume.cmd`](../../../agent-resume.cmd) /
   [`agent-resume.sh`](../../../agent-resume.sh), twins in sync):
   `AGENT_MODEL_MAP` per run-phase and `AGENT_CMD_MAP` where a phase needs a
   different template. **Precedence honesty:** with `docs/agents-enabled`
   present, the registry + tier map drive selection and the env maps are the
   *fallback* path (absent enable-list = legacy behavior) — fill them anyway as
   the owner-directed declared fallback, coherent with `DEFAULT_PHASE_TIER`.
   Preserve today's strong-tier stance for gate-bearing work: set
   `AGENT_TIER_MAP`/`--tier-map` `BUILD=strong` initially (tier-up-never-down
   makes reviews ride medium safely); relaxing BUILD to medium is a later,
   deliberate dial turn at a ratification sitting.

## Constraints

- **Config layer only — no spine change expected.** The routing/guardrails
  capabilities are already SR-traced kit behavior; this WI *declares* the
  meta-repo's use of them (the WI-075 "dev tooling, no SR change" precedent).
  If the owner elevates any part to requirement level, it enters as a
  `Phase=v2` Draft SR with the WI-085/087 batch instead.
- **Never-breaking:** every file lands whole and valid — a half-seeded
  `agents.csv` with a present enable-list fails preflight loudly (by design);
  land registry + enable-list in one commit.
- **Consent stays explicit:** the enable-list header + the launcher CONSENT
  banners are the record; no silent model swaps (the loop logs every selection
  before launch).
