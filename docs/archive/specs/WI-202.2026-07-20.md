**Status: queued (filed 2026-07-17). Depends on WI-200 — this implements the

## Problem

`docs/status.md`'s `## Current State` bar hand-transcribes DERIVED facts — the
spine counts (`SN/SR/LLR/TC`, seams, coverage), the derived gate, and the
open-items list — that `trace.py` / `derive_gate.py` / `docs/open-items.md`
already own. Hand-copied derived data drifts: the DP-001 build (WI-194..199)
moved the spine to LLR=76 / TC=76 / 61 seams while the bar still read
LLR=69 / TC=69 / 57 seams (IF-057 Proposed). The `agent_loop` resume path feeds
exactly this section to the driver as its resume excerpt
(`current_state_excerpt`), so the drift is handed straight to the unattended
loop, and it misdescribes the very seams the next WI (WI-201) re-homes.

WI-200 restored the forward-only done-id guard but explicitly scoped OUT
number-freshness: its docstring
(`check_trajectory.status_forward_only_findings`) records the real fix as a
generated-block + `--check` freshness check that is "SPECIFIED here as the
retirement's promise but not implemented, because no status.md generator exists
yet." The mode-aware guard already stands the token rule down the moment
status.md carries the `<!-- BEGIN GENERATED ... -->` marker
(check_trajectory.py) — this WI builds what that marker promises.

## Scope

1. A generator (`gen_status.py`, or a `--status` mode of `gen_trajectory.py`)
   that splices a `<!-- BEGIN GENERATED STATUS ... -->` / `<!-- END ... -->`
   block into `docs/status.md` carrying ONLY derived facts:
   - spine + derived gate from `trace.py` / `derive_gate.py` (the same values
     the dashboard already renders);
   - the open-items list projected from `docs/open-items.md`'s `## OI-N`
     headings + each section's one-line summary.
2. Its `--check` freshness step (the `gen_arch_map --check` idiom): regenerate
   in memory, byte-compare, non-zero on drift — wired into `check.py` in the
   same freshness family as `trajectory-map` / `arch-map`, so a registry or
   open-items edit that stales the block blocks at commit, not first in CI.
3. The mode-aware handoff: with the marker present,
   `status_forward_only_findings` stands its token rule down (already coded) and
   the freshness step becomes the invariant; the S-3 presence lint's
   "named-in-both" direction (`check_docs.check_status_surface`) retires — a
   generated list cannot disagree with its source. S-3's line-budget and
   Open-items-order warnings stay (they guard the hand-authored region).
4. The format contract for the liftable per-OI one-liner is pinned in
   `docs/specs/open-items-surface.md` (an explicit one-line field, or the first
   Recommendation sentence lifted verbatim) so the projection is deterministic.

## Interfaces

Crosses the generator -> checker boundary: the freshness consume EXTENDS the
existing **IF-023** (check_trajectory's consume of the trajectory/status
surface). The block-splice emit follows the established generated-block idiom
(`gen_arch_map` into `architecture.md`, `gen_trajectory` — the shared
`<!-- BEGIN GENERATED -->` sentinel is the contract, no new seam). Any new seam
surfaced at build is filed `Proposed` with its nearest-IF rationale (WI-191).

## Done-when

- [ ] `docs/status.md` carries a `<!-- BEGIN GENERATED STATUS -->` block holding
      the spine/gate + open-items projection; the hand-authored "Next action",
      the Open-item briefs, and Scope stay OUTSIDE the marker.
- [ ] The generator's `--check` fails `check.py` on any drift of the block, and
      is green when fresh; regenerating after a registry / open-items edit
      updates it.
- [ ] `status_forward_only_findings` token rule stands down under the marker
      (already coded) and the freshness check is proven its successor; the S-3
      "named-in-both" direction is removed, with a test.
- [ ] Volatile "re-verify at read time" facts (OI-3's git state) are NOT baked
      into the block — they stay a live-check instruction, not a stamped string.
- [ ] `trace.py --strict` + `check.py` at the derived gate stay green.

## Non-goals

- No change to the forward-only INTENT content ("Next action", the Open-item
  briefs) — only the derived snapshot is generated.
- No new spine requirement beyond the wiring; this is tooling + enforcement, not
  a behavior change to the status surface's meaning.
