# WI-234 — Project every pending owner action into the central open-items surface

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-234** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Branch:** dualplan-routing-fix · **Filed:** 2026-07-19 (owner directive:
attestation/owner work from parallel branches must reach the root review
surface) · **BuildTier:** medium · **SafetyClass:** high-risk (dispatcher
terminal flow writes an owner surface).

## Why

WI-229's stage-2 attestation stop was invisible from the owner's review
surface: the worker blocked correctly, but the ask lived only in the spec, the
quarantine exit code, and a plan doc stranded on the quarantined train branch
— the owner went to `open-items.md` and found nothing (the
OI-14 brief was filed by hand a day later). The same class recurs for every
parallel-branch hard stop: source-conflict NEEDS-HUMAN asks (WI-232),
quarantines with reasons (WI-233 made them non-blank), and `blocked` registry
rows with a BlockRef. The owner surface contract says open-items.md is *the*
single owner-review surface; anything that needs the owner and isn't there is
a filing gap by construction.

## Scope

A **generated "Pending owner actions" section** in `docs/open-items.md`,
marker-delimited like the status snapshot (`<!-- BEGIN/END GENERATED PENDING
-->`), rendered by the same generator family (`gen_trajectory.py --status`
sibling) from **durable state only** — never from the journal cache (§11):

- `blocked` registry rows whose BlockRef names an attestation/ratification
  page (the WI-229 shape), including the train-branch read path when the
  referenced doc is not on the dev branch (`git show <train>:<path>`);
- source-conflict records under `refs/llm/conflict/*` (WI-232) with their
  train + conflicted paths;
- quarantined trains' recorded reasons;
- the current run-state `ask:` line when NEEDS-HUMAN.

Hand-authored OI briefs stay hand-authored and above the marker; the generated
section carries one line per pending action with a pointer, not a brief. The
dispatcher regenerates the section at its terminal decision (same place
run-state is written); `gen_trajectory --status --check` gains the freshness
guard so a stale projection fails the harness like the status snapshot does.

**Non-goals:** no auto-authored OI briefs (numbering and judgment stay human);
no new durable stores — the section is a pure projection of existing state; no
change to what blocks/quarantines.

## Done-when

Regressions prove: a blocked-with-BlockRef row, a conflict record, and a
quarantined train each project one line with the right pointer; resolving each
(row unblocked / record cleared / train retired) drops the line on the next
regeneration; the freshness `--check` fails on a stale section; hand-authored
briefs above the marker are byte-untouched by regeneration. Suite green.
