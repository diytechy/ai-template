# WI-254 — Pre-commit sweeps stray coverage residue from the repo root

> **ARCHIVED 2026-07-20 — done.** Spec-of-record for **WI-254** (`done`; deliverable in `docs/requirements/work-items.csv`, session record + 109-REVIEW-A verdict in `docs/log.md` / `docs/reviews/109-REVIEW-A.md`). Archived at close per the lifecycle its own rule R-F now enforces.

**WI:** WI-254 · **Status:** queued · **Delivers:** meta-repo hygiene (no

## Problem

Owner finding (2026-07-20): `.coverage` / `.coverage.*` files (pytest-cov,
including `-n auto` parallel shards) accumulate in the repo root and clutter
the working view. They are gitignored residue, regenerated by every coverage
run — nothing consumes them between runs.

## Approach

The **meta-repo wrapper hook**, not the shipped kit hook: extend
[.githooks/pre-commit](../../../.githooks/pre-commit) to delete `.coverage` and
`.coverage.*` from the repo root before delegating to the shipped floor —
this-repo-only (the wrapper is already meta-repo-specific), so downstream
repos see no behavior change and no migration. Guard rails: delete only the
exact top-level residue names; never touch `.coveragerc`-style config (none
here) or anything tracked by git.

## Interfaces

No cross-module seam — a two-line edit inside this repo's own hook wrapper.
