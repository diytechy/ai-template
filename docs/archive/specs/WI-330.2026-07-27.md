# WI-330 — Trace the three untraced spine-text checkers

**Status: done** (found 2026-07-27 while scoping WI-329; owner ruled *"clear it
now, before any re-attest"*).

## The gap

Three checkers ship in `trace.py` with **no `SR`, no `LLR`, no `TC`**:

| Checker | Tier | Landed by | Traced? |
|---|---|---|---|
| `provenance_findings` | **gating** (`--strict`) | WI-327 | no |
| `form_findings` | **gating** (`--strict`) | WI-328 | no |
| `paraphrase_advisories` | advisory (warn-only) | WI-328 | no |

The convention is unambiguous and already worked elsewhere: `ac_advisories` — the
same *kind* of thing, a warn-only lint over `SR` prose — has `SR-004`
("Acceptance-criteria advisory") → `LLR-004` → `TC-004`. One row per lint.

So this is not a judgement call about whether these deserve rows. It is a gap.

## Why the harness could not catch it

`trace.py` reports **orphans among rows that exist** — an `SR` with no child, an
`LLR` with no parent. It has no notion of *shipped behaviour with no row at all*,
because nothing in the registries points at the behaviour to begin with.

That is worth stating plainly rather than treating as an oversight: **the
traceability harness cannot detect untraced work.** Only a reviewer reading the
diff against the spine can, and two adversarial reviews of this exact change
missed it — 124-REVIEW-A and 125-REVIEW-A were both scoped to *prose fidelity*,
not to *coverage*. The gap was found by hand while scoping an unrelated WI.

The uncomfortable version: a repo whose product is traceability shipped two
**gating** checks untraced, and its own process caught neither.

## Scope

Three chains, following the `SR-004`/`LLR-004`/`TC-004` shape exactly:

| New `SR` | Covers | Verification |
|---|---|---|
| `SR-126` | a spine row states the system, not its own history — gating | Test |
| `SR-127` | a requirement states one testable obligation — gating | Test |
| `SR-128` | a child that re-words its parent warns, never gates | Test |

Each gets one `LLR` naming `trace.py` + the real symbol, and one `TC` citing the
tests that already exist and already pass:

- `tests/test_trace.py::test_a_spine_row_states_the_system_not_its_own_history`
- `tests/test_trace.py::test_a_requirement_states_one_testable_obligation`
- `tests/test_trace.py::test_a_child_that_rewords_its_parent_warns_but_never_gates`

**No production code changes.** This WI writes registry rows for behaviour that
already ships and is already covered; if it needed a code change, the rows would
be wrong.

## Status of the new rows

`Modified`, not `Verified`. The evidence exists and passes, but **no human has
ever attested these rows** — they did not exist to attest. `Modified` is the
state that says "owes a sitting" and derives G2, which is where the spine already
is, so this adds three rows to the open window and changes no gate arithmetic.

Marking them `Verified` would be the driver signing for the owner, which is the
thing this whole layer exists to prevent.

## Deliberately NOT in scope

- **Widening `trace.py` to detect untraced behaviour.** Tempting, and wrong at
  this size: it would mean parsing the script surface and guessing which
  functions constitute "behaviour", which is a heuristic with a large legitimate
  majority — the failure mode the provenance rule was measured to avoid. The
  honest control here is review, and the honest record is this document saying so.
- **Auditing every other kit script for the same gap.** A real question, and a
  different WI: this one closes the gap its own predecessors opened.
