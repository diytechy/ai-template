# WI-316 — The `Modified` spine status: re-attestation as registry state, not commit-message prose

**WI:** WI-316 · **Status:** queued · **Delivers:** SR-049

## Problem

Nothing durable tracks that a re-attestation is **owed**. The flag lives in
commit messages and log headings as the phrase `RE-ATTESTATION PENDING` —
prose-tier, invisible to every checker, surfaced to the owner only if a session
happens to read the git log and say so. The five-commit batch pending as of
2026-07-26 is known only that way. This is the escalated-in-conversation,
filed-nowhere failure mode again, one layer down:
[enforcement-audit.md](../../enforcement-audit.md) records the attestation itself
as Prose, but the *owed* state has no home at all.

**Owner ruling (2026-07-26, Decisions log):** the marker belongs in the
**requirements registries**, not the WI layer. The SR/LLR/TC registry is the
current state of the *what*; `work-items.csv` is work applied over time. When a
spine row's content changes after attestation, that is a change to the what —
so the row's `Status` should say so. A third recognized value, **`Modified`**,
such that both `Modified` and `Draft` surface to the owner and pull the derived
gate back for re-attest. (Alternatives passed over, recorded in the ruling:
a synthetic `blocked` WI + `BlockRef` — models artifact-state as work-to-do and
no work is actually blocked; a stamp file beside `docs/gate` — a brand-new
artifact the owner asked to avoid; the prose status quo.)

## The load-bearing fact: the gate-pull is already free

[`derive_gate.py`](../../../project-trajectory/scripts/derive_gate.py) computes an
SR that is decomposed but **not** `Status=Verified` as **G2** for its phase —
today, with zero code change. Only `Draft` (G0 + decomposition exemptions) and
`Verified` (G3) are magic; any other value already lands at exactly the right
rung: below attested, above drafting, children still required. `Modified` is
therefore **canonization, not new gate mechanics** — the work is naming the
value, surfacing it, and guarding its consistency. Do not add gate logic for it.

## Semantics (the design, decided at filing)

- **`Modified`** = the row landed complete and green (its checks pass, its
  chain exists) but its **content changed after the last human attestation**;
  a re-attest is owed. Title-Case, matched case-insensitively — the same
  one-casing rule as the other two (`process.md` §4).
- **The SR is the attestation unit.** A change anywhere in a chain (SR cell,
  child LLR `Detail`, TC `Expected`, a child added/superseded) flips the
  **owning SR** to `Modified`. Child LLR/TC rows *may* also be marked (useful
  precision) but their status stays non-gating — `maturity_gate` is untouched,
  preserving the anti-coupling ruling that LLR/TC status never independently
  gates.
- **Re-attest = `Modified` → `Verified` in a reviewed commit**, recorded in the
  log's Decisions — the mirror of ratification's `Draft` → `Planned`. The gate
  re-derives to G3 on its own. One sitting can flip a batch (the phase-cadence
  rule already says to batch them).
- **The flip asserts two things, not one** (owner probe at filing, 2026-07-26):
  `Verified` is the V&V claim — the declared `Verification` method ran with
  passing evidence — while ratification (`Draft`→`Planned`) is the
  prose-blessing. A post-attestation amendment stales **both**: the blessed
  prose is no longer the current prose, and the evidence proved the **old**
  text. `Modified`→`Verified` therefore claims *the amendment is blessed AND
  the existing evidence still verifies the amended text* — the right default
  for narrowings and judge-reassignments whose tests are green against the new
  wording. When an amendment **invalidates** the evidence, the honest flip is
  **`Modified`→`Planned`**: the row re-earns `Verified` through
  re-verification, and the gate correctly stays below G3 until it does. The
  `gate-advance` skill paragraph (deliverable 4) must state both flips.

## Accepted trade, stated honestly

While an SR sits `Modified`, the derived gate reads G2 and `check.py` runs the
**G2 bar** — the G3-only steps (`lint`, `dupes`, `--require-verified`) drop out
until re-attest, exactly as during any `Draft` window. That is the derived-gate
model working as designed (an unattested spine is not a G3 spine), but it is a
real laxening: re-attest promptly, don't let `Modified` windows sprawl.
