# WI-365 — Split the three double-shall SRs the open window let through

**WI:** WI-365 · **Status:** queued

## Problem

`check.py --gate G3` reds on the `traceability` step: SR-006, SR-130 and
SR-131 each carry two `shall` in their Requirement cell — WI-328's gated
one-obligation-per-row rule. All three entered at one Phase 3 commit
(`7f66720`; SR-130/SR-131 born compound, SR-006 amended 1→2 — measured by a
per-commit transition scan at the Phase 5 sitting) while the restructure's
open window held the G3 tier advisory, so the findings warned on every run
and gated only when the 2026-07-29 Phase 5 sitting closed the last window
and armed G3. Until this lands, the G3 harness bar carries exactly these
three named findings; everything else passes (19/20 steps green,
2026-07-29).

## Approach

The WI-328 pattern re-applied (`728cbda` is the worked precedent: 13 SRs →
28, no new TCs where the existing test genuinely covers both halves):

- Split each row into one-obligation rows; do NOT reword the second
  obligation into a participle (the WI-328 ruling: that hides it, a recorded
  sanction accepts it — split it).
- Re-point/extend the LLR/TC chains; new SR ids, `SupersededBy` on the old
  rows if the split takes the WI-229 supersession form (then the TC-099
  evidence pattern applies) — or an in-place narrowing + sibling rows if one
  obligation keeps the id; decide per row against the WI-328 precedent.
- **This amends `Verified` rows, so it lands AT a sitting** (the flips ride
  the same commit as the amendment; a window opens and closes with it).
  `trace.py --ratify` generates the brief.

## Interfaces

No cross-module seam — registry rows + their spine chains only.
