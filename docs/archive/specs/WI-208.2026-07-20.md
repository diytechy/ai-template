## Problem

`agent-resume` still boots the **legacy serial resume driver**: the ratified
dispatcher contract ([parallel-wi-dispatch.md](parallel-wi-dispatch.2026-07-20.md) §1.2 —
"`agent-resume` is the dispatcher/integrator; `--jobs 1` is the explicit
serial escape hatch") is built and tested (WI-180…186, WI-204), but §14 gates
the default flip on two audits this repo has never run on itself: the
registry has **no `SafetyClass` column** and there is **no
`docs/archive/history/parallel-ready`**, so every row reads `unclassified` and the dispatcher
would schedule nothing. The two-execution-paths state is a half-finished
migration (owner sitting 2026-07-17, log), and every guard wired per-path
(the dual-plan quiet-park hole) is a symptom.

## Scope

1. **The `SafetyClass` column** appended to
   `docs/requirements/work-items.csv`'s header (after `BuildTier`; the
   scheduler reads optional columns by name via DictReader, so column order is
   presentation only). Do NOT backfill `done` rows — the frontier reads open
   rows only; a blank cell on a done row is honest history, not an audit gap.
2. **The SafetyClass audit (§14.10):** classify **every open row** —
   queued/active/blocked **and deferred** (a deferred row re-enters queued on
   an un-defer; classifying now means the un-defer needs no second audit) —
   deliberately, against the declared vocabulary
   (`ordinary|spine|gate|attestation|protected|high-risk`) and the validator's
   structural cross-check (a SpecRef/deliverable resolving into the spine
   registries ⇒ `spine`; gate/ratification scope ⇒ `gate`; etc. — a
   mis-declaration quarantines as unclassified, so classify honestly, not
   optimistically). Record the per-row reasoning as one audit table in the
   session log entry (id → class → one-line why), not a new doc.
3. **The soft-edge audit (§14.9):** re-check every `~` soft edge among open
   rows — the optimistic scheduler treats every soft edge as
   safe-to-run-concurrently, so a soft edge that is *really* a hard
   correctness edge is promoted to hard in the same commit; the audit table
   records each edge's verdict (advisory-confirmed / promoted).
4. **Sign `docs/archive/history/parallel-ready`** (the declared-file idiom: `#` comment lines
   + the value): the sign-off line naming both audits + the audit commit, per
   §14's format guidance (read §14 items 9–10 at build for the exact shape it
   expects; if §14 leaves the format open, use the gate-policy file's comment
   style and record the choice).
5. **Flip the launchers:** `agent-resume.sh` / `.cmd` / `.command` export
   `AGENT_JOBS=2` (the §6 default; model quotas — not CPU count — are the real
   ceiling constraint, so 2 stays the deliberate default). `--jobs 1` remains
   the per-run serial escape; absent-`AGENT_JOBS` legacy behavior is untouched
   for downstream repos that have not migrated. Keep the three launchers'
   slots in sync (the file-header rule).
6. **Prove the boot:** one real `agent-resume` (or
   `agent_loop --root . --jobs 2` with a no-op/dry window) reaching the
   dispatcher banner — reconcile → gate → build-out — with the reason-coded
   telemetry line and zero unclassified rows in `schedule.py ready --explain`.
   With the queue drained this is a banner + clean-exit run, which is exactly
   the desired evidence (nothing to dispatch ≠ failure).
