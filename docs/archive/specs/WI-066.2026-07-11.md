## Context

The OKF export (`project-trajectory/scripts/gen_okf.py`, WI-034 / SR-042) writes
a generated `docs/okf/` bundle — one typed markdown concept per registry row,
tier indexes, a root index, and `UPSTREAM.md`. A 2026-07-11 audit of the meta
bundle found two problems:

- **Weak self-identification.** ~210 of the 218 generated files carried no
  in-body signal that they are generated reference copies — only a subtle
  `resource:` frontmatter line. A reader (human or agent) landing on one file
  could mistake it for the reviewed source of truth.
- **Doc-graph pollution.** `project-trajectory/scripts/check_docs.py` counted the
  whole bundle in its doc discovery, so 218 of its 219 orphan warnings were okf
  files, drowning the one real orphan (`docs/test/report.md`).

## Owner ruling (2026-07-11)

- **(a)** Every file `gen_okf.py` emits gets a one-line GENERATED banner making
  clear the file is a generated reference copy, naming its source of truth and
  the regen command. Deterministic (no clock), one template source-slotted,
  consistent across file types.
- **(b)** `check_docs.py` excludes `docs/okf/` from its doc-graph / orphan scan —
  the idiom `gen_arch_map.py` / `gen_trajectory.py` / `check_doc_refs.py` already
  use so tools never lint generated output.
- Nothing else: no default flip, no `.ignore` change, no `rg` changes.
