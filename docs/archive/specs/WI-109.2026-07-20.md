# WI-109 — Cross-provider enablement: GPT-5.6 via opencode + agent-CLI dev tools + routing failure context

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **WI-109** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Status: done** (owner-directed 2026-07-12, the sitting after WI-107): add
`claude` and `opencode` as required dev tools for this repo, register the
GPT-5.6 family (Sol/Terra/Luna — strong/medium/quick) routed through opencode,
and surface sign-in/install guidance when models fail — "better failure
context", specifically the opencode/claude auth paths.

## Deliverables

1. **`docs/agents.csv` + 3 OPENAI pair rows** — `OPENAI-SOL`/`-TERRA`/`-LUNA`
   (`gpt-5.6-sol/-terra/-luna`, Version 5.6; strong/medium/weak), CmdTemplate
   `opencode run --model openai/{model} {prompt}`. Model ids verified against
   the GA release (2026-07-09): the explicit ids are `gpt-5.6-*`; bare
   `gpt-5.6` aliases to Sol. Reviews now route **cross-family** (Terra) after
   an ANTHROPIC build; same-family remains the degraded-legal fallback.
2. **Effort pinned on the ANTHROPIC rows** — `Env` =
   `CLAUDE_CODE_EFFORT_LEVEL=high` (owner: "high or very high as a good
   balance"; `high` is also the documented Opus 4.8 default, so this *declares*
   rather than changes it, and uplifts any row where the CLI honors the var).
   `xhigh` is the deliberate dial-up candidate; mechanized selection is
   **WI-110** (deferred).
3. **`docs/agents-enabled`** — the 6 ids, ANTHROPIC-preferred within each tier.
4. **dev-setup rows (meta `scripts/dev-setup.{sh,ps1}`)** — `claude` +
   `opencode` named required dev tools with install + sign-in hints
   (report-only `--check` stays exit-0/consent-first; the loop preflight is the
   hard enforcement point). Kit templates untouched — a downstream repo
   declares its own agent CLIs.
5. **Failure context (kit code, `agent_route.py`/`agent_loop.py`)** — the
   registry `Notes` column is the declared home for each provider's
   install/sign-in hint, echoed at the three failure points:
   - managed preflight, when a row's CmdTemplate CLI is missing;
   - the moment an ERROR/TIMEOUT session cools its model (this path was
     silent — now `route: <id> session outcome=… (exit N); cooled ~Ns …`);
   - the NEEDS-HUMAN "no routable model" page, which now renders the whole
     enabled pool per row (tier, family, cooling state, Notes) via
     `agent_route.pool_context()` — an exhausted pool says what to *do*
     (e.g. `opencode auth login`), not just that it paged.

## Constraints

- No spine change: the routing/dispatch capabilities are SR-traced kit behavior
  (SR-045); the failure-context lines are message surface within SR-045's
  selection-logging claim, and the registry/dev-setup edits are meta config
  (the WI-075/WI-107 precedent).
- Kit stays provider-neutral: no provider names in kit code — hints live in
  the registry data.
