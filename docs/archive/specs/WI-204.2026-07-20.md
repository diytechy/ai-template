## Problem

SR-058's classifier rule 1 is a flat ban: spine/gate/attestation "serialize
whole-project and **never join a multi-WI traincar**." The intended dominant
path for spine work is the launch sequence's stage-2 gate pass
(`parallel-wi-dispatch.md` §4): all ready spine content cleared as **one
coherent whole-project pass** per gate level, with ratification exits batched
per `docs/gate-policy` — so ratification/gate-clear count never scales with WI
count. But for spine WIs that surface **mid-run**, after the gate stage, the
letter of the rule forces *N sequential single-WI trains*, each integrating
before the next starts (§5.1). That contradicts the batching intent (owner,
2026-07-17): all ready spine work touches the same registries and should be
wrapped into **one** serial traincar and iterated as a group. The sequential
form costs extra integration cycles and wall time — not extra ratifications
(ratification is a batch-scoped `[phase]-[g*]` gate event, not a per-train
event) — and splits one coherent body of spine edits across several branches.

## Scope

1. **Amend SR-058** (requirement text + AC): the spine-serial class
   (`spine`/`gate`/`attestation`) still serializes whole-project — exactly one
   spine train active, every other lane drained, integrating before the next —
   but its members **may pack together into one spine-only multi-WI traincar**.
   They never pack with `ordinary`, `protected`, `high-risk`, critique-bound,
   or checkpoint-bound work. **Ruled (owner, 2026-07-17): the whole
   spine-serial class packs as one batch — `attestation` rows included.** "If
   it's all drafted together and reviewed together, it should be attested
   together": the batch is one review scope and one ratification scope,
   mirroring the stage-2 gate pass. No attestation-singleton narrowing.
2. **Classifier + packing:** `schedule.py` `classify()` keeps returning
   `spine-serial`; the traincar packing (work-advisor, §7) gains the
   spine-only aggregation — ready spine-serial WIs cluster into a single
   serial train (hard-edge order inside the train; the train cap and the §7
   continuation re-checks still apply). Reason codes name the batch.
3. **Spec + doc sync:** `parallel-wi-dispatch.md` §4 rule 1 / §5.1 / §7 and
   any PROCESS_OPTIONS restatement updated to the amended rule, stated once.
4. **Tests:** the existing rule-1 pins updated; new pins — spine+spine packs,
   spine+ordinary never packs, the packed train still serializes
   whole-project, one spine train at a time.
