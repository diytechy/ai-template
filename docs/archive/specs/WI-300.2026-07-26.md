## The reframing

OI-9's option **(e)** proposed marking each rubric anchor `mechanized` or
`perceptual`, with each `mechanized` mark naming the test that owns it. That is the
right *instinct* expressed in the **wrong registry**. The kit already has a
structure whose entire job is "a requirement, decomposed, each part bound to a named
check": `SR → LLR → TC`. And the critique is already a TC method, not a parallel
system:

| | TC-051 | TC-053 |
|---|---|---|
| `Verifies` | `SR-050;LLR-051` | `SR-052;LLR-053` |
| `Level` | Integration | **Critique** |
| `Automated` | Yes | No |
| `Evidence` | 7 × `tests/test_gen_trajectory.py::test_…` | `docs/reviews/074-CRITIQUE.md` |

So "mechanizing an anchor" is not a new concept needing a new classification field.
It is **splitting an LLR and giving each child a TC with `Automated: Yes` and a
pytest node id in `Evidence`.**

**This exposes the actual defect.** `LLR-053`/`LLR-054`/`LLR-055` are each *one*
LLR whose `Detail` is a near-verbatim restatement of its SR — a paraphrase, not a
decomposition, which is precisely what this repo's decompose-don't-paraphrase rule
forbids. All four A-anchors collapse into one LLR with one all-or-nothing TC. **The
"must a train pass the whole rubric?" question is an artifact of an
under-decomposed LLR layer, not a critique-policy problem.** OI-9 has been debating
gate policy to work around a missing decomposition.

It is also the path the kit already documents. [`docs/rubrics/README.md`](../../rubrics/README.md):
*"When a critique round proposes a measurable sub-criterion, it routes through the
change-intake flow (process.md §5) to harden the TC — the critic never edits the
spine,"* and *"Not a second source of truth. The requirement lives in the
`SN→SR→LLR→TC` spine; the rubric is the judgment reference for the subjective slice
the TC can't pin."* `critique_ratchet_findings` (WI-068) exists to warn when a
critique round closes **without** doing this. The binding mechanism was never
missing — the rounds just have not been using it.

## The per-anchor pass (all 17)

`core` = the checkable claim that becomes a child LLR + automated TC. `residue` =
what genuinely needs eyes and stays in a slimmed rubric. Verdicts are proposals for
the ruling, not a fait accompli.

### SR-052 — accessibility ([rubric](../../rubrics/dashboard-accessibility.md), A1–A4)

| Anchor | Verdict | Core (child LLR + automated TC) | Residue |
|---|---|---|---|
| **A1** Keyboard reachability | mechanized | Parse the emitted HTML; every interactive element (tab buttons, `<details>`, SVG nodes with detail panels) is natively focusable or carries `tabindex` + a key handler | "sensible order" — thin; document order is assertable, *perceived* order is not. Proposed: assert document order matches emission order and drop the perceptual claim |
| **A2** Accessible names | mechanized | Every interactive element and meaningful graphic resolves to an accessible name; **no `role="img"` container encloses focusable descendants** (children-presentational conflict) | none — this is **WI-297** |
| **A3** No information by colour alone | mechanized | For every status/phase/type encoding the emitter declares, the rendered element carries a redundant text or shape cue beside the fill | none — the emitters own the palette, so the encoding set is enumerable |
| **A4** Text contrast | mechanized (partly done) | WCAG 2.1 AA arithmetic over every text/fill pair, both themes. `test_a4_theme_token_fills_behind_white_text_meet_the_floor` already owns the hub case | none — arithmetic |

**SR-052 has no perceptual residue.** All four anchors are structural or
arithmetic. → `Verification: Critique → Test`; the rubric is retired (kept as a
pointer file, per this repo's retire-don't-delete habit).

## Build finding (2026-07-25): most anchors are ALREADY mechanized — only the binding is missing

The first build slice surveyed `tests/test_gen_trajectory.py` before writing anything
new, and found the estimate above understates how much is already done. Tests owning
anchor cores **already exist, several already named after their anchor** — written by
past critique rounds converting findings into checks, exactly as the rubric README's
change-intake rule prescribes. What was never done is the **registry binding**, so the
critique kept re-judging properties a test already enforced on every commit:

| Anchor | Existing owning test(s) | Bindable now? |
|---|---|---|
| A1 | `test_a1_drill_leaf_blocks_are_keyboard_focusable` | partial — tabs are WI-273's subject |
| A2 | `test_svg_nodes_carry_escaped_title_tooltips` | no — **WI-297** open (`role="img"`) |
| A3 | `test_every_multifill_panel_emits_a_palette_bijection_legend` | partial |
| A4 | `test_a4_every_emitted_dashboard_contrast_pair_meets_floor`, `test_a4_no_sub_label_opacity_discount`, `test_a4_theme_token_fills_behind_white_text_meet_the_floor` | no — **WI-299** open (focus ring) |
| U1 | `test_u1_node_labels_share_one_type_scale` | no — **WI-295** open (Process tab) |
| U3 | `test_u3_sw_drill_has_a_legend_and_a_wired_detail_aside`, `test_u3_knowledge_edge_stroke_uses_the_shared_muted_token` | no — **WI-294** open |
| T2 | `test_knowledge_graph_collapses_above_type_threshold`, `test_how_sw_collapses_above_component_threshold` | **yes — bound** |
| T3 | `test_when_view_breadcrumb_restores_parent` | **yes — bound** |

Two consequences for the plan. First, the remaining work is **mostly registry
decomposition, not test authoring** — cheaper than the ruling assumed. Second, the
gating constraint is not test-writing but **open defects**: an anchor whose test
exists but whose defect is still open cannot be bound without a lax classification,
which is the one failure mode the ruling names. So the five queued render WIs are not
merely *compatible* with (f) — they are its critical path, and each should close by
binding its anchor's child rows.

**Hard constraint discovered while sequencing:** child rows cannot land ahead of their
tests via `Status: Draft`. `Draft` does exempt a row from the orphan rule and from
`--require-verified`, but `derive_gate.py` returns `G0` for a draft row, so a single
draft would **drop the derived gate off G3**. Every child LLR/TC must therefore land
`Verified`, with its test, in the same commit — which is the sequencing rule the
ruling already states, now enforced by the harness rather than by discipline.

## What this buys over (e)

1. **No new enforcement machinery.** `trace.py` already buckets TCs by `Verifies`
   and flags uncovered LLRs. (e)'s requirement that each `mechanized` mark name its
   test **is** the `Evidence` column; its safeguard that a removed test reverts the
   anchor to `perceptual` is just trace coverage failing. (e) would build a second
   registry expressing what `LLR→TC` already expresses — against the kit's
   single-source rule and the rubric README's own "not a second source of truth."
2. **No gate change at all.** `_train_is_render_surface` keys on
   `Verification=Critique` SRs. An SR carries that value only while a perceptual
   LLR/TC remains under it; empty the residue and the SR drops out of
   `_load_critique_srs` on its own. OI-9's "the gate is per-SR, not per-anchor" gap
   is **dissolved rather than solved** — no per-anchor granularity is ever needed.
3. **It clears all seven blocked/queued rows.** WI-292/294/295 deliver SR-053;
   WI-297/299 and blocked WI-273 deliver SR-052. Both SRs become `Test`-verified,
   so **none of them owe a CRITIQUE dispatch**. WI-272 (SR-038;SR-053) was never a
   critique finding and is unaffected either way.
4. **Less downstream change, not more.** The critique loop ships in
   [`PROCESS_OPTIONS.md`](../../../project-trajectory/PROCESS_OPTIONS.md) *"Critique
   verification"*. (e) would export a new anchor-classification schema to every
   adopting repo. (f) exports **no new concept** — it sharpens guidance the rubric
   README already gives.

## Sequencing, and the risks to weigh

- **Tests before the flip.** An SR's `Verification` must not change until every
  child LLR has a TC with real `Evidence`. Trace coverage enforces the LLR side;
  the ordering is a build discipline. Land the children, then flip.
- **Build each open row as *fix + the check that owns its anchor*** — already
  status.md's standing instruction. Each of WI-292/294/295/297/299 then *is* one of
  the child TCs above, so the decomposition is paid for by work already queued
  rather than by a separate migration.
- **Risk: narrowing is how this fails.** U3 and U4 are proposed as token/attribute
  parity, which is *narrower* than the prose anchor. That is a real reduction in
  what "uniform" means, and it is the honest cost of mechanizing them. If the owner
  judges the narrowing too lossy, those two stay perceptual and SR-053 keeps a
  rubric — the scheme degrades gracefully.
- **Risk: losing the independent eye.** SN-024 exists because "the agent didn't know
  how to judge it, it just shipped it." Flipping SR-052/SR-053 to `Test` removes an
  independent look at those properties. Mitigation: SR-054's critique still judges
  the **whole rendered dashboard** cold ("as a first-time reviewer"), so an
  independent eye passes over the artifact every dispatch — it simply no longer
  blocks on what a test owns. The eye is preserved; only its veto narrows.
- **`perceptual-stale` is unchanged and still correct.** It stays path-based on
  `gen_trajectory.py` and keeps firing for SR-054 — but against **one** rubric and
  one dispatch instead of three. Its cost drops by two thirds without a code change.
- **Anchor→WI provenance.** Findings currently name anchors in prose WI titles
  ("117-CRITIQUE U5"). Once each anchor is an LLR, that link becomes a registry ref
  and the provenance stops being free text.
