## Why

Reconcile classifies a train `blocked` whenever any `Blocked-WI` trailer
exists in its novel commits, with absolute precedence
(`agent_dispatch.py:2191-2192`)
— there is no supersede and no worker re-dispatch, so a train whose blocker
is CURED after the block can never retract it. Field event 2026-07-19: the
WI-229 worker completed the entire ratified migration, blocked honestly on a
base defect (the dupes-census race the parallel WI-237 train fixed within
the hour), and the train then dead-ended — the machine's only path was the
blocked disposition (itself broken, WI-238), which records the block and
releases the reservation for a FRESH train that would redo the finished
work from scratch. The completed, verified migration had to be integrated
manually.

## Scope

Trailer-ordering semantics: classification reads the train's novel commits
in order, and a **later** commit claiming the WI via the completion trailer
(`WI: <id>`) supersedes an **earlier** `Blocked-WI: <id>` — the train
classifies `ready-to-integrate` (or `resume`) again. An earlier completion
followed by a later block still classifies blocked (the block is newer
truth). A resumed worker session on a blocked train whose registry/base no
longer exhibits the BlockRef'd condition is the intended author of that
superseding commit — give the resume path a chance to run: reconcile should
dispatch a worker for a blocked train when the blocker's BlockRef names a
condition the worker can re-evaluate, rather than short-circuiting straight
to the disposition. Document the lifecycle (block → cure → supersede →
integrate) in the dispatcher spec §; the WI-232 idempotence pattern is the
precedent for recording enough state to avoid loops.

**Non-goals:** no auto-clearing of blocks by the dispatcher itself (only a
worker session or the owner retracts a block); no change to the
genuinely-blocked path (disposition + release, WI-238-fixed).

## Done-when

Suite green.
