# WI-281 — smoke tier true to its name: ≤ 60 s commit bar + a declared runtime budget

**WI:** WI-281 · **Status:** queued · **Delivers:** the meta commit bar
(tests/conftest.py WI-122 tiering + the declared bar in status.md); no spine SR
— test-harness layer, 150-row empty-`SR-Refs` precedent.

## Problem

The smoke tier is not a smoke test. Tiering is **opt-OUT** (WI-122,
`tests/conftest.py::SLOW_MODULES`): every collected test is `smoke` unless its
module is one of 15 named heavy end-to-end modules — so the commit bar runs
**1088 of 1378 tests (79%)**. Measured on the dev box (2026-07-23, 3.11.9 venv,
`-n auto`, three runs): **6:12 / 6:51 / 8:01 wall** — against a declared
"~3.3 min" in status.md that was already generous. The owner's directive
(2026-07-23): a smoke test answers *"is it basically alive?"* — the per-commit
bar should run in **≤ 60 seconds**, and the runtime should be **its own
declared budget item** so drift is caught, not re-discovered.

Why it matters: the bar's cost shapes behavior. Sessions pay it on every
commit (the session-protocol §3 commit bar), so a 7-minute "smoke" either slows
every loop iteration or tempts skipping the bar — both worse than a fast bar
plus the unchanged full suite at slice/phase close and in CI.

The WI-122 intent worth preserving: opt-out means a NEW test lands in the
commit bar by default ("never a false green" by omission), and `smoke`/`slow`
**partition** the suite (`test_smoke_tier.py` guards it). The intent worth
correcting: at 1378 tests the generous default has inverted the tier's
purpose.

## Approach

Two deliverables — the re-tier and the budget sensor. Measure first, then cut:

- **(a) Measure.** One `-m smoke --durations=0` run (plus per-module wall
  totals); record the module-level ranking in the close deliverable. Expected
  shape: the cost concentrates in modules driving subprocesses / bootstrapped
  scaffolds through `conftest.run_py` (subprocess-coverage overhead included) —
  the same class the existing 15 SLOW_MODULES already name.
- **(b) Re-tier to the budget.** Preferred: **keep the opt-out partition**
  (new tests still default into the bar) but move whole modules to `slow` by
  the measured ranking until smoke fits ≤ 60 s with headroom (~45 s target),
  drawing the line at the mechanical boundary where possible (subprocess/
  scaffold modules out; in-process unit modules in). Fallback if the budget
  cannot hold that way: flip to the **opt-IN `@smoke` posture the kit itself
  ships** (`project-trajectory/pytest.ini` uses opt-in marks with unmarked =
  full-suite-only — the meta-repo would then match its own template; note the
  erosion risk: new tests default OUT of the bar). Record whichever line is
  drawn and why in the spec/close notes.
- **(c) The budget item.** Declare the budget once and give it a sensor that
  bites, in the repo's growth-sensor idiom (`test_module_size_ratchet.py`,
  `test_dashboard_size_budget.py`):
  - **Declared home:** a `smoke-budget` entry alongside the tier declaration
    (docs/stack.ini `[tiers]` vicinity) — seconds for humans/CI, plus the
    deterministic proxy below.
  - **Deterministic sensor (always-on):** wall-clock asserts are
    machine-dependent and flaky, so the *ratchet* budgets what is
    deterministic — smoke-tier **membership** (collected-count ceiling, and/or
    the SLOW_MODULES line itself). Exceeding it fails the suite with the
    "raise deliberately or re-tier" message the size ratchets use.
  - **Wall-clock check (where timing is stable):** CI times the smoke step
    against the declared seconds budget (warn locally, enforce in CI — the
    build session picks warn-vs-fail per lane and records it).
- **(d) Update the declared surfaces** that state the bar's cost/shape:
  status.md "Bar (per commit)" (~3.3 min text), the `pytest.ini` header
  comment, `tests/conftest.py`'s WI-122 block, and the `session-protocol`
  skill §3 if it names the runtime. `test_smoke_tier.py`'s partition guard
  stays green throughout.

**Hard edges:** no test is deleted or weakened — re-tiered only; the full
suite (`-q -n auto`, slice/phase close + CI) is untouched; `smoke`+`slow`
remain a total partition.

## Interfaces

No cross-module seam — acts only within `tests/` (conftest tiering, the new
budget sensor, `test_smoke_tier.py`), `pytest.ini`, and the declared-bar prose
homes (docs/status.md, docs/stack.ini comment vicinity, the session-protocol
skill). Intra-module, test/harness layer. Nearest seam for reference: SR-007's
declared stack profile (`docs/stack.ini [tiers]` is already the tier
declaration check.py reads), unchanged in shape.

**Line drawn — the MECHANICAL boundary (preferred approach, not the opt-IN
fallback).** The opt-out partition is KEPT (a new in-process test still defaults
into the bar — the WI-122 "never a false green by omission" intent). The 27
modules above joined the 15 existing `SLOW_MODULES` (→ 42) on one rule:
*cost dominated by driving the heavy scripts (gen_trajectory / trace / check\* /
agent_loop) or bootstrapping a scaffold as subprocesses → runs at close + CI, not
per commit*. The retained smoke set is the in-process unit modules (decision /
routing / schedule / planning / registry-parse / dogfood-sync / the size &
budget ratchets). No test deleted or weakened; `smoke`+`slow` stay a total
partition (`test_smoke_tier.py`); the full suite is untouched. The opt-IN
fallback was **not** needed (the budget held with the opt-out posture intact).

**Result:** re-tiered smoke = **349 tests → ~7.5 s wall** at 24 cores (also
~8.1 s at 4 cores, ~10.5 s at 2 — startup-dominated, not core-bound; 3.11.9).
This is after the review-A rework re-tiered `test_session_stdin` (17 tests) to
slow; the build session's figure was 366 tests / ~7 s. Well under the 60 s bar
and the ~45 s headroom target.

**Budget item (split in two, per the spec).**
- *Declared home:* `docs/stack.ini [smoke-budget]` — `seconds = 60` (per-lane
  wall target) + `max-tests = 450` (the deterministic proxy, ~29% headroom over
  349 for in-process growth).
- *Deterministic sensor (always-on, GATES):* `tests/test_smoke_budget.py`
  independently collects `-m smoke` and asserts the count ≤ `max-tests`.
  **Bite-proven live:** with the ceiling temporarily set to 300 the real count
  (349) failed with the "re-tier or re-stamp" message; re-adding any one big
  slowed module (test_agent_loop ~113, test_gen_trajectory ~98, test_trajectory
  ~115) blows past 450.
- *Wall-clock check (CI, ENFORCES — changed in review-A rework):*
  `scripts/check_smoke_budget.py` times the declared smoke command against
  `seconds` and, in the `.github/workflows/test.yml` `smoke-budget` lane, runs
  `--mode enforce` (exit 1 on breach). The build session chose WARN, fearing a
  hard time-assert would flake on GitHub's fewer-core runners; the rework
  re-measured across worker counts and the fear did not hold — the re-tiered tier
  is startup-dominated (~7.5 s/24 → ~10.5 s/2 cores), so 60 s keeps ~5x headroom
  on any real runner. A breach therefore signals a real regression (a heavy
  subprocess/scaffold module back in the bar — which the deterministic membership
  ratchet also catches), not runner noise. `--mode warn` remains the report-only
  local default. This resolves review-A finding 2 without weakening the budget.

## Review A rework (2026-07-23) — CHANGES-REQUESTED, 4 findings

- **Finding 1 (MAJOR, Windows smoke red) — FIXED in scope.** The re-tier had left
  `test_session_stdin` in the bar, and one of its tests
  (`test_run_session_codex_reads_last_message_not_transcript`) fails on a Windows

  re-tiering WI. Taking the reviewer's named in-scope alternative, this module —
  which drives the `run_session` subprocess/shim transport and hosts those reds —
  was re-tiered whole into `conftest.SLOW_MODULES` (module-granular, like every
  entry). It still runs at close + CI, where the full suite exposes the red for
  WI-275; the per-commit bar is now green on every supported OS. No test deleted
  or weakened. Real output: `349 passed in 7.48s` (`-m smoke -n auto`, Windows,
  3.11.9; was `365 passed, 1 failed` before the re-tier).
- **Finding 2 (MAJOR, CI wall-clock ran `--mode warn`) — FIXED in scope.** The
  `smoke-budget` lane now runs `--mode enforce` (exit 1 on breach). The build
  session's flakiness fear (fewer-core runners) was tested by re-measuring across
  worker counts: ~7.5 s/24, ~8.1 s/4, ~10.5 s/2 — the tier is startup-dominated,

- **Findings 3 & 4 (MAJOR, status.md prose / row close + spec archive) — DEFERRED
