# WI-087 — Hierarchical, phase-aware When & How drill-down views

**Status: queued** (filed 2026-07-12, phase v2; needs a **new SR** + owner G1
sign-off — the requirements below are the owner's stated intent, to be ratified).

## Goal

Give the dashboard's **When** (roadmap DAG) and **How-SW** (module) views a
count-thresholded, click-to-explode hierarchy — "Simulink-style" blocks a viewer
clicks into — so a large project reads top-down (phase → workstream → work item;
component → module) instead of as one dense graph. And surface the delivery
**Phase** on the When view.

## Builds on (the foundation already exists)

- **When:** campaign binning (WI-074) already renders collapsed `<details>`
  campaign containers with **campaign-crossing edges aggregated** to one deduped
  container-to-container edge. This WI adds tiers above/beside it.
- **How-SW:** component containment (WI-073) already renders a containerized top
  view (≤ 10 bound), expandable members, and **boundary-aggregated
  cross-component seams**. This WI generalizes the interaction.
- So "connections inherited for parents from children" is an **existing idiom**
  (edge aggregation to the container) — apply it at each new tier.

## Owner requirements (to ratify at G1)

**When view — tiered, count-thresholded drill-down:**
- If **> 3 phases**: the view **starts at phase blocks**; click a block to
  explode it.
- If **> 3 workstreams** (within a phase, or at the top when phases ≤ 3): show
  **workstream blocks**; click to explode into individual work items.
- Bottom tier: the individual-WI DAG (today's view).
- **Parent connections inherited/aggregated** from children (the WI-074 idiom).
- **Phase encoding** on the When view — color, parent-grouping, or both
  (**open question**, decide at G1).

**How-SW view — tiered drill-down:**
- If **> 3 components**: **start at component blocks**; click to explode into the
  software-module items. Parent connections inherited from children (WI-073).

**Interaction:** click-to-explode blocks (a Simulink flow diagram a viewer clicks
into), an evolution of today's native-`<details>` expand. Self-contained,
byte-deterministic, `--check`-stable (the WI-070/073/074 discipline).

## Open requirements questions (for the G1 review)

1. **Grouping composition.** The When view already groups by **Campaign**
   (WI-074); this adds **Phase** and **Workstream** tiers. How do the three
   compose — Phase ⊃ Workstream ⊃ WI with Campaign orthogonal, or does Workstream
   (or Phase) replace Campaign here? The owner named phase → workstream → WI.
2. **Phase encoding** — color vs. grouping vs. both.
3. **"Explode" semantics** — in-place expand (today's `<details>`) vs. a
   drill-in / zoom navigation.
4. **Thresholds** — the "> 3" collapse rule per tier, and how it composes with
   the existing How-SW `TOP_VIEW_MAX = 10` right-sizing bound.

## Verification

A generated view → a **Test** TC (deterministic render, `--check`-stable, the
tiering fires at the > 3 thresholds and is flat below them, aggregated parent
edges match the union of child edges). If an interaction/authored element resists
a data assertion, a **Critique** TC covers its fidelity (the WI-085 pattern).
