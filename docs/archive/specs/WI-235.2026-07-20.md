## Why

WI-231's conflict auto-resolution keys off `GENERATED_ARTIFACTS`
(`agent_dispatch.py:987-1000`)
— a module-level tuple hardcoding this kit's artifact set (dashboard, OKF
bundle, arch-map block, status block). That is *declaration*, not discovery:
correct for every repo that keeps the scaffolded defaults, but a downstream
repo with its own generated artifacts (or one that relocates a default)
cannot teach the integrator without editing vendored kit code — exactly the
kind of fork the kit exists to avoid. The kit already has the pattern for
this: `docs/stack.ini` declares per-repo commands; the generated set is the
same species of repo-local fact.

## Scope

Move the tuple's rows (path · optional marker pair · regenerator kind) to a
declared home in `docs/stack.ini` (a `[generated]` section), scaffolded by
`bootstrap.py` with the current defaults so a fresh repo behaves identically.
`agent_dispatch` reads the declaration at composition time (worktree's own
`stack.ini` — the integrate worktree may differ from the primary);
**absent section ⇒ the built-in defaults; malformed row ⇒ fail closed to
park** (an unparseable declaration must never widen auto-resolution). The
skills-index exclusion ruling (WI-231) holds: the scaffolded defaults do not
include it, and the section comment records why. ADOPTING.md §6 gains one
line: the section is project-owned on re-sync.

**Non-goals:** no dynamic discovery (scanning for markers is guessable and
guessing widens silent auto-resolution — the safety direction is declared-
only); no change to the resolution/union mechanics themselves.

## Done-when

Regressions prove: a repo-declared extra artifact auto-resolves where it
previously parked; a removed default parks again; a malformed section row
parks (fail closed) with a non-blank reason; an absent section reproduces
today's behavior byte-for-byte; bootstrap scaffolds the section and
`test_bootstrap.py` lists it. Suite green.
