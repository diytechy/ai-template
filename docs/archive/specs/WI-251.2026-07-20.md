# WI-251 — Spec-lifecycle close side: absorb-verify sweep + fail-closed R-F

> **ARCHIVED 2026-07-20 — done.** Spec-of-record for **WI-251** (`done`; deliverable in `docs/requirements/work-items.csv`, session record + 109-REVIEW-A verdict in `docs/log.md` / `docs/reviews/109-REVIEW-A.md`). Archived at close per the lifecycle its own rule R-F now enforces.

**WI:** WI-251 · **Status:** queued · **Delivers:** SR-068 extension (or a new
SR isolated from it — builder's call at decomposition)

## Problem

The spec-of-record lifecycle ([specs README](../../../project-trajectory/specs/README.template.md) —
template-only; this repo scaffolds no `docs/specs/README.md`, part of the gap)
is enforced on one side only. R-E ([check_trajectory.py](../../../project-trajectory/scripts/check_trajectory.py)
`spec_ref_findings`) mechanizes the *open* half — an open WI names a resolvable
spec — but the *close* half ("Deliverable filled, `SpecRef` cleared, spec
archived") lives in prose alone, and autonomous close sessions have skipped it
since the 2026-07-13 campaign closes. Measured 2026-07-20: **137 done WIs still
carry a non-empty `SpecRef`** and **~60 of the 67 files in `docs/specs/` belong
to closed WIs**. The repo's own WI-243 lesson applies: prose rules and warns get
skipped by autonomous agents; only a gate failure is agent-proof.

Owner constraint (2026-07-20, this WI's mandate): archiving must not orphan
knowledge. A spec's durable content — capabilities, design rationale, seams —
must have a **living home** (the SR/LLR/TC spine, [architecture.md](../../runtime-flows.md),
[interfaces.csv](../../requirements/interfaces.toml)) *before* the file leaves the
working surface. That is already the WI-000 Done-when contract ("the spine
reflects it"); this WI verifies it retroactively for the backlog and mechanizes
the checkable halves going forward.

## Approach

Two parts, sweep before rule (the rule must land on a clean registry):

1. **Absorb-verify sweep (reviewer-tier judgment, per spec).** For each live
   `docs/specs/` file whose citing WIs are all closed: confirm its durable
   content has a spine/architecture home — top up SR `Rationale`, LLR `Detail`,
   `architecture.md`, or `interfaces.csv` where it does not (decompose, don't
   paraphrase; most specs will need nothing — their content landed at build) —
   then archive to `docs/archive/specs/` with the close date appended and the
   WI ids noted inside (the existing idiom). A shared effort doc archives only
   when its **last** citing WI is closed; `deferred` is open, so e.g.
   `WI-065.md`, `WI-108.md`, `research-knowledge.md` stay. Clear `SpecRef` on
   every done row — including refs into `docs/reviews/`, `docs/plans/`,
   `docs/log.md` (nothing to archive there; the pointer still rots). The sweep's
   per-spec disposition (absorbed-where / nothing-to-absorb) goes in the log,
   not the registry.

2. **Mechanical rule R-F in `check_trajectory.py`** (extending SR-068's
   coherence family), two findings:
   - a **done** WI with a non-empty `SpecRef`;
   - a live `docs/specs/` file (README/`WI-000` excluded) with **zero open-WI
     citations** — covers both "cited only by done WIs" and "uncited residue".

   Route both through the strict-promotable findings loop (the WI-243 /
   run-state precedent): **WARN at the commit bar, ERROR under `--strict`**,
   which `check.py` adds at G2/G3 — a rotting spec surface cannot reach a green
   gate, while a plain commit stays warn-first. Downstream blast radius: the
   rule ships in the kit script, and an adopter with accumulated done+`SpecRef`
   rows reddens **at their next G2/G3 gate**, not at every commit — that is the
   rule working, but flag it in `PROCESS_OPTIONS.md` ("Spec-of-record": name
   R-F beside R-A/R-E) and the specs-README lifecycle so the migration is
   announced, not silent. Opt-out remains `docs/trajectory-check`.

3. **Dogfood the scaffold (owner ruling 2026-07-20: this repo follows its own
   template).** `docs/specs/` predates WI-053's spec-of-record machinery, so
   the two files bootstrap ships downstream ([bootstrap.py](../../../project-trajectory/scripts/bootstrap.py)
   MAPPING → `docs/specs/README.md` + `docs/specs/WI-000.md`) were never
   backfilled here — measurably causal: 57/58 live specs kept the Done-when
   shape but **0** carry the close-ritual boxes; agents copied neighboring
   specs, not the absent exemplar. Copy both in, and extend
   `tests/test_dogfood_sync.py` to gate them against the templates (STRUCTURE
   must not drift). Resolve first the **template contradiction this exposed**:
   `WI-000.template.md`'s banner says "delete on first real entry", but the
   README links `WI-000.md` twice as the shape reference (obeying the banner
   breaks the README) and the kit's `-000` convention is *inert-and-stays*
   (CLAUDE.md; `check_trajectory` ignores the `WI-000` row). Fix the banner to
   the permanent-exemplar reading; R-F excludes both names.

   The 2026-07-20 full-MAPPING audit (91 targets, owner-triaged) found two more
   in the same class — fold them in:
   - **`docs/rubrics/README.md` + `rubric-000.md`**: the dir exists with 7 real
     rubrics but the convention README + `-000` exemplar were never backfilled
     (the identical copied-from-neighbors risk).
   - **`.githooks/commit-msg`**: only `pre-commit` of the kit's three hooks is
     installed; commit-msg carries the **always-on secrets floor** over commit
     *messages* (its header: pre-commit runs before the message exists — a
     credential pasted into a body goes unseen until push). Install it.
     `pre-push` stays out: it is the privacy-checked-repo backstop and this
     repo declares `privacy-check` off — record that, don't install it.

   Make the audit a standing invariant: extend `tests/test_dogfood_sync.py` to
   walk `bootstrap.MAPPING` and assert every destination exists **or** is on a
   declared-omissions list (test-side constant or a short note in
   `architecture.md`'s self-adoption section — builder's call), seeded with the
   owner-ruled omissions: the 35 in-place kit scripts, `docs/process*.md`
   masters, `run.*`/`onboard.*`/`setup`/`check` wrappers + `run_menu.py`,
   `check.yml` (test.yml's gate job is the equivalent), `docs/blackout`
   (absent = disabled by spec), `docs/interfaces.md` (cross-project only),
   `GEMINI.md`, `.githooks/pre-push`, the off-spine PB/procurement/assets
   registries, and `docs/plan.md` (superseded here by the trajectory layer +
   parallel dispatch — each with its one-line reason).

4. **Docs:** `PROCESS_OPTIONS.md` R-rule list + spec-of-record section; specs
   `README.template.md` lifecycle sentence naming the enforcement;
   [enforcement-audit.md](../../enforcement-audit.md) gains the row (close-side
   lifecycle: Harness for the mechanical halves, Reviewer for absorb-quality —
   the honest gap: no check can verify absorption *happened well*, only that
   the pointers cleared).
