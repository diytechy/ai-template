## The coverage model (ruling recorded)

The **continuous** contradiction net is *change-scoped by design*: every diff
that adds or changes SN/SR/TC rows obliges the independent reviewer to sweep
the new rows against the ENTIRE existing registry for "contradiction, overlap,
or attribute/limit conflict" (the embedded REVIEWER_PROMPT). That gives
inductive pairwise coverage — each pair was checked when its newer member
landed — at diff-review cost. This model is hereby a **recorded decision**
(2026-07-17, owner sitting; log Decisions), not an accident of prompt shape.

What it structurally misses: **old-vs-old** — contradictions between rows that
both predate the sweep prompt, and *interpretation drift* accumulated across
many individually-sane amendments. No driven task audits the unchanged
registry as a whole.

## Scope

A **driven, recurring whole-registry audit** — reviewer-class (semantic
contradiction is not mechanizable), so the deliverable is a rubric + a wired
occasion, not a checker:

1. **Rubric** `docs/rubrics/registry-contradiction-audit.md` (the
   `docs/rubrics/` pattern): all-vs-all scope over SN/SR (LLR/TC where they
   restate limits); anchors = direct contradiction, semantic overlap /
   double-home (the anti-duplication rule applied to meaning), attribute or
   limit conflict, and drifted-interpretation (two rows using one term in
   incompatible senses). Findings route as WIs / registry amendments through
   normal intake — the audit never edits the spine itself.
2. **Occasion:** at **phase close** (with the gate bar) and **before
   G-Final**. Stated once in PROCESS_OPTIONS (the "Trajectory / work-items
   layer" or gate-cadence home) with an applies-when; per-commit stays
   change-scoped (the continuous model above is untouched).
3. **Execution:** one independent fresh-context session (the S8 posture:
   never the implementer; redacted to the registries + rubric) writing a
   recorded verdict — `docs/reviews/` `*-AUDIT.md`, the CRITIQUE verdict-file
   idiom (`VERDICT: APPROVE|CHANGES-REQUESTED findings=N`). Manual dispatch
   is acceptable first; loop wiring at phase close is an explicit follow-up
   slice if the manual round proves the shape (the WI-190 precedent).
4. **First run:** execute one real audit over the meta repo's own registry
   (25 SN / 66 SR) as the dogfood; its verdict is this WI's primary evidence.

**No new SR at filing** (process-layer task + rubric — prose surfaces; the
WI-129/open-items precedent). If loop wiring lands as a coordinator behavior,
that slice drafts its requirement then.

## Interfaces

Prose + rubric + a review-session occasion — **no cross-module seam** (the
PROCESS.md §8 intra-module escape: nothing here crosses a module boundary).
The optional loop-wiring slice acts on the existing coordinator review
dispatch (its seams declared at that slice, not invented here — the WI-191
rule).

## Done-when

- [ ] The rubric exists with numbered anchors; PROCESS_OPTIONS states the
      occasion once with an applies-when.
- [ ] One real audit of the meta registry is recorded (verdict file + log
      entry), findings triaged into WIs or explicitly dispositioned.
- [ ] The change-scoped continuous model is recorded in the log's Decisions
      (done at filing — this spec is its pointer).
- [ ] `check_docs` / `check.py` at the derived gate stay green.

## Non-goals

- No mechanical semantic-contradiction detector (the `check_dupes` textual net
  already exists; meaning-level judgment stays reviewer-class).
- No change to the per-diff reviewer sweep or its prompt.
- Not a standing G-gate: the audit is an occasion-driven review, warn-first;
  promoting it to a gate criterion would be its own ruled change.
