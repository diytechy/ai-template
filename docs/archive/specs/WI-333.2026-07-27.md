## The observation, and the correction that matters

[`docs/stack.ini`](../../stack.ini)'s `[step:lint]` runs
`ruff check {src} {tests}`. That command reports **20 findings**.

The first reading was "pre-existing debt at a gate we have not reached". **That
was wrong, and the dating is the finding.** `check.py --gate G3 --jobs 0` was
`RESULT: PASS` on **all 17 steps** on 2026-07-25 — *after* a format/lint fix pass
(log, 2026-07-25). Every one of these 20 findings landed **after** that green:

| Rule | Count | Where | Entered |
|---|---|---|---|
| `F402` module `html` shadowed by a loop variable | 13 | `tests/test_gen_trajectory.py` | `44024b3` (WI-318, 2026-07-26) — `for label, html in _every_emitter_document(...)` |
| `F821` undefined name `pytest` | 2 | `tests/test_trace.py` (lines 1525, 1672) | 2026-07-26 (`4cc61fa`, then a second site) |
| `F401` unused import | 5 | `gen_open_items.py` (`io`) + 4 test modules | `41b228a` / `faa3cba` / `c714e1e`, 2026-07-26–27 |

**Why nobody saw it.** `lint` is a **G3-only** step. From 2026-07-26 the
`Modified` re-attestation window held the derived gate at **G2**, which drops
`lint`, `dupes` and `--require-verified` from the bar by design — so twelve
commits went green over a step that was no longer running. The window did not
cause the regression; it *hid* it, and the moment the sitting flipped the rows
back to `Verified` the gate returned to G3 and the step came back red.

That is the more valuable half of this WI: **a deliberately lowered bar is a hole
regressions fall into.** `status.md` already warned "don't let it sprawl" about
the window's duration; this is the concrete cost of a five-day one. Consider
whether the G3-only steps should still run **advisory (warn, non-gating)** while
a window is open, so a regression surfaces at the commit that causes it instead
of at the sitting that closes the window.

19 of the 20 are in `tests/`; one (`io`) is in a kit script.

## Why this is not purely cosmetic

**`F821` is a latent defect, not a style nit.** Both sites read:

```python
git = _sh.which("git")
if not git:
    pytest.skip("needs git on PATH")
```

`tests/test_trace.py` never imports `pytest`. The guard is there to skip when git
is absent — and on the machine where that is true it raises `NameError` instead
of skipping, so the *safety net itself* is what fails. It has never fired because
every machine that has run this suite had git on `PATH`. That is the same shape as
the traps this repo keeps paying for: a guard nobody has watched fail.

Triage `F821` **first**, and against the two sites rather than the rule name —
decide whether the import is missing or the branch is dead, and say which.
