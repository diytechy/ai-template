## Why

WI-220's `_salvage_round_evidence` scans only `git status --porcelain --
docs/plans`. On the one error path that fires *after* the disposition commit
succeeds — `dual_plan_disposition`'s stale CAS
([agent_dispatch.py:1133](../../../project-trajectory/scripts/agent_dispatch.py#L1133),
an external actor moved the integration ref mid-round) — the DP-* evidence is
already committed, porcelain is clean, salvage copies nothing, and the
`reset --hard old_head` discards the round's only output (reflog-only
recovery, then the WI is quarantined). The salvage machinery gives false
confidence on exactly the path where a full ~8–14-session round is most
expensive to lose. `integrate_train`'s CAS-stale path shares the shape but its
real work survives on the train branch — the fix should cover it anyway for
uniformity (docs-only registry edits are still discarded there).

## Scope

Extend `_salvage_round_evidence` to also collect round names from
`git diff --name-only <old_head> -- docs/plans` when the caller supplies
`old_head` (the reset target `_reset_failed_disposition` already holds):
the diff names every tracked `docs/plans/DP-*` path that differs from
`old_head` — committed, staged, or unstaged — and the files are still on disk
because salvage runs *before* the reset, so the existing copy-from-worktree
mechanics need no change. The porcelain scan stays (it alone sees untracked
files). `_reset_failed_disposition` forwards its `old_head`; no call-site
changes. Best-effort contract unchanged: a failed diff degrades to the
porcelain-only scan, and a salvage failure never masks the original error.

**Non-goals:** the quoted-path blind spot stays WI-224's; no journal/schema
changes; no change to which paths reset.

## Done-when

A regression proving the previously lost case: a disposition whose DP-*
evidence is **committed** past `old_head` with a clean porcelain, driven
through the stale-CAS error path, ends with the evidence under
`out/dispatch/salvage/<train>/` and `"round evidence salvaged to"` in the
returned detail — failing pre-fix. Existing salvage/disposition tests
unchanged and green; LLR-064's Detail amended (uncommitted → uncommitted or
committed-past-reset-target); smoke bar green per commit, full suite at close.
