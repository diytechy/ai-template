## Why

`_salvage_round_evidence` parses `git status --porcelain` (and, after WI-222,
`git diff --name-only`) as plain text. With git's default `core.quotepath=true`,
a `docs/plans/DP-*` path containing non-ASCII or special characters is emitted
C-quoted (`"docs/plans/DP-\303\251..."`), so the leading `"` defeats the
`parts[:2] == ["docs", "plans"]` guard and that round is silently not
salvaged. Rename parsing (`" -> "`) makes the same unquoted-output assumption.
Round slugs are kit-generated ASCII today, so the exposure is downstream repos
with non-ASCII WI titles feeding slugs — real but narrow.

## Scope

Harden the scans with NUL-terminated output (`status --porcelain -z`,
`diff --name-only -z`) parsed on `\0`, which git never quotes — or, if the
`-z` status format's rename records complicate the shared parser
disproportionately, run both commands with `-c core.quotepath=false` and note
the residual control-character caveat in the docstring. Keep the best-effort
contract: parse failures degrade to salvaging nothing, never raise.

## Done-when

A regression with a non-ASCII DP-* round slug (skipped on filesystems that
cannot encode it) proving the evidence is salvaged; existing salvage tests
green; smoke bar green.
