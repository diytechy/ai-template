# WI-331 — Re-tune the agent-facing guidance for the standard model

**Status: queued** (owner-raised 2026-07-27, after reading Anthropic's
prompting guidance for the model this repo now routes to by default).

## Why now

The owner's framing: *"this model will be the standard going forward, so I don't
want the tooling to constrain it — but I also want the tooling to stay
appropriate for other agents."* Both halves are load-bearing, and the second one
is what makes this a careful edit rather than a copy-paste.

An audit against the published guidance found the repo **already aligned on
four of five axes**, one of them non-obviously:

| Guidance | Repo state |
|---|---|
| Constrain task scope | `CLAUDE.md` already says it, near-verbatim |
| Keep prose terse | `PROCESS.md` §5's *"literal, terse"* |
| Don't put severity filters in a review prompt | **Zero occurrences.** `REVIEWER_PROMPT` says severity-*ordered*, and *"an APPROVE must mean you tried to break it"* — coverage-first |
| Keep thinking enabled | Never disabled anywhere |
| Cap delegation | **The gap — see below** |

The reviewer-prompt row is worth recording: the published guidance names
conservative-reporting instructions as the thing that silently depresses review
recall, and this repo arrived at the opposite framing independently.

## The three findings

### 1. `PROCESS.md` frames delegation as a duty (the real one)

The in-flight tiering paragraph says the driver **should** step down and step
sideways to subagents. That wording was written when models under-delegated; the
current guidance says the opposite — this model delegates readily on its own, and
prompts that push for more delegation multiply cost and latency.

`AGENTS.template.md` is already the right shape (*"Spawn subagents
**deliberately**"* plus three named cases). Only the `PROCESS.md` **should**
needs softening — to a when-it-pays-off condition, which is model-neutral advice
rather than tuning for one model.

### 2. No deterministic spawn cap

The dispatcher bounds concurrency (`--jobs` default 2, traincar cap 4), but
nothing bounds **in-session** subagent spawning. The published guidance
recommends a deterministic cap for cost-sensitive workloads; the kit has none.

### 3. The effort pins predate the current model

`docs/agents.csv` pins `high`/`xhigh` — the right ballpark, and it matches the
recommendation for demanding coding and agentic work. But those values were set
for an earlier model, and the guidance is explicit that carried-over effort
defaults should be re-swept: the lower levels are unusually strong now, and
effort is the primary cost/latency lever.

## Deliberately NOT changed

**The self-review tier stays.** `PROCESS.md` §6 keeps *"Medium: self-review
against the gate checklist"* despite guidance to delete redundant verification
instructions, because the two are about different things. The guidance says the
model verifies its own **work**; what it cannot verify is its own **claims** —
126-REVIEW-A found eight statements in this repo's own registries that were
false, including a mechanism described backwards. An author cannot catch that
class, because the author believes it. The risk-tiered rule stays; what changes
is that the limit is now recorded beside it.

## The architectural constraint — where the tuning may live

**No model-specific tuning in `AGENTS.template.md` or `PROCESS.md`.** Those ship
to every adopter and are read by every agent family; this repo already routes
work to three (`docs/agents.csv` carries ANTHROPIC, OPENAI and OPENCODE rows, and
the last three independent reviews ran on a non-Anthropic critic). A cap tuned
for one model is noise — or a mis-tune — for a model that under-delegates.

The kit already has the seam: **`docs/agents.csv`'s `Env` column is per-model**,
which is where the effort pins already live. Model-specific behaviour goes there
or in the host `CLAUDE.md`; the shipped process docs stay agent-neutral. The
`PROCESS.md` delegation edit qualifies only because "delegate when it pays off"
is true of every agent.

## Done-when

- [ ] `PROCESS.md`'s step-down/step-sideways **should** is a when-it-pays-off
      condition, stated model-neutrally, with the byte baseline re-stamped.
- [ ] A deterministic in-session spawn cap is either declared (and where it
      lives is recorded) or explicitly ruled out with the reason.
- [ ] The self-review tier carries its recorded limit: it catches wrong work,
      not wrong claims — that is what the independent reviewer is for.
- [ ] The effort pins in `docs/agents.csv` are re-swept against real work, and
      the chosen values carry their reason.
- [ ] `AGENTS.template.md` and `PROCESS.md` remain free of model-specific
      tuning; anything model-specific lands in `agents.csv` `Env` or the host
      `CLAUDE.md`. Verified by re-reading both for a vendor or model name.
