# WI-209 — M2: dual-plan auto-dispatch + the quiet-park auto-page

> **ARCHIVED 2026-07-20 — WI-251 spec-lifecycle sweep.** Spec-of-record for **no registry citer (working notes for the effort it accompanies)** (all `done`; deliverables in `docs/requirements/work-items.csv`, session records in `docs/log.md`). Absorb-verified before archiving: every durable decision has a live spine/architecture/process home (dispositions in the log, 2026-07-20 entry).

**Status: queued (filed 2026-07-17, owner-directed). Hard predecessor: WI-208
(the dispatcher must be the live default before its auto-dispatch behavior is
the load-bearing path).**

## Problem

A `PlanMode=dual` WI on the frontier is **inert until a human runs
`agent_loop --dual-plan <WI>`**: the fail-closed refusal covers only the
worker path, `schedule.py` knows nothing of `PlanMode`, and no path pages. So
the dual row — and its whole dependent subtree — can park *quietly* (owner
finding, 2026-07-17 sitting). SR-066 already **rules** the residual: "for
frontier auto-dispatch (deferred to the --jobs dual-dispatch WI) a
PlanMode=dual row is ruled to classify as a single-WI traincar — the SR-058
high-risk/critique class **derived from the PlanMode signal**, never packed
with other WIs." This is that WI.

## Scope

1. **Classifier derivation (the WI-201 ruling wired):** `schedule.load_wis`
   reads the `PlanMode` column (absent ⇒ empty, unchanged behavior);
   `classify()` derives `SCHED_SINGLE_WI` from `PlanMode=dual` with a new
   reason code (`single-wi:dual-plan`) — from the signal itself, never a
   second hand-set `SafetyClass` cell (single-source; a *contradicting*
   declared SafetyClass on a dual row quarantines `unclassified`, the
   existing cross-check posture). Never packed with other WIs.
2. **Dispatcher auto-dispatch:** when the build-out loop selects a traincar
   whose single constituent is a dual row, it runs `run_dual_plan_round`
   (the WI-199 engine — reuse, no new round logic) instead of spawning a
   BUILD worker: reserve the WI as usual, run the round, and on SELECT the
   filed child WIs enter the registry through the round's existing artifact
   path; on PAGE apply `plan_round.page_action(gate_policy)` exactly as the
   `--dual-plan` CLI entry does (autonomous → design-check routing, attended
   → NEEDS-HUMAN — the pause-free-under-autonomous invariant holds). The
   worker-path fail-closed refusal stays as the backstop.
3. **The quiet-park auto-page (the legacy-path half, until WI-210 retires
   it):** in the serial resume driver, when the derived frontier's only
   actionable rows are `PlanMode=dual`, the loop surfaces the ask instead of
   idling: run-state note naming `--dual-plan <WI>` (the WI-127 headline
   idiom). Cheap and honest — a dual row must never park silently on either
   path.
4. **SR-066 amendment:** drop the "deferred to the --jobs dual-dispatch WI /
   classifier wiring deferred" clauses from Requirement + Rationale (they
   describe this WI as unbuilt); the AC gains the auto-dispatch acceptance
   (a fixture dual row on the frontier auto-runs the round under `--jobs`,
   never packs, and the swap-disagreement PAGE still honors gate-policy).
   Spine change → the TC (TC-070…076 family, whichever carries the SR-066
   AC) extends in the same commit.
5. **Tests:** classifier derivation (dual ⇒ single-wi + reason; contradicting
   SafetyClass ⇒ unclassified); packer never packs a dual row; dispatcher
   fixture — a dual row auto-runs the round end-to-end (the
   test_agent_loop_dualplan.py harness has the round fakes); the legacy-path
   auto-page fires when only dual rows are actionable; the `--dual-plan` CLI
   entry unchanged.

## Interfaces

Acts on the declared seams **IF-053/IF-054** (`schedule.py`'s classifier/
frontier contract — the `PlanMode` read extends the same rows of record) and
the dual-plan round seams **IF-058…IF-061** (the WI-199 engine consumed as-is).
No new seam expected; any surfaced at build files `Proposed` with its
nearest-IF rationale (WI-191).

## Done-when

- [ ] A fixture `PlanMode=dual` row on the frontier under `--jobs` auto-runs
      the full round unattended and files the selected child WIs; it never
      joins a multi-WI traincar.
- [ ] The serial driver pages (run-state note naming `--dual-plan`) when only
      dual rows are actionable — no silent park on either path.
- [ ] SR-066's deferral clauses are gone; its AC covers auto-dispatch; the TC
      moved in the same commit; `trace.py --strict` green.
- [ ] Full suite + `check.py` at the derived gate green.

## Non-goals

- No change to the round engine's internals, caps, redaction, or PAGE
  semantics (WI-199/SR-066 own those).
- No multi-dual concurrency (one round at a time — the single-WI-traincar
  class serializes it naturally).
