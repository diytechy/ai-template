# WI-252 — Demote the plan/build cadence: mutual exclusion with the trajectory layer

> **ARCHIVED 2026-07-20 — done.** Spec-of-record for **WI-252** (`done`; deliverable in `docs/requirements/work-items.csv`, session record + 109-REVIEW-A verdict in `docs/log.md` / `docs/reviews/109-REVIEW-A.md`). Archived at close per the lifecycle its own rule R-F now enforces.

## Problem

`docs/plan.md` (the plan/build session-block cadence,
[PLAN.template.md](../../../project-trajectory/PLAN.template.md) +
`PROCESS_OPTIONS.md` "Plan/build cadence") is fully duplicated by the
trajectory / work-items layer wherever that layer is enabled: a plan block =
deliverable + done-when + size + tier hint, and a WI row + spec-of-record
carries the same content mechanized (`Predecessors` = sequencing, `BuildTier` =
tier hint, the spec's Done-when = the observable done-when, R-E gates the
hand-off exists). No script consumes `docs/plan.md` (grep-verified: zero
references in `agent_loop`/`agent_dispatch`/`agent_session`; its mechanized
bounce rode the retired `run-phase` file, WI-180). The kit currently ships both
layers with no statement of precedence — two "what's next and how" surfaces, a
violation of its own single-source-of-truth rule. Owner ruling 2026-07-20:
**demote, don't delete** — the cadence stays as the zero-tooling rung (attended
sessions, no registries, pure markdown), and the two become explicitly mutually
exclusive.

## Approach

Smallest edits that state the precedence, all prose:

1. **`PROCESS_OPTIONS.md` "Plan/build cadence"** — the section's applies-when
   becomes: applies when the **trajectory / work-items layer is not enabled**;
   one sentence pointing forward ("enabling work-items.csv + SpecRef supersedes
   `docs/plan.md` — the WI DAG + specs are the plan").
2. **`PROCESS_OPTIONS.md` "Trajectory / work-items layer"** — the reciprocal
   sentence (this layer supersedes the plan/build cadence's plan file).
3. **`PLAN.template.md`** — one header line: skip/delete this file if the
   trajectory layer is enabled.
4. Byte-budget-guard before/after on `PROCESS_OPTIONS.md` (budget-watched);
   push any overflow nowhere — the edit is a few lines net.

Out of scope: deleting the template, bootstrap MAPPING changes, ADOPTING.md
restructure (its plan.md mentions stay valid — the doc describes the file for
repos that use it).

## Interfaces

No cross-module seam — process-doc prose only.
