## 4. Traps this session paid for — do not re-pay them

1. **Do not put backslashes in a heredoc'd Python script.** The shell collapses
   `\\` → `\`, and `Git\bin` became `Git` + **BACKSPACE (0x08)**, which was written
   into the WI registry and corrupted the exact string WI-326 exists to make
   actionable. Every G3 step passed over it. Write scripts to a scratch file and
   run them; `Write`/`Edit` for anything with escapes. (WI-349's guard now catches
   the class.)
2. **`Path.write_text(newline=…)` is 3.10+. `Path.read_text(newline=…)` is
   3.13+.** They are NOT symmetric, and an earlier version of this very file said
   both were 3.13+ — the false claim that caused the crash in §1a. On the 3.11
   floor, `p.write_text(text, encoding="utf-8", newline="\n")` is the **preferred**
   form; reach for `open()` only where `write_text` cannot express the write
   (append, incremental). Pinned by
   `tests/test_generated_newlines.py::test_write_text_accepts_newline_on_the_declared_floor`,
   which asserts what both APIs actually do rather than restating this.
2a. **A mechanical rewrite of `X.write_text(...)` into `X.open(...)` is a
   precedence trap.** When `X` is an expression, `docs / "run-state".open(...)`
   binds as `docs / ("run-state".open(...))`. Three shipped functions crashed this
   way and neither `ruff` nor 1,680 tests saw it. If you ever do such a sweep,
   *call the rewritten functions* — the AST guard that checks their shape cannot
   tell you they run.
3. **`main()` is called BARE at the bottom of `trace.py`** — a plain `return` sets
   no exit status. A new checker there must `sys.exit(code)` or it will report its
   finding and exit **0**, which is worse than no checker.
4. **Measure AFTER the last edit.** The module-size ratchet was stamped mid-edit
   (2472, real 2495) on the same session that logged the rule.
5. **Re-stamping a ratchet is a reviewed edit with a reason at the entry** — and a
   ratchet stamped at *current+1* is a freeze, not a sensor. Leave headroom (~8%).
6. **Never blanket-append census sanctions.** Three were appended without
   individual reasons and the WI-340 audit guard caught all three gaps (a dead
   fingerprint, a disposition outside the declared vocabulary, a class missing
   from the distribution table). Triage each.
7. **Prove a CSV round-trip byte-exact before changing a cell**, and assert no C0
   control bytes after writing.
8. **Never `git stash` mid-session.** Never run the suite while still editing.
9. **A number in prose rots; a number a test re-derives does not.** 130-REVIEW-A
   refuted *both* figures that justified WI-352's design — one had been measured
   against an earlier implementation and never re-measured after the code changed.
   The fix was not a corrected number, it was
   `test_the_live_only_scope_is_load_bearing_not_vacuous` and
   `test_done_when_holds_the_overwhelming_majority_of_checkboxes`, which assert
   the *design claims* as properties with headroom. Prefer that shape whenever a
   number is load-bearing for a decision.
10. **A guard is not done when it passes — only when you have made it fail.**
   Two guards on this branch were driven and bypassed by reviewers *after* being
   mutation-tested against the shapes their author imagined. If a guard's property
   is semantic, say so and put the residue in
   [enforcement-audit.md](../../enforcement-audit.md) rather than shipping a check that
   advertises what it cannot hold.

## 5. Method note — what actually found things

Across five adversarial rounds on this branch (127/128/129-REVIEW-A, an Opus
review of WI-326, and the codex batch review), **the large majority of findings
were not broken code — they were signed CLAIMS the code did not support.** Every
test passed and every gate step was green throughout.

The single most productive move was not a test. It was a reviewer asking *"does
the number this thing prints go up when tests stop running?"* — and then running
it with the gate closed. That found a declared `git` gate with **nothing routed
through it**: 171 tests silently skipping while the new counter printed `0`.

So: after finishing a WI, dispatch a **non-Anthropic** adversarial review of your
own commits before calling them done. `codex` (OpenAI) answers in seconds; the
OpenCode-Go gateway has died twice — **probe before planning, and route by
PROVIDER, not by gateway.** Give the reviewer the calibration (the branch's
signature defect) or it will look for bugs and miss the claims.

**The prompt that worked** is kept at `docs/reviews/130-REVIEW-A.md`'s header and
was built from four parts, all of which earned their place:

1. **the calibration** — "this branch's recurring defect is signed claims that
   pass every test, not broken code", with a prior review named to read;
2. **a named-suspect list** — every load-bearing number and design claim, quoted,
   with an instruction to verify each independently;
3. **an explicit instruction to MUTATE the guards** and check they can fail —
   this produced two of the four BLOCKERs;
4. **"do not leave the repo modified"**, with a `git status --short` check. It
   complied byte-exact, which is what made it safe to run against a live tree.

Two runnable commands worth reusing:

```
codex exec --sandbox workspace-write --skip-git-repo-check \
  -o <out>.txt "$(cat <prompt>.md)"          # codex writes its FINAL message to -o
```

and tell the reviewer plainly that **its final message is the deliverable** —
`codex` streams a long working log that is not the review.
