## 4. Traps this session paid for — do not re-pay them

1. **The 18-step block is not the G3 bar, and a `PASS|FAIL|ERROR` filter hides the
   WARN tier.** Both in §1. This pair cost three missed findings.
2. **Measure AFTER the last edit — it failed again.** I signed "5 rows carry an
   anchored SpecRef", then filed WI-355 (which adds one) and never re-measured. It
   is six. The fix is not care, it is re-derivation: the close script now computes
   the count instead of my typing it.
3. **PowerShell's `Measure-Object -Line` SKIPS BLANK LINES.** It reported 2343 for
   a 2590-line file. Use `read_bytes().count(b"\n")`, or the ratchet's own number.
4. **`git status` cannot show line-ending drift** — `git ls-files --eol` can. It is
   a per-session check, not a one-time fix.
5. **A guard is not done when it passes — only when you have made it fail.** Four
   guards this session were mutation-proven; the review still found one whose case
   normalization I had never mutated. Mutate the shapes you did NOT imagine, and
   restore from original bytes, verifying byte-identity.
6. **When a review hands you a fix, measure the fix too.** 131-REVIEW-A correctly
   refuted the `nearest_anchor` prefix rationale and then recommended deleting the
   branch; measuring showed a severe truncation defeats plain `difflib` outright,
   so the branch stayed and the *rationale* was corrected.
7. **Do not sign a mechanism you did not establish.** I wrote "regenerate
   PROJECT_STATE.html LAST" from one observation; the reviewer isolated the inputs
   and showed the dashboards sha256-identical across a `--status` regen. The rule
   was fiction. The honest invariant needs no ordering folklore: **regenerate each
   derived artifact after its inputs are final.**
8. **Do not put backslashes in a heredoc'd script**, and prefer writing a scratch
   file and running it. PowerShell here-string escaping bit twice this session.
9. **Never `git stash` mid-session. Never run the suite while still editing.**
10. **Adding a public function means `gen_arch_map.py` must be regenerated**, and a
    new *sibling module* is a scaffold-surface change (bootstrap MAPPING, README

## 5. Method note — what keeps working

Dispatch a **non-Anthropic** adversarial review of your OWN commits before calling
them done. Six rounds now (127/128/129/130/131-REVIEW-A + an Opus review), and the
large majority of findings are **signed CLAIMS the code does not support**, not
broken code — every test green throughout.

`codex` (OpenAI) answers in seconds; the OpenCode-Go gateway has died twice.
**Probe before planning, and route by PROVIDER, not by gateway.**

```
codex exec --sandbox workspace-write --skip-git-repo-check -o <out>.txt "$(cat <prompt>.md)"
```

Tell it plainly that **its FINAL MESSAGE is the deliverable** — it streams a long
working log that is not the review. The prompt that works has four parts:
the **calibration** (this branch's defect is signed claims, with a prior review
named), a **named-suspect list** of every load-bearing number quoted for
independent verification, an explicit **"MUTATE the guards and check they can
fail"**, and **"do not leave the repo modified"** with a `git status --short`
check. The header of [131-REVIEW-A](../../reviews/131-REVIEW-A.md) records the shape.

One caveat learned this round: **verify the reviewer's environment**. 131-REVIEW-A
could not run the repo `.venv` and fell back to Python 3.8, below the declared 3.11
floor, so every code-behaviour finding was re-verified here before being acted on.
