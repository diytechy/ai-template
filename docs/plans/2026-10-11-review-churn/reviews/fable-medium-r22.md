- [MAJOR] [phase 2] README.md item 13, "How the red-before is proven" (lines 861–867) -> The contract says "the commit carrying the marked tests passes the ordinary commit bar, and item 13's tree-bound bar attestation records that", and the implementation commit's check "confirms ... that the parent carries a green bar attestation". But the ordinary commit bar is `pytest -m smoke` (`docs/stack.ini:1270`), and `tests/conftest.py` partitions the suite: every test is smoke UNLESS its module is in `SLOW_MODULES`, which names 122 of the 232 test modules (`grep -cE '^\s*"test_[A-Za-z0-9_]+",' tests/conftest.py` = 122; `ls tests/test_*.py | wc -l` = 232). A new strict-xfail test added to any of those 122 modules (`test_agent_loop*.py`, `test_trace_hats_driven.py`, ...) is never executed by the parent's commit bar, so its "green bar attestation" proves no red at all, and the static check as written accepts it. -> State that the attestation names the selection it ran, and that the strict-mark check refuses a removed mark whose test was outside the attested selection (smoke tier or the scoped set); or require the test commit's bar to be the review bar (smoke plus the scoped set), not "the ordinary commit bar". Same fix on the implementation side ("the test now passes" is only the bar's execution if the bar selected the test).

- [MINOR] [phase 2] README.md item 13, "The Python reference" (line 865) -> `@pytest.mark.xfail(strict=True, raises=AssertionError)` rejects a red that is not an `AssertionError`: `pytest.fail(...)` and a `pytest.raises` block that does not raise produce `Failed`, whose MRO is `Failed → OutcomeException → BaseException` (checked, pytest 9.1.1; `_pytest/skipping.py` sets `rep.outcome = "failed"` for an exception outside `raises`). This repo's tests use `pytest.raises` 194 times in 53 files, so a test-first test of a refusal ("DID NOT RAISE") goes red the bar refuses. -> Reference `raises=(AssertionError, pytest.fail.Exception)` (or word the stack-neutral clause as "fails at the test's own check", and let the reference name both classes).
