## Item 11: views for the owner

**Open call 1 — code points only to interfaces, or keeps both tags.** Prefer one authored implementation trace through IFs once the owner confirms its coarser meaning and replacement discharge gate. Keeping both indefinitely recreates independently maintained claims. Define each contract once at its owning realization, with citations at relevant symbols. Remove `Implements:` only when the replacement supports structural checks, test-first checks, coverage measurement and non-code realizations through one coordinated migration.

**Open call 2 — IF carries LLR/SR IDs.** Confirm a single IF-to-obligation allocation relation in principle. Removing the old down-pointer can eliminate the second home, but does not establish semantic correctness. Independently review which obligations each IF carries and verify those obligations specifically. Distinguish this allocation from retained SR→boundary-crossing links. An SR-only IF supports system acceptance but must not silently discharge unrelated implementation obligations.

**Open call 3 — every LLR has an interface.** Require every implemented leaf obligation to have a meaningful observable realization and verification path. The verified 55-row census means “no owned IF,” not necessarily “no observable interface”: existing or externally owned seams may already suffice. Read original rationales before reframing or retirement. Resolve OI-48 and physical part-source treatment explicitly; recursive composite LLRs need child-completeness and integration evidence, not decorative helper-call interfaces.

**Open call 4 — file/CMP declarations and LLR allocation.** Confirm component declarations for software realization units, but retain LLR→CMP as independent design intent. Deriving intended and actual placement from the same header makes the check circular. Derive an internally owned IF’s component only from a unique, role-identified owner; external interfaces require external ownership plus local participating components. Physical realizations need appropriate PART/ASSET/source representations.

**Open call 5 — IF approval.** Use existing Drafted/Approved architecture authority. Confirm that changing carried obligations requires independent acceptance and amendment review with the relevant baseline, while generated code paths remain generated and do not themselves reopen approval. Agreement on an interface is distinct from evidence that its implementation passes tests.

**Open call 6 — citations only where served.** Confirm no universal per-function contract requirement and no manufactured contract for an internal helper. Mechanically check declaration syntax, live IDs, roles, cardinality, independent allocation and verification links. TC execution proves reachability, not semantic realization; component membership also cannot prove it. Independent review remains necessary for that residual question and is compatible with item 1’s preference for mechanically closed syntax.

**Open call 7 — WI references and needs.** Add optional `if_refs` beside `sr_refs`: affected seams and delivered obligations answer different questions, and requirement/process work can precede interface design. Use a meaningful scope explanation where needed for interface-free work, never placeholder IDs. Keep actual execution dependencies authored. The July 14 decision already deferred this column on migration-cost grounds; confirm that the proposed queries now justify that cost.

**Open call 8 — decomposition choice.** Prefer (b), system-boundary SRs with recursively decomposed LLRs, conditional on explicit parentage and composite-versus-leaf completion. It keeps system acceptance stable while architectural refinement splits obligations without changing their tier. Alternative (a) remains defensible, especially for assemblies, but needs the parent-obligation and component-scope cells currently missing from its promised recursion.

An IF is a split candidate, not S1’s unit: one deliverable can need several directional IFs, and several deliverables can safely share one.
