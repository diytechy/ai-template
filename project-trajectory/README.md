# Project Trajectory Template

A portable, **stack-agnostic** kit for taking a project from brief (or draft)
to an accepted, maintainable deliverable via a **gated, requirement-traced**
process — with modular/deduplicated code, testable chunks, and explicit
attention to end-user usability and corner cases.

It encodes a key lesson: the value is in the **artifacts, gates, and role
discipline** — not in spawning many agents. One driver wears the role "hats" in
continuous context; a separate reviewer is summoned only for high-risk pre-gate
audits.

| `LOG.template.md` | The **append-only history** status.md points at (gate sign-offs, verdicts, ratified decisions — process.md §5) → copy to `docs/log.md`. |
| `ARCHITECTURE.template.md` | One-page overview + generated map → copy to `docs/architecture.md`. |

| `registries/performance-budgets.template.csv` | PB-### quantitative perf/resource budgets (NFRs), off-spine but back-linked to the SR/LLR/Module they bound; owned by the Integration/Coordination hat (process.md §9). Optional, like interfaces. |
| `registries/procurement.template.csv` | PART-### purchased/external parts the project **buys rather than builds** (motors, boards, cameras). Off-spine and optional like interfaces/PB; `trace.py` integrity-checks the `PART-` ids. Deliberately **minimal** — full BOM tracking (alternates, per-module allocation, roll-ups) is a deferred extension (process-options.md "purchased parts"). |
| `registries/assets.template.csv` | ASSET-### binary/large-asset provenance registry for unavoidably-binary deliverables (art, music, voice, video). Tracks the facts *about* an un-diffable asset in text: `Provenance` (human-made/ai-generated/mixed — for Steam-style AI-content disclosure), `License`, `Attribution`, `ContractRef` (voice-actor release / commission), and a `Location` pointer + `Hash`/`Version`. Off-spine and optional like procurement/PB; `trace.py` integrity-checks the `ASSET-` ids. The ideal-not-requirement stance made concrete (process-options.md "Binary assets"). |
| `registries/components.template.csv` | CMP-### **domain-neutral component** registry — the set-grained home for **knowledge + lifecycle** (a subsystem, "the left arm", a software package group). Structure is **derived, never restated**: membership is a `Component` tag on the primitive rows (LLR/IF/ASSET/PART); an IF with both endpoints inside a CMP is internal, one endpoint in is its boundary; `PartOf` nests (tag primitives at the finest CMP); `SupersededBy` carries identity across a rewrite. Off-spine and optional like procurement/assets; `trace.py` integrity-checks `CMP-` ids and resolves the joins (process-options.md "Component layer"). |
| `registries/work-items.template.csv` | WI-### execution registry for the **opt-out** trajectory/work-items layer: each row is a work item that **delivers** SR(s), belongs to a **workstream**, and **depends on** predecessor WIs (hard or advisory edges), moving `queued→active→done`. Optional `BuildTier` and `CritiqueBudget`/`CritiqueExhaustion` cells steer unattended routing and subjective-quality loops per WI. Off-spine like procurement/assets; `check_trajectory.py` owns the `WI-` ids (`trace.py` doesn't read them). Ships an inert `WI-000` row, so a repo that never adopts the layer pays nothing (process-options.md "Trajectory / work-items layer"). Its `SpecRef` column + the status.md↔registry SSOT rules (R-A…R-E) are mechanized by `check_trajectory.py`. |
| `specs/README.template.md`, `specs/WI-000.template.md` | The **spec-of-record** directory scaffolded to `docs/specs/`: a README explaining the layer (one file per WI or a shared effort doc with `#anchor`; archive-at-close) and an inert `WI-000.md` example carrying a **Done-when checklist**. The `SpecRef` column of `work-items.csv` points here (rule R-E); the `-000` example is inert so nothing gates on it. |
| `knowledge/README.template.md` | The hand-owned **knowledge-pack** home scaffolded to `docs/knowledge/`: its contract keeps durable evidence, rationale, quirks, failed approaches, and dated references without restating the requirement spine; its index makes packs discoverable by documentation checks. Packs stay advisory and findings that harden into requirements are promoted through change intake. |
| `rubrics/README.template.md`, `rubrics/rubric-000.template.md` | The **critique-rubric** directory scaffolded to `docs/rubrics/`: a README explaining the convention and an inert `rubric-000.md` example. A rubric is the written reference a `Verification=Critique` requirement is judged against — derived from the SN/SR intent (**not** the possibly-lax TC), carrying numbered good (`G#`) / bad (`B#`) anchors that **accumulate at rework**, cited by the critique verdict. Read by an independent critical eye, never the authoring session (process-options.md "Critique verification & the critique loop"); the `-000` example is inert so a repo that never uses `Critique` pays nothing. |
| `prompts/dual-plan-{planner,critic,arbiter}.template.md` | The three hat prompts for the **dual-plan decomposition** layer (process-options.md section of the same name): identical redacted planner briefs, the rubric-anchored cross-critique (hard cap one round), and the provenance-anonymized, position-swapped select-and-port arbiter — the redaction/anonymization/anti-verbosity safeguards are **embedded in the prompt text**, so they ride the artifact, not session memory. **Not** scaffolded by bootstrap — copy them in when a goal trips the layer's applies-when; the mechanical companion is `scripts/plan_coverage.py`. |
| `registries/repos.template.csv` | REPO-### coordinator repo-delegation registry for the **rare** multi-repo rung (`MULTI_REPO.md` §6): one row per delegated repo, `DelegatedSRs` back-linking the coordinator SRs it fulfils (formerly `modules.template.csv`/`MOD-###`; the legacy file + ids are still read). Coordinator-only — **not** scaffolded by bootstrap; `trace.py` validates it when present. |
| `scripts/bootstrap.py` | **One command to scaffold a new repo** from this kit (copies/generates templates → `docs/`/`scripts/`/CI, renames, won't clobber). The Markdown docs are *generated* from the masters per the declared profile (`--stack python\|node\|go\|rust\|powershell\|any`, `--omit nfr,multi-module`), recorded in `docs/kit-profile`; an explicitly non-Python `--stack` skips `pytest.ini` and appends the harness-rewiring checklist to `docs/status.md`. |
| `scripts/check.py` | **The harness.** Runs format · lint · tests · coverage · traceability · arch-map freshness; gate-scoped (`--gate` defaults to the active gate recorded in `docs/gate`, so CI enforces the bar the project is actually at); nonzero on failure. Python-first reference — wire to your stack. |
| `scripts/trace.py` | **Ready-to-use** traceability checker (Python 3, stdlib only): joins the registries, writes `test/report.md` (counts, matrix, a line-reviewable `SN→SR→LLR→TC` text outline, and a small Mermaid `graph LR` colored by orphan/draft state), exits nonzero on orphans (and duplicate/malformed ids) with `--strict`. If an optional `performance-budgets.csv` (PB-###, §9) is present, it also fails when a budget row's `Refs` don't back-link a real SR/LLR/Module. `--html` also writes a dependency-free collapsible `test/report.html` map that scales to any size. `--phase v1` scopes the G3 Verified criterion for phased roadmaps (out-of-phase SRs reported as explicitly deferred); `--no-placeholders` (G2+) rejects leftover `-000` rows; `--strict-schema` (G3) checks required fields and the closed `Verification`/`Tier` vocabularies. Called by `check.py`. |
| `scripts/check_flows.py` | Verifies the **authored "Runtime flows"** section in `architecture.md` (required from G2): diagrams present, every cited SR/LLR id real — so reviewers verify *behavior* (concurrency, ordering) from sequence diagrams, not CSV rows. Called by `check.py` at G2/G3. |
| `scripts/check_docs.py` | **Doc navigability** check (Python 3, stdlib only): parses the link graph across `docs/` + root `*.md` and **fails on broken intra-repo links** (missing file or `#anchor`), **warns on orphan docs** (unreachable from an entry root), and with `--stale` (git-gated) emits a low-severity **`hint`** (below `WARN`, never a finding) on docs frozen beside churning code. Also **fails unless the root README states the singleton `PROJECT-VISION:` tag exactly once** (§4 G1's mechanizable half; other docs point at the tag, never restate it) and, when the README carries an opt-in `<!-- sn-inventory -->` section, checks its SN citations both ways (every cited id exists; every Must/Should need is cited). Keeps the hand-written doc map honest like `gen_arch_map.py` keeps the code map honest (process.md §3). Called by `check.py` from G1. |
| `scripts/check_perf.py` | **Performance-budget comparator** (Python 3, stdlib only, metric-agnostic): compares a product-emitted `perf-metrics.json` against `performance-budgets.csv` (PB-###) and a committed `perf-baseline.json` — **absolute** breach vs `Budget` and **regression** vs baseline ± `Tolerance`, warn-vs-fail per the row's `Gate`, tier-scoped — and writes the gitignored `perf-report.md`. `--update-baseline` accepts a move (commit its diff in the same PR). The kit owns the *comparison*; the project wires the *measurement* (process.md §9). Called by `check.py` at G3 (absent metrics skip). |
| `scripts/check_stubs.py` | **No-stub / substance** tripwire for the G3 criterion (process.md §4): lists public symbols whose body is a stub (`pass`/`...`/`raise NotImplementedError`/bare `return None`/docstring-only), writing the gitignored `stub-report.md`. Stdlib, but **product-layer and warn-first** (exit 0 unless `--strict`) — a stub's shape is language-specific, so it ships like the perf *meters*: opt-in, **not** wired into `check.py`'s required floor. Informs the human/LLM G3 Inspection; a non-Python stack swaps or drops it. |
| `scripts/check_doc_refs.py` | **Doc reference validation** (Python 3, stdlib only, Thread 49 — the rot classes link-checking can't see): the **path tier** flags a backticked repo-path-shaped token (`scripts/x.py`, `docs/y.md`) that no longer exists on disk — a renamed/deleted file named in prose is the commonest real doc rot; the **symbol tier** checks only the explicit `sym:<module>.<name>` convention against the generated module map in `architecture.md` (you *assert* a symbol exists; no inventory → the tier skips, so files-mode/non-Python degrades). False-positive control is the design center: URLs/globs/placeholders skipped, generated marker blocks skipped, a `path-ok` line exempt (the `privacy-ok` idiom). **Warn-first and product-layer** like `check_stubs.py` (exit 0 unless `--strict`; not in the required floor) — opt in via `[step:doc-refs]`. |
| `scripts/check_dupes.py` | **Duplicate-code lint** (Python 3, stdlib only, Thread 53 — adapted from the proven gilbert detector): tokenizes every `.py` under `--src` and fails on any window of `--min-tokens` (default 30) consecutive significant tokens appearing at more than one location — copy-paste made mechanical ("one fact, one home — in code too"). Exact-token equality only (renamed-identifier near-dupes are out of scope: fast, deterministic, no arguable false positives); legitimate repetition is *recorded*, not fought, in a `docs/dupes-allow` allowlist matched against the line-number-free `a.py == b.py` pair. **Product-layer and opt-in** — wire it via a `[step:dupes]` line in `docs/stack.ini` (G2+ recommended); the tokenizer is the Python reference, swap for your stack. |
| `scripts/check_vendored.py` | **Vendored-doc drift check** (Python 3, stdlib only, network-gated, warn-first): for a repo that vendors a verbatim upstream doc set (e.g. the tier-conditional guardrails core), hash-compares each file against its **pinned** raw URL in `docs/guardrails/UPSTREAM` and **warns** on drift (local edit or upstream re-pin). Degrades to a clean skip offline; `--strict` exits 1. Never fetches into the workspace, never auto-updates — updating is a human-reviewed re-copy that bumps the commit. **Not** wired into `check.py` (the gate stays hermetic); used by the "Tier-conditional guardrails" layer (process-options.md). |
| `scripts/check_privacy.py` | **Secrets + privacy lint** (Python 3, stdlib only). Two layers: an always-on **secrets floor** (private-key headers + GitHub/Slack/AWS/`sk-…` shapes) that runs in *every* repo — opt out with `off` in `docs/secrets-scan` — and **privacy** classes (the commit author email via `--author`, home-dir paths carrying an OS username, the current account/hostname, non-exempt emails, the global-git-config identity) gated on `docs/privacy-check` = `true`, with the exempt-email allowlist (`EXEMPT_EMAILS`, default `*noreply*`) in the script. Staged-diff + `--author` in the pre-commit hook, `--message` (the commit message) in the commit-msg hook, `--repo` sweep as a `check.py` process step, `--range` over outgoing history (diffs + commit messages) for the pre-push hook and the sync scrub's base pass; inline `privacy-ok` exempts a documented example line. | `scripts/gen_okf.py` | **OKF knowledge-bundle export** (Python 3, stdlib only, Thread 48): emits `docs/okf/` — an Open Knowledge Format (v0.1) bundle generated from the spine registries, one markdown concept per SN/SR/LLR/TC (+ IF when present) with YAML frontmatter (emit-only string formatting — the kit never parses YAML), the graph as normal markdown links, per-tier + root `index.md`, and an `UPSTREAM.md` spec pin. ## How to use

1. **Scaffold:** from this kit, run
   `python scripts/bootstrap.py --dest /path/to/new/repo` (add `--dry-run` to
   preview). This generates the docs and copies the scripts into `docs/`,
   `scripts/`, `AGENTS.md` (plus `CLAUDE.md`/`GEMINI.md` stubs), and CI,
   renaming `*.template.*` to working names. Declare a non-Python stack with
   `--stack node|go|rust|powershell`; opt out of the §9/§10 layers with
   `--omit nfr,multi-module` (each keeps a one-line stub; recorded in
   `docs/kit-profile`).
   *(Manual alternative: copy this folder in and rename by hand — then strip
   the `kit-only`/`profile` marker regions yourself; bootstrap is the honest
   path. Adopting into an **existing** repo — code, CI, a non-Python stack?
   See `ADOPTING.md`.)*
   If `python` is absent or Python 2, use `python3` (Linux/macOS) or `py`
   (Windows); the kit needs Python 3.8+.
   *Setting up for an agent? Add `--agents claude|gemini|both` to also
   materialize that agent's skills (run interactively without the flag and it
   asks; the default `none` keeps the agent-neutral scaffold — `skills/README.md`).*
2. **Brief:** fill the **PROJECT BRIEF** in the new repo's `AGENTS.md` and
   `docs/status.md`. To drive it conversationally instead, paste
   `KICKOFF_PROMPT.md` (brief filled) into your agent.
3. **Wire the harness to your stack:** edit the step list `scripts/check.py`'s
   `steps()` returns (and the `SRC`/`TESTS`/tool names in its "EDIT FOR YOUR
   STACK" block) for your toolchain (the reference uses `ruff`/`pytest`);
   `trace.py` and `gen_arch_map.py` are stdlib-only.
4. The agent runs the gates **G1 → G2 → G3 → G-Release → G-Final** (G-Release
   only for versioned releases), each accepted per the repo's declared gate
   authority (`docs/gate-policy`; default: your approval, per gate), with
   `python scripts/check.py` as the bar.

## The core ideas (why it produces sustainable code)

- **Traceability:** `SN → SR → LLR → TC`, joined by a generated matrix that must
  report **zero orphans**. Every line of intent is traceable to a need and a test.
- **Single source of truth + decomposition (not paraphrase):** facts live once
  and are referenced by ID; children add detail. This is what keeps docs and code
  from rotting into contradiction.
- **Modularity & dedup:** shared logic in one place; pure testable cores split
  from I/O/GUI shells; one-page architecture, generated so it can't drift.
- **Testability:** measurable acceptance criteria; tests cite requirement IDs;
  coverage threshold; a harness that runs locally and in CI.
- **Usability & corner cases:** a standing end-user lens for setup/first-run,
  failure modes, safety, automation/never-block, and honest docs.
- **Honest gates:** machine-checkable criteria where possible; everything else is
  explicitly classified Demonstration / Manual / Inspection — nothing hand-waved.

## Tuning knobs

- `COVERAGE_THRESHOLD` and `MAX_ROUNDS` in `PROCESS.md`.
- Drop a hat/gate for tiny projects (e.g. skip UX for a library); keep the
  SN→SR→LLR→TC spine.
- Scale review depth to risk — don't gate a rename like you'd gate a crypto path.
- Scale *structure* to scope: one module in one repo is the default; a repo can
  host several modules on the same spine (grouped by `Module`/`Area`, with an
  integration TC per seam), and multi-repo under a coordinator is a rare, later
  step — climb the ladder only when scope forces it (process.md §10; the
  coordinator model is `MULTI_REPO.md`, a design with the tooling deferred).
