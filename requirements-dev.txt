# Constrained dev toolchain for the meta-repo's OWN verification chain (WI-104 / the
# 2026-07-12b review's M6). The kit scripts under project-trajectory/ stay
# stdlib-only — a downstream repo runs them with no pip installs; nothing here
# ships downstream. These four tools are only what THIS repo's self-tests + gate
# drive, and CI (.github/workflows/test.yml) and scripts/dev-setup.{sh,ps1,command}
# both install from this file so every machine runs the same machinery.
#
# WHY CONSTRAIN: floating latest can let the next ruff format-rule change turn the
# `format` gate red or a coverage-tool major silently reweight the floor (the
# pytest-cov 7 contract
# break tests/conftest.py already had to absorb) — a gate that lies for reasons
# unrelated to any commit. These are compatible-release ranges (~=), so accepted
# patch/minor fixes still flow; this is intentionally not a byte-reproducible
# lock. The next MAJOR cannot drift in unannounced. A floating-latest
# canary job (.github/workflows/canary.yml) runs the suite unpinned on a schedule
# to catch that upcoming breakage WITHOUT gating merges.
#
# pytest-cov is pinned at 7.x for everyone: the kit's 3.11 floor (WI-262) sits well
# above the 3.9 that pytest-cov 7 requires (6.0 dropped Python 3.8), so the old
# Python-gated split — 5.x on the 3.8 floor, 7.x on 3.9+ — dissolves; conftest.py
# now targets the single 7.x plumbing (was the dual-major path of WI-105).
#
# pytest floors at 9.0.3, not a bare `~=9.0`: GHSA-6w46-j5rx-g56g (insecure
# predictable /tmp/pytest-of-{user} handling on Unix, CVSS 6.8, dev-only — the
# shipped runtime is stdlib-only) is fixed only in 9.0.3+, and the OLD `~=8.3`
# range excluded that fix entirely (repo-review 2026-08-19 M-11). `<10` keeps
# the same "next major can't drift in unannounced" posture as every other row
# here. Qualified 2026-08-20 (WI-480): the full suite run against a throwaway
# venv on pytest 9.1.1 produced the IDENTICAL pass/fail set as the pinned
# 8.4.2 it replaced (2624 passed, 13 skipped, 2 pre-existing golden-fixture
# failures in tests/test_trace_golden.py, unrelated to pytest and reproduced
# against 8.4.2 too — a WI-466 fixture gap) — zero regressions attributable
# to the version bump. `.github/workflows/sca.yml` now audits
# this file's resolved environment on the same weekly cadence as canary.yml,
# so a future advisory against a pin still inside its compatible-release range
# surfaces on its own schedule instead of sitting silent.
ruff~=0.15.0
pytest>=9.0.3,<10
pytest-xdist~=3.6
